# 行为契约模板

> **本文是什么**：较大改动 plan 的**行为契约骨架**——契约写哪几段、每段填到什么程度算合格，以及 plan 退役时契约结论的落点示例。
> **本文不是什么**：不是 plan 通用模板（头部护栏行、实施步骤与证据节见 [`PLAN_TEMPLATE.md`](./PLAN_TEMPLATE.md)）；不是任何模块的行为规范（现状见各 `CODE_WIKI.md` / `RULES.md`，定案理由见 [`docs/adr/`](../../docs/adr/README.md)）。
> **信源等级**：L1 —— 可作「契约该怎么写、结论该落哪」的直接依据；不得作技术事实的依据（回其 home）。
> **真源路由**：工作台的状态闭集与退役四步 → [`docs/README.md`](../../docs/README.md)「plan 规范」；ADR 准入条件与归宿表 → [`docs/adr/README.md`](../../docs/adr/README.md)。
> **继承**：通用协作与信源规则见项目根的 [`AGENTS.md`](../../AGENTS.md)；本文只补充契约这一对象特有的约束。

契约先于技术方案：先把「改完之后世界怎么表现」定死，再谈怎么实现。跨层、新模块、并发与资源类改动必写。

## 骨架（复制进 plan，替换 `<…>`）

````markdown
## 行为契约

> **契约状态**：<约定中 | 已批准（谁 / 日期）| 已生效（commit）| 已作废（理由 + commit）>

**目标行为**——玩家或系统可观察到的差别，不是实现动作：

| # | 观察者 | 可观察行为 | 现状差在哪（出处） |
|---|---|---|---|
| T1 | <玩家 / GUI / 日志 / 下一层调用方> | <在 X 条件下做 Y，得到 Z> | <核对到的事实 + 文件或实跑出处> |

**不变量**——改了也不能破，每条写得出破掉的表现：

| # | 陈述 | 谁依赖它 | 破掉的表现 |
|---|---|---|---|
| I1 | <……> | <哪个模块 / 哪条既有契约> | <哪条回归锁变红 / 哪种现场复现> |

**约束**——本契约明确不许做的，实现时的范围闸门：

- 归属：<这段逻辑住哪一层，为什么>
- 不许新增：<依赖 / 配置旋钮 / 特例分支 / 第二份真源>；确需新增时在此写出理由，并过 AGENTS.md「生态优先」两问与「抽公共层准入」一问。
- 不顺带：<本次契约之外的重构、清理、格式变更>
- 不承诺：<契约覆盖不到的场景，以及那部分由谁继续负责>

**验收条件**——可复算，尺子独立于待验证对象：

| # | 判据 | 数据源 | 通过线 | 现在的缺口 |
|---|---|---|---|---|
| A1 | <怎么算达成> | <trace / 回归锁 / 实跑局号 / grep> | <阈值或其真源指向> | <待标定 / 缺列 / 无留出集> |
````

## 每格的准入判据

| 段 | 算写对了 | 不算 |
|---|---|---|
| 契约状态 | 四值闭集，带批准人或 commit | 不写状态——无状态标注的断言会被后来者当有效前提转述 |
| 目标行为 | 主语是可观察者，谓语是可观察事件，现状栏给一手出处 | 「重构 route 层的承诺机器」是动作不是行为；「大概会更跟手」无法验收 |
| 不变量 | 每条同时给出「谁依赖」和「破了会怎样」 | 写不出破掉表现的是愿望，不是不变量；「保持性能」不可判 |
| 约束 | 写出层归属、不许新增的东西、不许顺带做的事、不承诺的场景 | 只写「要干净」——读者无法据此拒绝任何一个具体改动 |
| 验收条件 | 数据源与被改对象不同源；缺口如实登记 | 用改动自己新落的字段验改动自己；把同批样本的组间差当结论；阈值不知道就填占位数字 |
| 数值 | 可机检的值一律指向真源路径（配置 / 代码 / 资源） | 手抄阶段数、容差、测试条数——没有守卫就必然腐坏 |

阈值未知时的正确填法：通过线写「待标定」，缺口栏写清标定所需的统计量与数据来源；标定完成后数值落 ADR，契约只留指针。不用拍的常数代替未知阈值。

## 填写示例

对象：**急停只在程序接管输入期生效**（定案见 [ADR-0015](../../docs/adr/0015-contract-core-紧急停止启用范围.md)；起因是宏录制的键盘映射里 W+A 即两键，与急停判据直接冲突）。

- **契约状态**：已生效（维护者 2026-11-03 定口径）。
- **T1**：观察者 = 手动驾驶 / 录制阶段的玩家；可观察行为 = 键盘任意多键组合不再触发急停，GUI「停止」按钮仍可停；现状差 = 按键检测不区分输入归属，录制被误停。
- **I1**：程序接管期（深度几何、全程直行、宏回放）的急停行为不变。依赖方 = 全部既有模块；破掉的表现 = 接管期误停或误放行，回归锁 `tests/test_controller_emergency_scope.py` 变红。
- **约束**：归属 = core 的输入检测循环，模块只能声明当前是否人工阶段；不许新增 = 逐模块的急停开关、第二份「谁在开车」状态；不承诺 = 人工阶段的键盘急停。
- **A1**：判据 = 人工阶段跳过检测 / 程序阶段保留 / 无模块或取值异常时回落检测；数据源 = 上述回归锁三条用例，不需实跑。

其中「不承诺人工阶段的键盘急停」这一句决定了新增带人工阶段的模块必须自己声明阶段归属，否则误触发。契约里少这一句，实现时就会长出全局兜底开关——约束段的用处正在于此。

## 退役示例

契约的结论按结局落不同的 home，走的都是「plan 规范」的四步：结论迁 home → 资产提升或随删 → 拔引用 → 删除。

### 成立 → 升 ADR

```markdown
> **状态**：retiring
> **归属去向**：docs/adr/0002（arch-global：真源单一，禁止生成物回读）
> **退役条件**：ADR-0002 落地且全仓 grep 无 v3 活代码后删除
```

1. 结论迁 home：契约那句「仓库中不存在 v3 专属代码、真源（`*_assets.json`、`generated/`）、工具链」与验收「仓库搜不到 v3」写进 ADR 的证据节，指针是整删批次的 commit（写 SHA，如 `b9e3b3f`，不用阶段代号）。
2. 资产提升：迁移器与校验器被生产与 CI 消费 → 移入 `tools/` 正式位并改好引用；只对这次对拍有用的一次性脚本随 plan 删除。
3. 拔引用：`python tools/check_repo_hygiene.py` 的 R3 零命中。
4. 删除：走回收站。

### 不成立 → 结论落坑点

```markdown
> **状态**：retiring
> **归属去向**：plugins/<id>/CODE_WIKI.md 的定案与坑点
> **退役条件**：该节写下假设、否证数据与最终决定后删除
```

「假设 + 否证数据 + 最终决定」三段都写进模块文档，证据用 commit 指针；成立与否都要留痕，只留「不成立」三个字等于让下一个人重走一遍。ADR 的准入要求「架构级」——自检问句「这个决定让哪个别的模块做不了什么」答不出时，结论留在模块层。

### 条件成立 → 判据先落、阈值待定

```markdown
> **状态**：retiring
> **归属去向**：docs/adr/（criteria 类）+ 判定器提升后的 tools/ 正式位
> **退役条件**：主指标可算并给出结论后删除；主指标不可算时保持 active 并登记缺口
```

判据成立、标定数据未到，是这类契约常见的中间结局。此时迁 home 的是**不依赖阈值的结论**：证据分等（新鲜测量 / 保持值 / 预测值）、结论取三值（完成 / 未完成 / 无法确认）、事后核验证据不得回流决策拍的结论。带数值的门槛等标定后另立，未标定的阈值不写占位数值。

### 退役条件行的写法

| 不算 | 为什么 |
|---|---|
| 「等后续再看」 | 不可判定，等于永驻 |
| 「实施完成后归档」 | 工作台没有归档态，完成即删 |
| 「验证通过」 | 不写谁验、怎么算通过，不可复算 |
| 「下次发版前处理」 | 时间点不指向任何可判定事件 |

| 算 | 为什么 |
|---|---|
| 「ADR-0002 落地且全仓 grep 无 v3 活代码后删除」 | 条件可判、可 grep、有归属 |
| 「影子门跑满一场出现真实案例并给出结论后删除」 | 观察事件与结论落点都具体 |
