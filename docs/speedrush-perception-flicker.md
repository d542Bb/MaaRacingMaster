# speedrush 感知层「证据闪」问题图谱

> **本文是什么**：感知链（检测 → 跟踪 → 聚合 → 深度锚点 → 走廊）上「证据跨帧出现/消失」这一类问题的机制图谱与实测量化——定位感知层问题、判别修在哪层时的底稿。
> **本文不是什么**：不是修复设计（候选方向只在末节，落地以对应设计稿为准）；不是感知链的完整知识（模块机制见 `plugins/speedrush/CODE_WIKI.md`）。
> **信源等级**：L2——机制段以代码为准（文内 `file:line` 指向），量化段为 2026-10-17 两局实测（代码变动后数值需重测）。

## 一、问题类定义：证据闪

感知层各证据源（车速度/距离、币组、奖励车横位、走廊）都存在**跨帧出现/消失**的形态：证据有节拍空档、被守门清零、随轨道身份重建、随置信跳动。决策层的承诺制（CHANGE 意图需 `k_stay`/`k_up` 拍的持续证据、平手阈偏好路心）以**稳定证据**为前提——闪的证据永远凑不齐承诺条件，表现为：币组在持位中错过、快会车速度不成形、并线车追尾。

共类判据：**修在哪层，看证据是「产生节拍」问题、 「生命周期清零」问题还是「单帧质量」问题**——前者动 cadence，次者动清零/保持策略，后者动模型或阈值；对「闪」加兜底重试属于修在症状。

## 二、机制图谱（代码逻辑）

### 2.1 车速度与距离：锚间差分 + 簇跳变守门

速度不是像素估的。`v_close` 的唯一来源是**同一辆车前后两个深度锚点的区间差分**（`v_inst = (z_prev − z_new) / dt`，tracking.py:629-635）：需要连续两次锚点测量、间隔 ≥ `gate_eval_min_ms`（tracking 参数），到锚即发布。由此：

- **节拍空档**：锚点清单来自深度 worker，实测锚龄 P50≈170ms、P90≈320~350ms、最长 583ms（见 §三）——清单来一次才可能更新一次锚；锚龄即「清单没来」的时长。
- **簇跳变清零**（tracking.py:611-619）：新锚的 z 与旧锚差超过 `cluster_switch_m` 判为「量错对象」，**锚、焦距锚、v_close、v_inst 全部清零**并丢弃该锚。深度聚类在车体/背景语义间跳变时（起步锁错远簇、后修正到近车），每次修正都是一次清零，速度从头再来。亚门限跳变（tracking.py:620-628）丢弃单锚保旧锚，同样中断区间。
- **清零后重启成本**：清零后到下一次锚点又是一整拍（~170ms 起步，且可能又是一跳）。快会车场景（相对速度高、z 变化快）每个锚间间隔都容易超阈值——速度在整个接近过程中可能只成形 0~1 次，成形时已临近碰撞。

### 2.2 车横位：单目适用域门槛

`x_lane` 只在 `cy − y_h ≥ min_denom`（真源 gate0.json）时给（tracking.py:574-588 `_observe`；公式 world_model.py:93-97）。地平线附近（denom 小）单目投影发散，门槛以下的检出**横位为 None → 掉进 far_targets**（tracking.py:505-517 分流）——只有粗方向，没有横向数值。远场元素（奖励车平台、远币）整个可见生命大多落在该带内。地平线以上（denom ≤ 0）整帧丢弃。

### 2.3 币：置信跳动 + 单框组 + 地板

- **检测置信帧间大幅跳动**：日落逆光场景同一枚清晰可见的币，逐帧置信在 0.4~0.8 区间摆动、个别帧完全不检出（模型对该目标的稳定性问题，检测门槛 CONF=0.35，perception.py:37）。检测门槛以下的帧感知层无从谈起。
- **一排币只出最近一枚框**：币奖励以线状出现，检测器逐帧只框出最近的一枚（其余太小/贴地平线）。车一前进「最近的币」就换了一枚——轨道身份频繁重建，`rel_approach` EMA（tracking.py:447-448）与年龄门槛（`min_obs_ticks`，decision.json traffic 段）不断从头累计。
- **置信地板**：`scoring.conf_floor`（decision.json，与检测门槛 CONF 同值）以下整组不计分，以上按坡度折扣到 `conf_hi` 满权（decision.py:392-404）。地板切在置信摆动区间内的任何位置都会周期性把可见币组整组拒掉。
- **组价值下限**：观测 1~2 枚按整组 `coin_group_min_count` 计（decision.py:405-411，维护者口径：残缺视图按整组估值）——价值侧对单框组已兜底；扣分在置信与到站时间侧。
- **到站时间的依赖链**：币的 t_miss 走全场地面流系数 k（decision.py:418-433）——k 取全体健康轨道（rel_approach>0 且 denom 在适用域）的中位，本帧无任何健康轨道时 k=None → t_miss 无限远 → 币组只按远权计入、不进可达清单。币轨自身断链会拖累 k 的样本量。

### 2.4 走廊与收益报告：整拍缺席

走廊供数（深度栅格）缺席的拍，收益评估整体返回 None（decision.py:819）——该拍所有机会（币/车/奖励车）都不评。实测缺席率见 §三。

### 2.5 汇聚点：决策层的持续证据要求

以上闪的形态在决策层汇聚：CHANGE 意图需要连续证据升级/维持（`k_stay`/`k_up`/平手阈，decision.py 意图生命周期），走廊收益场每拍重评但承诺只认稳定证据。闪的证据 × 持续性要求 = 承诺永远差一拍。

## 三、实测量化（2026-10-17 两局）

逐拍口径对两局 debug 会话实测（一局 p1 749 拍 / 一局 p2 1324 拍；审计探针在感知实验区，此处只录结论）：

| 指标 | p1 | p2 |
|---|---|---|
| 车仪器 UNKNOWN（无锚）拍占比 | 52% | 54% |
| 锚点集翻面（有锚↔无锚） | 15% 拍（113 次） | 31% 拍（413 次） |
| 锚龄 P50 / P90 / 最大 | 167 / 317 / 550ms | 178 / 350 / 583ms |
| 锚龄 >250ms 占比 | 24% | 26% |
| 币组可见拍占比 | 16% | 38% |
| 收益报告缺席拍占比 | 14% | 8% |
| 走廊缺席拍占比 | 14% | 8% |

单帧置信跳动（币）：同一目标逐帧 0.4~0.8 区间摆动、个别帧不检出（§2.3）。

典型实例（证据指向 debug 会话 20261017_193629_p1）：

- **快会车速度不成形**：一辆从右向左并线的车，锚点序列 z=83→37→17m 两次簇修正各清零一次，速度只在簇内小间隔成形过（3.02 m/s），再成形时（32.5 m/s）距碰撞 0.3s——掠过得分与碰撞判据对它双双不生效，追尾。
- **币组在持位中错过**：可达状态在 0.5s 内翻脸四次（能→不能→能→不能），配合置信 0.49 的关键拍，承诺条件从未凑齐，币组在车持位等待中过去。

## 四、修的方向（候选，未定案）

按共类判据排：

1. **锚点重置后的速度像素桥**：簇修正清零后速度需等下一对锚（~300ms 起步）；像素侧行运动 EMA（tracking.py:447-448）逐帧都有——锚点链无有效区间时以像素运动桥接速度估计，治快会车根。
2. **簇跳变清零的分级**：量错对象清锚正确，但可按「x 是否连续」区分「换对象」与「同车修正」——同车修正保留重基线后的区间账，不清速度生命周期。
3. **走廊缺席的短暂保持**：走廊槽位机制已有先例（pair_slot），缺席拍按上一有效走廊短保持，治 8~14% 整拍不评。
4. **币检测置信稳定性**：模型对逆光/旋转目标的帧间稳定性——检测层专项，单帧质量问题的正修。

方向 1/2 属锚点链结构改动（感知层契约面），方向 3 属走廊供数，方向 4 属模型——各自独立立项，不混一个改动里。
