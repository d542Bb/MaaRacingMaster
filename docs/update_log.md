- **方法（离线，不占实机）：** 录制帧含完整 HUD，故规则实测可用已录的 4 个会话离线完成，不必等新的实机驾驶。探针五种模式：`discover`/`scan` 标定区域，`read`/`timeline`/`formula` 按生产口径（关文本检测）读数。`hud_regions.json` 每格由 `scan` 的**按位置**统计定出、不是目测——按文本聚合会漏掉数值字段（每帧都不同，全塌成 count=1，`我方总分` 就这样漏过一次）。

- **实测结论（证据与采样点见该目录 README）：** ① **合计分值 = 里程 + 30 × 超车**——5 个超车档位、两阶段独立吻合，并与 `RULES.md` §7#4 已记录的「里程 338 + 超车 1 → 合计 368」一致；② **阶段计时是剩余时间倒计时**（单段 73/76 有效、单调性零违例），阶段 1 上限约 35s、阶段 2 约 4m50s，与 §7#5 记录的 00:28 / 04:54 吻合；③ **里程 + 超车 只占总分约 12%**，其余来自金币与连击——与 §4.2「主要加分项＝金币」独立吻合，直接决定收益模型的权重取向。另两条待复核旁证：贴车/超车有 `+120` 浮字（与维护者口径一致，但它与合计里的"每辆超车 30 分"**不是一个量**，不可混用）；画面自带「N米」距离标注，可供世界模型直接使用。

- **两个坑（已写进探针注释）：** ① 左侧信息面板会闪烁，OFF 时对 ROI 做 OCR 读到的是天空（曾产出 `[2901, 1, 337, 1]` 这类垃圾值）；② 该面板还有"矮版"变体不显示合计分值，按整面板判在场会放行那一格。判据改为**逐字段暗像素占比**（纯 numpy，零 OCR 开销）。

- **录制场景分层（schema v3）：** meta 增记 `phase` / `round_no`。此前阶段号只隐式存在于会话目录名的 `_p<N>` 后缀里、**回合号则根本没有来源**（`FLOW` 只有三元组，`_run_flow` 不计数轮次）。回归锁断言"不给则为 None、给了就落盘"——None 是显式状态，不许靠键缺席来猜（那正是 schema 1 那批数据认不出字节序的成因）。**天光仍未采集**：无天气检测代码、也没做成配置项，宁可留缺口写在 docstring 里，也不留恒空的假字段。

### 暂存（未发布 · 待并入下一版本）speedrush HUD 区域逐格复核：撤回两条错结论 + RULES 记分条目回填 🔬

- **性质：** 未发版变更（`tools/experiments/speedrush_scoring/`（`probe_hud_ocr.py` 增 `overlay`/`dump`/`find` 三模式并收紧取帧判据、`hud_regions.json` 移除三格、`README.md` 重写复核结论）、`maaracing_master/plugins/speedrush/RULES.md`；master 直接提交、不 tag）

- **背景：** 维护者要求复核 HUD 区域，并指出「画面上的 `N米` 是对手车标注」——该前提下复核发现上一轮记录里的区域与结论都需要修正。

- **复核工具（本轮新增，都是"先搜后定"而不是"先猜后验"）：** `overlay` 把 ROI 画在真帧上、**并在每格标注框内实际读到的字**，框压歪了立刻可见；`find` 在**扩大的窗口**内用文本检测搜偶发文字，由命中坐标反推元素位置；`dump` 摊开框内全部文字块以判断 ROI 粒度。

- **两处判据假阳性（已修）：** ① 关检测的识别模型**框里没东西也会强行解码**——护栏的水平高光被读成 `-`、车尾贴纸被读成 `TXT`/`甲`，据此选出过"事件横幅场景"帧而框里其实是护栏；判"真读到东西"改为要求中文/字母/数字。② 左侧面板的暗底闸门会被**深色棕榈树**骗过（暗像素占比达标、框内是树叶、读出 `D`）；面板在场判据改为「闸门 **且** 三格都读出数字」。

- **逐格复核结论：** 左侧三格与双方总分、阶段、计时器、事件横幅全部 ✅（真帧叠加逐一核对）；**移除三格**——`hp_self`/`hp_opp` 框内混进玩家名（检测实测框内两块：昵称 + `血量:97%`，识别会连成一串），且血量由积分差决定、与双方总分冗余；`center_popup` 框没浮字时压在玩家车尾、读到车贴纸/车牌，**依赖玩家所选车辆的外观**（与硬约束冲突），且浮字实测跟着车跑（横向跨归一化 x 0.38–0.59）、根本定不了固定框。

- **撤回两条结论（本轮最重要的修正）：** ① ~~「里程是累计里程、同段内单调递增」~~ ——逐帧**目视核对**得：里程是**本段**累计，同段内单调增长（268 → 338）、跨段后从较小值重新增长（338 → 272，两者之间面板长时间不在场，段的边界落在其中），合计随之一同按段重置（合计 = 里程 + 30×超车 每次读数都成立，两者同源）；而右上每方自己的分数才是阶段内累计递增的（6 → 3693），两个"分"不是同一个量。**这条结论是用目视核对立的**：先前引用的自动读数（帧 365「里程=2」）是面板不在场时的**假读**——暗色建筑骗过暗底闸门、识别模型强行解码出单个数字，据此会把"段间重置"误读成"重置到 0"。② ~~「里程 + 超车 只占总分约 12%」~~ ——该比例用"按段重置的计数 ÷ 累计总分"得出，分子分母不同期，比例无意义，**撤回**；方向性结论（累计总分绝大部分不来自左侧两项）仍与 §4.2「主要加分项＝金币」一致，但具体占比给不出。教训记为复核判据第 5、6 条：**"读数对"不等于"语义对"**；且**暗底闸门会漏、离线没有可靠的二次在场判据**（试过"标签在场"作二次判据：31 个采样帧零命中，标签字太小），消费方应以**时间连续性**（段内里程单调）作二次判据。

- **第三处复核发现（比分面板会上下互换）：** 逐帧按"带内**饱和像素**均色"判定，右上两块面板（蓝＝本机玩家、红＝对手）一段内**互换多次**（实测 25–43 蓝在上 → 49–85 红在上 → 91–391 蓝在上 → 397–565 红在上），触发条件未知。故**位置不等于敌我**——原 `score_self`/`score_opp`（及 `rate_self`/`rate_opp`）的命名正是在诱导这个错误（本轮据此产出过一条无效结论），已按位置改名为 `score_top`/`score_bottom`、`rate_top`/`rate_bottom`；新增 `block_side()` 判归属供 `overlay` 在图上标出每格当前敌我，判据取饱和像素均色而非固定采样点（固定点会被天空骗过：天空同样满足 B>R，曾据此判出"下方永远是我方"）。

### 暂存（未发布 · 待并入下一版本）HUD 读数自带「定值」位：把动画中间值与真值在记录里分开 🎚️

- **性质：** 未发版变更（`maaracing_master/plugins/speedrush/hud.py`（`SCHEMA_VERSION` 1→2）、`plugins/speedrush/CODE_WIKI.md`、`RULES.md`、`tools/experiments/speedrush_scoring/`（工具读新位）、`tests/test_speedrush_hud.py`（+5 条）；master 直接提交、不 tag）

- **起因：** 复盘工具查明卡片出现时三行数字各自**滚动爬升**到定值（实测 268→292→317→338），爬升段的值"看着合理"却只是动画中间帧——拿它算增量会得到假的分数来源，拿它验「合计 = 里程 + 30×超车」会得到假违例。这条判据若留给消费方，每个消费方都要自己重算一遍，且各自的阈值会漂移。

- **做了什么：** `HudObserver._mark_settled()` 给卡片三格（`GATED_FIELDS`）标 `settled` = **本行与上一次可信采样同值、间隔 ≤ `SETTLE_GAP_S`**；`hud_meta.json` 增 `settled_fields` / `settle_gap_s` 声明契约，消费方不必猜哪些字段有这一位、也不必抄死阈值。**`trusted` 不因未定值而变 False**：读对了就是读对了，只是"还没涨到位"——原始值一律留下、标出判定，照本模块"假读标出、不静默丢"的既定口径；`settled` 也**不进** `flags`（那是假读清单，未定值不是假读）。

- **为什么是"与上一次相同"而不是"与下一次相同"：** 写盘是流式的，这一行落盘时下一拍还不存在。代价是每段平台的第一个采样点判不出定值（标 False，少一个可用点），换来的是不必缓冲一行、也不会在异常退出时丢掉最后一行。复盘工具因此**不许自己放宽**：它优先读落盘的这一位，只对旧格式（SCHEMA 1）按**同一规则**回退重算——若允许它看未来，同一行在两处会得出不同判定，正是要避免的第二真源。合成会话验证了"落盘位是权威"（故意与重算规则相反的位被如实采信）。

- **同步：** 域 `CODE_WIKI.md` §5 记入这条常驻判据（并修掉"时间连续性不替消费方判断"的旧表述）、`RULES.md` §4.8 淡入条目改为"消费方取 `trusted and settled` 即可"、实验 README 的判据说明改指落盘位。

- **验证：** 全量 `pytest` **803 passed / 1 skipped**（新增 5 条：连续两拍才算定值、间隔超限不算定值、未读出的一拍不移动基准、settled 只落在卡片三格、meta 声明契约）；真数据复跑 `review_run check` 仍**零公式违例**（定值点由 9/9 变为 6/6——平台首个采样点按新口径不再计入，这正是"少一个可用点"的预期代价）。
