# ADR-0001：分层靠引用方向，不靠目录

- **状态**：`accepted`
- **日期**：2026-09-10（定性）/ 2026-09-11（机检口径补全）
- **决策者**：用户拍板，AI 落实施
- **相关**：[宪法 §1](../NAVKIT_V4_PLAN.md) 第 1/2 条 · [MAAFW_GUIDE §5.6](../MAAFW_GUIDE.md) · commit `5d6c320`

## 背景

MaaFramework 的 Pipeline 协议**没有命名空间**：一个 `pipeline` 目录内的所有节点名合成为一张扁平图，跨文件连接靠 `next`/`on_error` 里的**节点名字符串**（协议事实，见 MAAFW_GUIDE §5.6）。

由此产生一个诱人但错误的方案：**靠目录摆放实现 core / plugin 分离**——把通用节点放 `core/`，模块节点放 `plugins/<id>/`，以为运行时互不可见。

这个方案在实践中失效并被证实为债：`core/resources/pipeline/global.json` 曾以"大厅骨架"名义装 7 个节点，其中 6 个带 `_owner: treasure`、模板图是鉴宝入口卡片，并抄了 `treasure.__boot.dwell` 已有的 13 条全页面清单两遍——**只有一个实现时抽出来的"公共层"，内容必然全是那个实现的私货**。

**根本约束**：协议层不提供隔离手段，且一旦两侧互指，`post_pipeline` 时 PipelineChecker 校验引用闭合，必须先合并为单次 post（本项目由 `nav_graph._post_pipeline_merged` 承担）。

## 决策

**core / plugin 分离的唯一可实现形态 = 引用方向单向。** 两条红线：

1. **core 真源不得占用 `<module>.` 前缀**（模块命名空间由 `plugins/*/module.py` 自动发现）；
2. **core 真源一切"按名字指人"的位置都不得引用 `<module>.` 节点。**

「引用」的口径 = `next`/`on_error` + And/Or 按名子项 + `anchor` 对象 value（收口在 `check_truth.all_name_refs`）。
**唯一合法方向 = 业务层引用通用层锚点**；通用层不指向任何模块节点（机检零例外，无白名单）。

补充判据：**抽公共层前先回答"第二个使用者是谁、今天是否真实存在"**——答不出就不抽。

## 后果

**收益**：
- 分层红线从"靠自觉"变成 CI 机检，违规即红；
- 目录可以不存在（加载路径按存在性纳入），避免为想象中的使用者预留空壳。

**代价与约束**：
- 需要"从通用画面回到某模块"时，**不能由通用层挂出口**——必须由该模块自己在 dwell 的 `next` 里挂通用锚点。跨层回跳的责任永远在业务层。
- 公共枢纽形态被否：枢纽必然要往下游指，一指就撞红线。
- 新增 core 节点时须自查不占用模块前缀。

**被否方案**：
- **目录隔离**（把东西放 `core/` 就以为分开了）——协议层不产生隔离，是幻觉；MPE 为此另造了文件级前缀，反证协议本身没有。
- **汇聚入口白名单**（各模块的 `<id>.__boot.dwell` 作为唯一允许接口）——与机检不符且无必要，2026-09-11 定案删除。

## 证据

- **协议事实（一手）**：MAAFW_GUIDE §5.6「真源组织与分层」——节点名全城唯一、无命名空间、互指须合并单次 post。
- **机检**：[`tools/navkit/check_truth.py`](../../tools/navkit/check_truth.py) `namespace_checks`（校验器第 7 条）。
- **机检活性测试**：[`tests/test_navkit_truth.py`](../../tests/test_navkit_truth.py) —— 合成违规图必须报错、盘上真源必须零报（防校验退化成装饰）。
- **实证案例**：`core/resources/pipeline/global.json` 归位（2026-09-10），完整叙事见 MAAFW_GUIDE §5.6「过早抽象同样是债」。
- **实施 commit**：`5d6c320` refactor(navkit): 真源归位 plugin、协议形态统一 v2、分层红线入机检。
