# ADR-0009：对象身份以 2D 框为主干，3D 量按属性分级

- **状态**：`accepted`
- **日期**：2026-10-19
- **决策者**：用户
- **相关**：[speedrush CODE_WIKI §19](../maaracing_master/plugins/speedrush/CODE_WIKI.md)、局 `20261019_204308_p1`、`tests/test_speedrush_tracking.py`、`tests/test_speedrush_hybrid_distance.py`、`tests/test_speedrush_motion_plan.py`

## 背景

车速逼近前车时，同一台车的跟踪身份会因框变大、跨车道线或近簇翻跳被重建，速度窗口随之清零；单拍丢框又会让距离状态整条消失。规划器只认“到站时间”，没有时间的车在 6m 外被视为空路，等时间重新出现时只剩 0.1~0.4s，只能满舵硬躲。车身横向是在 3D 路面系里反推的，不能承担身份判据。

## 决策

1. **身份只由 2D 检测序列决定**：帧间关联先看 YOLO 框（外推框 IoU 优先；扩框/快动回退到按框尺寸归一的中心位移与尺寸比）。3D 纵深、锚点、车道横位、速度都是挂在轨道上的属性，不得用于创建、销毁或交换身份。
2. **属性失效只降级属性**：单拍丢框时，最近锚点仍在 `track_lost_hold_ms`（150ms）内则以 `HELD` 输出最近距离；超窗后该属性转 UNKNOWN，但对象保留到 2D 轨道宽限期结束。任何单一观测缺失都不得直接删除对象。
3. **规划器必须有“有距无速”域**：本车道前方、有纵深、无到站时间的车，按保守闭速折算到达时刻并据此提前避让；该域不参与命中/擦车奖励。

## 后果

**收益**：逼近阶段不再因扩框或单拍闪烁换身份；超车动作不会因一拍空窗被撤回；规划器在到站时间出现之前就开始横移。

**代价与约束**：2D 关联在框重叠的两台相邻车之间可能歧义，必须保留 IoU/中心/尺寸三重门与旧几何门作第二遍；远场小框仍走旧门。`HELD` 距离最长陈旧 150ms，只用于闪烁，不得延长到“对象已物理消失”仍当障碍。有距无速域会对前方更快的车也产生提前横移，接受这一保守代价，直到有闭速证据可用。

**被否方案**：继续在 3D/车道空间匹配并放宽容差——身份仍会被深度簇跳变打断；按 track id 做长期重识别——会臆造身份；缺属性就丢对象——正是本次故障模式；纯 IoU 关联——大车快速扩框时 IoU 会跌破阈值。

## 证据

- 实机：`debug/speedrush/20261019_204308_p1`，2002–2014 拍本车道前车 z≈38.6m、无到站时间，计划保持 -0.20；2015 拍到站时间 0.442s 后满舵，0066 帧发生接触。
- 机检：`tests/test_speedrush_tracking.py`（大框增长、横向位移、相邻车不互换身份）、`tests/test_speedrush_hybrid_distance.py`（HELD 保持与超窗回落）、`tests/test_speedrush_motion_plan.py`（有距无速提前横移、非本车道不触发）。
- 离线重放：同一 trace 上 2007 拍起计划由 -0.20 改为 -0.55，早于原 2015 拍的应急动作。
