# ADR-0017（arch-shell）：无组散行收进「其他日志」容器卡

- **状态**：`amended by ADR-0022`（**仅**决策 3「容器卡默认展开」及其代价「不能把散行折叠起来」；决策 1/2/4/5 仍有效，正文保留不改写）
- **日期**：2026-11-05
- **决策者**：用户（承载形态拍板）· AI 落实施
- **相关**：[ADR-0007](0007-contract-log-日志记录为唯一事实源双投影.md) 决策 3 · [ADR-0012](0012-contract-log-日志归属强制与内容定界.md) 决策 1/4/6 · [壳工程 README](../../apps/MaaRacingMaster.Shell/frontend/README.md)「运行日志卡片」

## 背景

GUI 日志面板并存两种排版：带组号的记录进卡片，不带组号的散行直接铺成裸文本。归属强制落地后（ADR-0012），裸文本并没有消失，也不该消失——站点登记表里有一批**真的没有归属可挂**的行：采集线程的关闭回调、GUI 请求线程的设置回显、加载期告警、组收尾之后才到达的迟到事件（这类行即使补传组号也会被日志层降级为无组）。它们与卡片混排时，读者无法区分「有意无组」和「渲染漏了」。

同时确认了一类**该归组却没归**的行：启动步骤按进程名采纳窗口句柄后，编排层那次带归属的窗口连接被前置守卫跳过，真实连接落到模块自己发起的无组调用上，连接行即成裸文本。

两件事的性质不同，必须分开定：归属丢失修在生产者侧；无归属可挂的行怎么排版，是承载问题。此前 ADR-0012 决策 6 把「前端零改动」写成规则，等于禁止回答承载问题。

## 决策

1. **无组散行收进「其他日志」容器卡**：一张容器卡只收**相邻**的散行；开出任何组卡（含组头被环形冲出时建的匿名卡）即断开序列，后续散行另起一张容器卡。面板上不再有直接铺在容器外的日志文本行。
2. **容器卡不承载生命周期**：不给状态徽章，不按内容或行数推导状态；卡头承载首行时间与正文条数计数。组卡徽章仍只吃 `group_start/group_end` 的 `outcome`（ADR-0007 决策 3 的「前端不推导」约束不变）。
3. **容器卡默认展开**：散行多为告警与异常，折叠会把「发生即红」藏进卡体；组卡仍默认折叠。
4. **归属仍归生产者**：能归组的日志必须在生产者侧归组，容器卡不是漏归组的兜底。ADR-0012 的站点登记与机检照旧拦新增裸行，登记完备性不因本条放松。
5. **级别承载不变**：正文行的级别仍由文字色承载（WARNING 琥珀 / ERROR 红），容器卡不给整行色、不加彩点。

## 后果

**收益**：

- 面板一种排版语义：卡片是正文容器，容器卡是跨切面与迟到事件的容器，读者不再需要靠「有没有边框」判断系统是否漏画。
- 异常与告警的可见性不因收进卡片而下降（默认展开 + 级别色保留）。
- 承载与归属解耦：改渲染不再被理解为「可以在前端补归属」。

**代价与约束**（后续开发者会因此做不了什么）：

- **不能把「前端零改动」当作默认约束**：承载可以改，但只能改承载——不得用渲染兜住生产者漏掉的归属（那是 ADR-0012 决策 1 的机检要红的情形）。
- **不能给容器卡挂 `outcome`**：它没有起止，任何徽章都会伪造一次不存在的生命周期。
- **不能按容器卡推导运行状态**：它按相邻性分张，一张不等于一次运行、一个线程或一个模块。
- **不能把散行折叠起来**：折叠等于把告警藏进点击里。

**被否方案**：

| 方案 | 否决理由 |
|---|---|
| 给跨切面事件开一个常驻兜底组 | 违反 ADR-0012 决策 4（组只由业务层两处开）与 ADR-0007 决策 2（组边界由业务层声明）；常驻组恒「进行中」，徽章语义是假的 |
| 每条散行各建一张卡 | 一次设置回显两行就出两张同名卡，卡片数量与工作量脱钩 |
| 容器卡按最坏级别挂徽章 | 前端从内容推导状态，正是 ADR-0007 决策 3 退役掉的做法 |
| 维持裸文本不动 | 混排无法区分「有意无组」与「渲染漏了」，两轮真机反馈都因此误读 |
