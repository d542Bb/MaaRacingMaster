# ADR-0013：游戏进程归 core，启动/关闭作为内置步骤

- **状态**：`accepted`
- **日期**：2026-10-29
- **决策者**：用户（拍板「静默启动游戏主程序」「退出并入关闭游戏卡」）· AI 落实施
- **相关**：[core/CODE_WIKI.md §1.17](../../maaracing_master/core/CODE_WIKI.md) · [AGENTS.md](../../AGENTS.md) 绝对红线 1（分层靠引用方向）· [core/registry.py](../../maaracing_master/core/registry.py) · [core/builtin_steps.py](../../maaracing_master/core/builtin_steps.py) · [core/game_process.py](../../maaracing_master/core/game_process.py)

## 背景

此前"游戏怎么起、跑完怎么关"散在三处：用户手动先开游戏；设置页两个开关（关闭游戏进程 / 退出 MaaRM）在整轮正常完成后收尾；连接失败时只报"未找到游戏窗口"。任务列表只能装活动模块，模块契约是「阶段 / 断点 / 有效期 / 性能行 / 自带资源」。

要求变成：像 MaaEnd 那样把「启动游戏 / 关闭游戏」放进同一条任务列表，能拖、能勾选、能配。随之要定三件事——这两件事归谁、以什么形态进列表、原来的两个开关怎么办。

同时确认了平台事实：官方启动器起游戏前做版本比对与逐文件 MD5 校验；游戏主程序可直接拉起，13s 出窗口、39s 登录完成进大厅；启动器窗口与游戏窗口**同名**（都是「巅峰极速」）。

## 决策

1. **游戏进程归 core**：定位安装、直启、等窗口、关闭收在 `core/game_process.py`。插件不得自行启停游戏，也不得反向操纵窗口句柄——那是把分层方向拧反。
2. **新增「内置步骤」种类**：与活动模块共用任务列表、执行器与配置持久化，但**不进活动模块注册表**（`MODULE_REGISTRY` 仍只有插件）。步骤契约只有 `ID / NAME / DEFAULT_CONFIG / run(config, stop_event, log)`——跑一次、可被停止。
3. **找窗口按进程名，不按标题**：启动器与游戏同名，标题匹配会认错窗口。启动步骤认准窗口后把句柄交给连接层（`adopt_window`），连接时不再按标题搜。
4. **「运行结束后」不再由设置开关承担**：关闭游戏是步骤；「退出本程序」是它卡上的一个选项（`exit_app`）。步骤请求退出后，本轮自然完成时发退出事件，**剩余步骤按中止处理**——语义在界面上一句话写清，不在实现里加特判。
5. **旧开关一次性迁移**：`auto_close_game` → 队列末尾补一个关闭游戏步骤；`auto_exit_mra` → 该步骤打开退出选项。迁完从 profile 删键，不重复迁移。

## 后果

**收益**：

- 一处真相：进程启停只有一份实现，设置页不再有"结束后做什么"的开关组。
- 顺序可编排：启动、活动、关闭、退出在同一条列表里，位置由用户拖；手动停止或报错天然跳过队尾步骤，不需要额外判定。
- 断点/有效期/资源徽标这些活动模块概念不会被空壳模块污染。

**代价与约束**：

- 队列的 id 校验、配置槽、资源徽标、断点设置都要按「两种种类」分支；新增第三类步骤时要回到这些点。
- 步骤启动会清 `stop_event`（与 `start_module` 同理），停止信号的"唯一 clear 位置"从一处变两处，改动生命周期代码时必须同时看这两处。
- 直启跳过启动器的版本校验：游戏更新后首次可能起不来，靠「等窗口超时 → 回退启动器」兜底；回退会弹启动器窗口，属可接受的降级。
- 插件从此不能自己决定"跑完关游戏"——要关就往队列里放步骤。

**被否方案**：

- **做成插件（`plugins/gamehost`）**：活动模块契约要求阶段与断点，会得到零阶段的空壳；插件目录的语义是"某个玩法的实现"，进程启停不属于任何玩法；关闭游戏已有 core 实现，挪进插件等于跨层两份真相。
- **直接注册进 `MODULE_REGISTRY`**：UI 上会与活动卡并排显示有效期与资源徽标，语义错；断点、阶段进度、性能行都要逐个特判。
- **保留设置页两个开关**：与「关闭游戏」步骤构成两份真源，用户会问"两个都开了会关两次吗"。
- **只走官方启动器**：慢（启动器窗口约 6.6s 才出现，还要等校验），且多一个同名窗口要排除；实测没有任何"必须经由启动器"的校验点。

## 证据

- 实证（真机，2026-10-29）：直启 `g112-Win64-Shipping.exe` 后 13.2s 出窗口（`UnrealWindow`，标题 `g112` → 加载中变「巅峰极速」）、37s 进入登录流程并加载大厅地图、39s `OnLoginDone, code = 0` 进大厅；全程无启动器窗口、无人工登录、无反外挂弹窗。关闭：按窗口进程结束，2s 内退出。
- 一手核查：游戏自身日志 `LogInit: Command Line` 给出实际命令行（`-nosound -nohmd --MuMuLauncher -noexceptionhandler -Hdd -force_load_content`）；启动器日志记录 `real_start_game` 前后的校验与参数拼装；启动器文案表 `T_STANDARD_GAME_TITLE` 与游戏窗口同名。
- 机检：`tests/test_sidecar_run_queue.py`（两种种类按序执行、退出请求中止剩余、失败/手动停止中止）、`tests/test_sidecar_profile_restore.py`（旧开关迁移与清键）、`tests/test_rpc_allowlist.py`（RPC 三方一致）。
- 实施后复核：`python -m pytest tests` 全绿（1489 passed / 12 skipped）。
