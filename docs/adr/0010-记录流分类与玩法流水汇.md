# ADR-0010：记录流三分与玩法流水汇

- **状态**：`accepted`
- **日期**：2026-10-25
- **决策者**：用户（方案四轮评审后批准，含「玩法流水一个档、通用接法」裁定）
- **相关**：ADR-0007（日志为唯一事实源；本条是其后果③预留位的兑现）；`core/CODE_WIKI.md`（core 层实现现状）

## 背景

三条记录流的历史形态是实现巧合而非设计：玩法流水有**两个家两把闸**（鉴宝=会话目录同步写手、随日志开关；竞速=调试目录每 100 拍同步批写、随调试总开关——竞速当年是躲同步写盘才自建一套）；性能观测无立户（竞速性能卡是静态占位）。2026-10-25 卡顿排查（十七局一遇的整机图形栈停摆）暴露观测面缺口后统一收口。

## 决策

1. **记录流三分 + 两把闸**：日志（结构化全事件流）/ 玩法流水（各模块逐拍状态）/ 性能（系统与进程资源）三条流同受「日志记录」开关、同落会话目录 `logs/<会话token>/`；调试总开关收窄为**图与帧证据**（HUD/raw/坏帧/证据包），与三流互不牵连。判据是「谁读、何时读、多大代价」，不是媒介（文本/图像）。
2. **玩法流水汇是 core 通用件**（`core/trace_sink.py`）：模块声明即用（`get_trace_sink("<模块>")`，接线 ≤10 行），每模块每会话一个文件 `trace/<模块>.jsonl`。契约要点：序号在会话生命周期内单调、跨 `run_id` 不重置、换会话归零；提交先预留序号再判定（超大/队满拒收的序号进空洞）；丢弃以带内 gap 标记表达——非连续丢弃必须拆成多个区间、按逻辑序号归并定位；阶段边界是受保护的可回放控制记录（保护通道满员时合并相邻「结束→开始」或显式拒收）；flush/close 是纯同步屏障，不写文件不占序号；关闭超时/IO 失败即终态化（不复活不重试），文件尾三态 `end`/`close_incomplete`/无标记，硬杀损失=最后写入位置+未落队列。
3. **会话生命周期协议归 logger**（唯一属主，回调是协议不是分权）：`OPEN→CLOSING→CLOSED` 状态机经独立生命周期锁串行；会话 token 带短单调后缀（同秒反复开关不重名，保留清理兼容新旧目录名）；回调在记录锁外执行（回调内可安全 log）；关闭顺序=写手有界排空→收尾状态记账→主日志最后关（写手收尾诊断仍能落进本会话文件）；清理不等任何补写。navkit `TraceWriter` 不动不扩展，鉴宝零改动（其现状即通用汇形态的先例）。
4. **性能流独立双时钟轴 + 三方供数**（`core/perf_sampler.py`）：样本带 `ts_wall_ns`/`ts_mono_ns`/`sample_id`——性能诊断要与 Windows 事件日志等外部时间轴对表，故不并入玩法流水的帧号轴。core 采样器供资源面（系统/受管进程 CPU 与内存、GPU 系统级读数带 ok/timeout/unavailable 状态位，nvidia-smi 子进程带超时），活动模块经鸭子类型接口（`read_perf_snapshot`）供领域项（response/health），sidecar 聚合成带 `schema_version` 的 perf 载荷、不可用显式化（不伪装零值）。落盘三档：低频背景（每 N 样本一个）/ 事件倾倒（模块经通用观测接口报事件，前后窗样本补落，**每样本只写一次**，重叠窗口靠同一标记去重；窗口被会话关闭中断记 incomplete）/ 收尾全量（可配关）。环形缓冲随会话切换重置，关闸期样本永不进入新会话文件。

## 后果

**收益**：新模块接流水=声明式；竞速热路径的周期性同步批写消失（实测见证据）；调试开关语义回到「取证图」；竞速性能卡有数且 0.5s 级刷新；停摆类故障有断档前后证据窗。

**代价与约束**：模块 append 热路径多了序列化与入队（约定行大小内 p50 +0.12ms/拍，p99 反降——8.3ms 批写尖峰消失）；关闭日志开关从「立即」变「有界排空」（默认 2s，超时终态化）；会话目录多 `trace/` 与 `perf.jsonl`；前端 perf 载荷 `schema_version=2`（cpu 段改由 core 供数，键形兼容）。

**迁移与兼容**：竞速旧列名在新格式逐字保留（协议头是新增键，不覆盖旧键），帧证据（raw/hud/坏帧）仍留调试目录（新局按阶段时间窗桥接对齐）；局汇总同迁会话目录且列结构不变。旧离线消费者的迁移裁定：历史文件不动、旧探针对旧数据照常可用，新产物由实验区统一读取器承接（读取器与消费者登记台账随本批落地入库）。**被否方案**：① 按媒介分开关、流水两档两把闸（用户裁定：要给未来设计好的通用接法，一个档）；② 扩展 navkit TraceWriter（冻结的鉴宝依赖它）；③ 停摆期间因果归属承诺（进程内采样器做不到——断档推不出因果，V1 承诺=断档检测+前后证据保存）；④ 独立哨兵进程（V2 可选，未立项）。

## 证据

- 实现：`maaracing_master/core/trace_sink.py`、`core/perf_sampler.py`、`core/logger.py`（会话生命周期协议与 token 后缀）、`plugins/speedrush/module.py`（接线：~15 行声明+逐拍 append+阶段边界）、`core/sidecar.py`（perf 聚合与采样器常驻）。
- 机检：`tests/test_trace_sink.py`（序号作用域/预留状态机全表/非连续 gap 拆分/屏障不留假缺口/保护通道满员可关闭/超时终态与三态尾/硬杀无标记判定/同秒 token 隔离/logger 生命周期与保留清理）、`tests/test_perf_sampler.py`（GPU 三态显式与粘性/背景档/事件倾倒唯一落盘/重叠窗口去重/中断 incomplete/环随会话重置/聚合纯函数）。
- 实测（2026-10-25 本机，1200 拍 × 20Hz 同规模行）：异步汇每拍体耗时 p95 0.28ms / p99 0.35ms / 最大 0.52ms、最大拍间隔 50.94ms、阶段收尾合计 0.41ms；旧路径每拍 p95 0.085ms 但批写拍尖峰 8.3ms、单批写盘 p50 6.8ms、最大拍间隔 58.3ms。真探针回放：同探针代码跑旧布局与转换后的新布局，整跑报告逐字节一致；协议行对朴素加载器的影响已量化（1/22 元素）且统一读取器可剥离后严格等价。
