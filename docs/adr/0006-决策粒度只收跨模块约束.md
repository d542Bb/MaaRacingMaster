# ADR-0006：ADR 只收「跨模块约束」——子系统形态归子系统文档

- **状态**：`accepted`
- **日期**：2026-09-18（维护者拍板：形式上新写粒度规则，实质上把越界条目搬回子系统 README）
- **决策者**：用户拍板，AI 落实施
- **相关**：[本目录准入条件](README.md) 第 3 条 · [ADR-0005](0005-GUI标题栏移除系统标题栏.md)（迁出的实例） · [apps/MaaRacingMaster.Shell/README.md](../../apps/MaaRacingMaster.Shell/README.md)（迁入的住户）

## 背景

准入条件第 3 条一直写着"**架构级** —— 影响跨模块结构、分层、协议或运行时拓扑；**实现细节与域内坑点不收**（归对应 `CODE_WIKI`）"，但**缺一条可自检的判据**——收录时实际是按"这决策听起来重要吗"在判，于是 [ADR-0005](0005-GUI标题栏移除系统标题栏.md) 进来了：它记的是 GUI 壳**内部**的窗口形态（`SetBorderAndTitleBar(true, false)`、`win-controls` 消息、`InputNonClientPointerSource` 矩形上报、置灰联动删除），约束对象是"前端与 C# 怎么对接"，管不到任何别的模块；而它正文自己又把 `apps/MaaRacingMaster.Shell/README.md` 列为"施工事实"——**同一形态在一份 ADR 与一份子系统 README 两处讲，正是本目录立项时要防的第二份真源**。

维护者 2026-09-18 指出这点（"ADR 怎么把所有业务层级都包含了，这不对吧"），并裁定按"彻底"档处置。

## 决策

**ADR 只收有「跨模块约束力」的决定**，自检问句：

> **这个决定会让哪个*别的*模块 / 层的人做不了什么？答不出，就不进本目录。**

按内容形态的住户：

| 内容 | 住户 |
|---|---|
| 约束 core 与各模块、或各子系统之间（分层 / 协议 / 运行时拓扑 / 进程边界 / 打包形态） | 本目录（ADR） |
| 某子系统内部的形态、API 用法、类名 / 消息名 / 坐标等实现细节 | 该子系统 `README.md` |
| 域内定案与坑点 | 该模块 `CODE_WIKI.md` |

配套的两条：

1. **ADR 是"决策与状态"的索引，不承载各业务层的知识**——同一形态/口径只许一个住户，ADR 只写「决策 + 理由 + 后果 + 指针」。
2. **不要为了"重要/常查"破格**：若某子系统形态将来真的约束到别的子系统（例如窗口控制协议被第二个宿主复用），那是**新的**跨模块决定，另写一条 ADR，而不是把迁出的条目复活。

**迁出实例（本次落地）**：ADR-0005 的四条形态、被否方案与理由整体迁入 [apps/MaaRacingMaster.Shell/README.md](../../apps/MaaRacingMaster.Shell/README.md)「窗口形态与标题栏」一节；0005 标 `deprecated`（**条目本身**迁出，形态仍在生效）；0004 的状态注记改指该 README；指向 0005 的其余指针（壳工程 README、前端 README、[docs/CODE_WIKI.md](../../docs/CODE_WIKI.md)）同步改指。

## 后果

**收益**：

- 收录判据从"听起来重要吗"变成一句可自检的问句，越界在写之前就能拦住；
- 子系统形态回到其子系统文档，不再两处并存、各自腐坏；
- ADR 目录保持"打开就能看完"的规模，只留真正约束别人的决定。

**代价与约束**：

- 查**窗口形态的取舍理由**要去 `apps/MaaRacingMaster.Shell/README.md`（L2），不再在 L1 目录里——这是**有意的层级下移**：子系统形态本就不是架构事实；
- 反过来说，**准入条件第 3 条的判据此次并未放宽，而是收紧了**：从"有没有长期约束力"补上"约束的是谁"。

**被否方案**：

- **放宽准入，让 ADR 也收子系统定案**——ADR 立刻退化成第二份真源（同一形态在两处各自腐坏），且"决策索引"与"实现文档"混作一谈；
- **原地改写 0005 正文、把细节删掉**——违反状态机"禁止原地改写已 `accepted` 的正文"，历史理由会丢。
