# ADR-0019（arch-core）：一次运行是一条时间线——调试流、生命周期与身份统一

- **状态**：`amended by ADR-0021`（仅「运行编号作为唯一身份」与「调试目录按运行编号分组」两部分；分段、预览、模块取证、全局性质与界面约束仍有效）
- **日期**：2026-11-05
- **决策者**：用户（方向裁决：先做地基，界面属未来可选）
- **相关**：ADR-0010（记录流三分）、ADR-0018（启动步骤与资源所有权）、`core/CODE_WIKI.md`（调试流 / 控制器 / 日志）

## 背景

同一次队列运行里的证据被拆成几套互不相认的记录：调试流按段平铺、模块取证另立目录、日志只有秒级时间、玩法流水与性能各有身份，段边界没有时间；全局性质（静音、停止、运行态、退出请求）由模块与步骤各自设置、各自恢复，换项时会恢复再设置，停止请求还会被下一项入口清掉。结果是「一条日志、一帧、一行流水、一个卡顿点」无法可靠对齐，调试画面在导航步骤之间反复闪空。

## 决策

1. **一次队列轮次 = 一个运行编号，是所有流的唯一身份**。日志记录、轮次事件、调试索引、玩法流水、性能样本共用它；日志与调试索引的所有事件带墙钟纳秒与单调钟纳秒，`HH:MM:SS` 只是显示投影。序号作用域各自独立（日志会话、调试运行、流水文件、性能采样），不合并。
2. **调试流按执行器分段，段归属在入队时固定**。帧在入队时携带所属段、阶段、外层运行项与开关状态；队列满只淘汰帧，控制事件不参与淘汰；收尾先排空、再写段结束，超时剩余帧计入 `pending_at_close`。
3. **存盘目录按「运行项 / 执行器」分组，不按时间顺序编号**：`debug/<运行编号>/<模块>/<执行器>/<全局帧序号>.jpg`。目录只回答「谁的」，顺序与时间由索引承担；新增/删除执行器不牵动其他模块的路径。
4. **预览不跨运行项残留**：作用域边界清空；同一运行项内的执行器切换保留最后一帧直到新段首帧，避免逐段闪空。
5. **模块自有取证不复制**：模块以 `DEBUG_SAVE=self` 声明，统一流只记段边界与取证路径，帧仍走模块自己的格式与目录。
6. **运行级全局性质按「运行」获取与释放**：静音在运行边界执行一次、记录并恢复用户原音量；停止请求保留到整轮结束，项入口只在非手动停止时清项内信号；运行态判据同时供后端校验与前端锁定/高亮；退出请求按轮清零。
7. **界面不是地基**：运行编号与相对时间只进诊断信息与索引，不作为主界面文案；是否展示留给后续独立决定。

## 后果

**收益**：一次运行的所有证据可按运行编号与双时钟互相对齐；模块增删执行器不再影响目录与其他模块；停止、静音与运行态不再跨项泄漏；调试画面不再随导航步骤闪空。

**代价与约束**：调试目录多一层模块目录，旧运行目录不迁移；模块不得自行设置或恢复全局性质，也不得在 `cleanup()` 里改音量/停止请求；界面不能把原始运行编号当作主文案。

**被否方案**：① 目录使用 `00_` / `01_` 顺序前缀——执行器增删会牵动后续编号，顺序信息本就在索引里；② 把模块取证复制进统一目录——同一帧两份，违背 ADR-0010 的模块自有取证裁定；③ 让模块/步骤各自拥有静音与恢复——必然出现项间恢复/再静音空隙；④ 先做时间轴界面——表现层不能替代身份与时钟的地基，且用户暂不要求。

## 证据

- 机检：`tests/test_debug_stream_contract.py`（入队绑定、淘汰下的计数闭合、排空 pending、预览连续性、新旧布局）、`tests/test_controller_step_link.py`（运行边界、停止不被清、静音原值恢复、窗口句柄失效）、`tests/test_logger_records.py`（运行编号与双时钟）、`tests/test_sidecar_run_queue.py`（轮次事件身份）、`tests/test_window_search_noise.py`（轮询静默）。
- 真机：日志会话 `20261105_164539` 核对到整轮只静音一次并在结束恢复原值；调试索引记录到 26 个导航段，逐段清空即为预览闪断来源；项与项串行执行，无并发模块。
- 全量回归：1961 passed / 12 skipped；仓库卫生检查通过。
