# ADR-0025（arch-shell）：自动展开收窄为真异常

- **状态**：`accepted`
- **日期**：2026-11-07
- **决策者**：用户（真机反馈「展开的卡片还是太多了，只有真异常才展开」）· AI 落实施
- **相关**：[ADR-0024](0024-arch-shell-日志面板读侧叙事视图.md)（仅决策 2 的「渲染即展开」与决策 3 的展开范围由本条收窄；渲染门槛、复制全量、组卡正文不裁剪仍有效）· [ADR-0022](0022-arch-shell-界面反馈只承载阶段进度与影响结果的异常.md)（「收起之后散行没有严重度摘要」的接受范围随本条扩大）· [壳工程 README](../../apps/MaaRacingMaster.Shell/frontend/README.md)「运行日志卡片」

## 背景

ADR-0024 落地后的实跑观察：`warning` 收尾的组卡（驾驶阶段的可继续降级）与手动停止的 `incomplete` 卡都会自动展开——展开成为常态而非信号，摊开的正文（十几行节拍细节）反而把面板吵回去。展开要当信号用，就必须只留给用户没有预期的东西。

## 决策

1. **组卡仅 `failure` 收尾且有正文时自动展开**；`warning` 与 `incomplete` 由卡头徽章承载信号，保持折叠——警告是可继续的降级，手动停止的原因用户自己刚按下，都不需要摊开正文。
2. **收容卡渲染门槛不变**（含 WARNING+ 行才落 DOM），但仅含 ERROR 行时展开；WARNING-only 的收容卡渲染后保持折叠，卡头计数是唯一在场信号（无徽章的承载代价 ADR-0022 已接受）。
3. **截断提示仍无条件可见**——它是系统级提示，不走告警通道。

## 后果

**收益**：展开重新成为信号；绝大多数情况面板只有卡头骨架，噪音回到骨架这一层。

**代价与约束**（后续开发者会因此做不了什么）：

- **WARNING 级异常的正文从「默认可见」退到「徽章/计数可见、点击查看」**：ADR-0022 的接受代价从散行扩大到组卡警告正文；需要即时可见的 WARNING 必须在生产者侧升级表达（或提升级别），不得要求读侧特判。
- **「告警必显」的口径收窄为「真异常必显」**：failure/ERROR 的正文仍默认摊开，这条不退。

**被否方案**：

| 方案 | 否决理由 |
|---|---|
| warning 也展开但只摊告警行、藏 INFO 行 | 读侧按内容裁组卡正文，违反 ADR-0024 决策 4；且前端要逐行判内容 |
| incomplete 保持展开 | 停止动作是用户自己按的，原因已知，摊开没有信息增量 |
| 维持 ADR-0024 原范围 | 真机观察：展开常态化后信号失效，面板回到噪音状态 |

## 证据

- 实现：[`js/log.js`](../../apps/MaaRacingMaster.Shell/frontend/js/log.js)（`group_end` 仅 `failure` 展开；容器仅 ERROR/截断提示展开，WARNING-only 渲染折叠）。
- 机检：桥桩探针混合批次断言——警告组折叠、未完成组折叠、失败组展开、WARNING-only 收容卡渲染折叠、含 ERROR 收容卡渲染即展开、纯 INFO 缓冲不落 DOM；[`tests/test_log_attribution.py`](../../tests/test_log_attribution.py) 等回归锁全绿。
- 真机：用户实跑反馈（2026-11-07，展开过多）即本条的起因与验收输入。
