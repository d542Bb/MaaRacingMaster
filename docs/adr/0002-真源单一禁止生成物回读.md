# ADR-0002：真源单一，禁止生成物回读

- **状态**：`accepted`
- **日期**：2026-09-08（宪法定稿）/ 2026-09-10（P4 落地）
- **决策者**：用户拍板，AI 落实施
- **相关**：[宪法 §1](../NAVKIT_V4_PLAN.md) 第 1 条 · [MAAFW_GUIDE §5.6](../MAAFW_GUIDE.md) · `docs/plan/v4-p4-retire.md` · commit `b9e3b3f`

## 背景

v3 时代的真源是**五套并行概念**——`anchors` / `stages` / `transitions` / `routes` / `policies` 各为一份 schema，外加一层**编译映射**把前四者编译成 MaaFramework pipeline 节点，生成物落在 `generated/pipeline/` 与 `<id>_assets.json`。

后果是**三份结构必须靠 parity 测试维持一致**：真源（五段 JSON）、图投影（`graph_api` 手写的第三份逻辑——routes 边无节点、policies 不进图、global 段不在数据里）、运行时 pipeline。任何一处改动都要同步三处，否则漂移。

更根本的是：MaaFramework 生态已经给出标准答案——**pipeline 节点即真源**，且已有成熟可视化编辑器（MPE）。自研的五段 schema + 编译器是对协议能力的重复发明。

## 决策

**逻辑只存在于节点 JSON（+ 策略表文件）。生成物禁止落盘再被运行时读取，只允许内存临时存在。**

配套判据：**加逻辑 = 加节点 / 改连线 / 改策略表，不写 Python**。写 Python 仅限引擎能力本身（新识别、新动作），且引擎代码永远不感知业务语义。

落地形态（v4 真源三件套）：
- `core/resources/pipeline/global.json`（通用层）
- `plugins/<id>/resources/pipeline/<id>.json`（业务层）
- `plugins/<id>/resources/policy/<id>.policy.json`（策略表）

## 后果

**收益**：
- 结构从三份收敛为一份，parity 测试随之消亡（它维持的正是本不该存在的不一致）；
- 编辑闭环打通：MPE 画布编辑 → 保存 → 引擎直接跑，中间无转换步骤；
- 运行时不再有"生成物比真源旧"的漂移可能。

**代价与约束**：
- **加载时内存内透传映射可以，落盘转换不行**——需要中间表示时只能活在内存里，不能写文件再读回；
- 想加新逻辑时**不能写 Python 绕过去**，必须先想清楚它在节点/策略表里怎么表达；确有引擎级需要（新识别/新动作）才动 Python，且引擎不得感知业务语义；
- 引入任何"节点/策略表"以外的概念都需过宪法第 5 条准入制（写清替代什么、何时能删）。

**被否方案**：
- **五段 schema + 编译层**（v3 形态）——三份结构靠测试维持一致，整代返工；P4a 一次性删除 **-18,757 行**（commit `b9e3b3f`）。
- **`generated/` 落盘生成物 + 运行时读取**——生成物与真源可能不同步，且"哪份是准的"永远模糊。
