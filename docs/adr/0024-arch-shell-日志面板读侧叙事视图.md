# ADR-0024（arch-shell）：日志面板读侧叙事视图

- **状态**：`amended by ADR-0025`（决策 2 的「渲染即展开」与决策 3 的展开范围由 [ADR-0025](0025-arch-shell-自动展开收窄为真异常.md) 收窄为真异常；渲染门槛、复制全量、组卡正文不裁剪仍有效）
- **日期**：2026-11-07
- **决策者**：用户（拍板「面板=用户叙事」方向与三项规则）· AI 落实施
- **相关**：[ADR-0007](0007-contract-log-日志记录为唯一事实源双投影.md)（记录唯一事实源双投影——本条全部收敛发生在渲染层）· [ADR-0012](0012-contract-log-日志归属强制与内容定界.md)（决策 6 余留句的取代范围在本条明示）· [ADR-0017](0017-arch-shell-无组散行收进其他日志容器卡.md)（决策 2 不动）· [ADR-0022](0022-arch-shell-界面反馈只承载阶段进度与影响结果的异常.md)（决策 1/4 的延伸；被否方案④的适用范围在本条划界）· [壳工程 README](../../apps/MaaRacingMaster.Shell/frontend/README.md)「运行日志卡片」

## 背景

日志面板的两类读者长期共用一套显示规则。组卡正文里混着玩家要看的进度与结局，也混着配置注入、截图采集就绪、导航坐标这类开发者细节；无组散行收进「其他日志」容器卡后，设置回显、注册表优化、启动家务与真实告警同屏，列表上一排计数胶囊读不出轻重。开发者视角的全量出口早已另有归宿：文件日志单流全量（DEBUG 在内）、玩法流水与调试目录（ADR-0010 三分立户），面板收敛不损失任何诊断材料。

生态对照（MAA 官方客户端、MFW-PyQt6、MFAAvalonia、MXU）：「策展面板 + 全量文件 + 打包/复制出口」是 MAA 生态的通行分工，四个壳无一例外在回调入口策展（成功静默、失败/告警必显），原始日志一律只进文件；壳与壳之间没有共享的日志组件。方向属跟随主流，不引入生态轮子；机制上本项目的组生命周期与站点登记比各壳的「手动投递列表 + 颜色反推级别」更结构化。

## 决策

1. **面板默认视图 = 用户叙事**：卡头骨架（组卡标题与结局徽章）永远可见，即进度叙事层；正文与收容卡按下列两条收敛。
2. **收容卡渲染门槛**：容器卡含 ≥1 条 WARNING/ERROR 行才落 DOM，此前缓冲的行随卡按原时序插入，渲染即展开（告警必显）；纯 INFO 容器（设置回显、注册表优化、启动家务、静音边界行）不渲染。截断提示无条件可见。可见性由渲染门槛承载——容器卡仍无徽章、不按内容推导状态（ADR-0017 决策 2 不动）。
3. **组卡结局驱动自动展开**：`group_end` 的 outcome 为 `warning`/`failure`/`incomplete` 且卡有正文时自动展开；`success` 保持折叠。由 outcome 驱动（ADR-0007 决策 3 的许可载体），前端不读正文内容；空身卡不展开，与「可点性=内容存在」同口径。
4. **组卡正文不做行级裁剪**：开发者细节从正文退出走生产侧（降级 DEBUG、迁流水、文案玩家化），逐模块进行；读侧不为组卡做任何按内容的隐藏。
5. **复制不受收敛影响**：复制永远等于本次会话收到的全部 INFO+ 记录（含被隐藏行），与文件日志按 seq/组号可对照（ADR-0007 决策 1 的既有形状）。数据通道不新增过滤——收敛只发生在渲染层，文件投影不减。
6. **ADR-0022 被否方案④的适用范围划界**：该句否决的是「按级别把告警裁出面板」的读侧裁剪（诊断完整性）；本条的收敛按「叙事/家务」划线、告警必显、全量仍在文件与复制，不属该被否情形。ADR-0012 决策 6 余留句「前端零改动」的渲染承载由本条接管。
7. **静音边界行不豁免**：有意无组的跨切面 INFO 行随家务隐藏；「用户相关 INFO」的放行将来走生产侧的显示类别标记协议，前端不按行文本特判。

## 后果

**收益**：面板默认只剩进度叙事与告警——卡头讲到了哪一步、结局徽章讲结果、警告卡自动摊开原因；家务行与开发者细节各归复制/文件/流水；卡头骨架的表达与生态先例（MAA 按任务链分节）同型。

**代价与约束**（后续开发者会因此做不了什么）：

- **不能给收容卡挂徽章或严重度摘要**（ADR-0017 决策 2 与 ADR-0022 代价条不翻案）——可见性只能走渲染门槛与自动展开。
- **不能在数据通道按显示策略裁事件**：文件、复制、面板三者同源，隐藏行的去处只有「不显示」，没有「不下发」；DEBUG 依旧不进 GUI，闸门维持 INFO。
- **不能靠读侧让某条 INFO 常驻可见**（如静音边界行）：需要时走生产侧标记协议，逐条立项。
- **组卡正文的开发者行不会因本条消失**：那是生产侧逐模块的工作，读侧不裁。

**被否方案**：

| 方案 | 否决理由 |
|---|---|
| 给整轮开一张常驻组卡收纳静音行 | 徽章语义为假（整轮恒「进行中」），且把恢复音量行藏进页面顶部远端，尾部可见性变差 |
| 读侧按级别全线过滤（面板只显 WARNING+） | 撞 ADR-0022 被否方案④的口径；组卡正文的叙事行也会被误伤 |
| 前端按行文本特判放行个别 INFO | 「前端不推导」的口子一开就收不住；放行需求走生产侧标记协议 |
| 收容卡照旧渲染只折叠 | 面板改善有限：计数胶囊与家务卡头仍是主要噪音 |
