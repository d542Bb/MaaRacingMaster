# ADR-0022（arch-shell）：界面反馈只承载阶段进度与影响结果的异常

- **状态**：`accepted`（被否方案④的适用范围由 [ADR-0024](0024-arch-shell-日志面板读侧叙事视图.md) 划界：按叙事/家务收敛且告警必显的读侧分层，不属「按级别裁剪」）
- **日期**：2026-11-06
- **决策者**：用户（拍板「显示不对称」：成功回执整句删除、散行容器默认收起、警告色只留给影响结果的事）· AI 落实施
- **相关**：[ADR-0017](0017-arch-shell-无组散行收进其他日志容器卡.md)（取代其决策 3 与「不能把散行折叠起来」那条代价，其余仍生效）· [ADR-0016](0016-contract-core-模块配置面板由插件声明宿主渲染.md) 决策 4 · [ADR-0012](0012-contract-log-日志归属强制与内容定界.md) · [壳工程 README](../../apps/MaaRacingMaster.Shell/frontend/README.md)「模块配置面板」「运行日志卡片」· [`js/rpc.js`](../../apps/MaaRacingMaster.Shell/frontend/js/rpc.js) 错误通道协议

## 背景

后端早就定了不对称的分级口径：级别表把里程碑归 INFO、可继续的降级归 WARNING、不可恢复归 ERROR，产出侧另有「不带结论的行不记 / 稳态重复改边沿触发 / 失败链首次必记其后节流」三条判据（ADR-0012 与 `core/CODE_WIKI.md` 日志节）。显示侧没有对应规则，四个通道各自为政：

- 配置面板每次写入成功都闪一句「已保存」，判据只是「RPC 返回成功」，与用户改的是哪个字段无关。切一下驾驶模式也刷这句，在宏录制档下被读成「宏已保存」。更糟的是这句话会在两种情况下说谎：偏好落盘失败只记日志警告（sidecar 既有语义），非法档位被模块静默忽略但 RPC 仍成功。
- 设置页把错误通道 toast 用来播成功（「已完成 N 项权限优化」「已忽略启动提醒」）。
- 面板状态行用 `warn` 级报「本次未开启录制」——一件不是错误、且任务卡摘要已经写了的事。
- 无组散行容器默认展开，把可继续的降级与致命异常铺在同一屏（ADR-0017 决策 3 当初的理由是「散行多为告警与异常」）。

反馈与信号等量时，用户读不出哪条要看；宏档下的误读是这条约束要防的具体失败模式。

## 决策

1. **界面反馈只承载两类内容**：阶段进度（执行到哪了）与会让本次运行达不到预期的异常。成功回执、常规确认、非错误的状态提醒一律不占行内、toast、modal 任一通道；要给用户看的东西由控件自身状态、任务卡摘要或卡片徽章承载。
2. **写入类操作成功静默**：配置保存成功后状态行回落到模块声明的 `_status`，不闪回执；失败仍走行内红字停留。落盘失败只在日志留 WARNING——本条不改动 sidecar 的落盘语义，只停止用一句成功话掩盖它。
3. **警告色只用于影响结果的异常**：模块的 `config_status()` 不得以 `warn` 级报正常状态；正常状态归摘要与控件本身。
4. **无组散行容器默认收起**（取代 ADR-0017 决策 3）：卡头仍不挂徽章、仍不按内容推导状态（ADR-0017 决策 2 不变），级别仍由正文行文字色承载（决策 5 不变），条数计数胶囊保留，展开回看细节。
5. **失效选项说「无」**：下拉里存的值已不在候选集时，通用补显给「无（原选项已失效）」，不再回显裸目录名——候选标签由模块给出人类可读形态，宿主不解释其内容。

## 后果

**收益**：反馈通道与严重度一致，新增控件不必各自决定要不要报成功；「已保存」这类与字段无关的通用回执不再误导宏录制场景；状态行的警告色重新变成可信信号。

**代价与约束**（后续开发者因此不能做什么）：

- **新写入路径不得添加成功播报**（含 toast）。需要即时确认的，只能落在控件自身状态或卡片徽章上。
- **收起之后散行没有严重度摘要**：这是本条明确接受的代价。不得为此给容器卡挂按内容推导的徽章（ADR-0017 已否，本条不翻案）；需要即时可见的告警必须在生产者侧归组（ADR-0012 决策 1 的义务不因收起放松）。
- **不得把落盘失败包装成界面提示**：sidecar「写失败仅记警告」的语义不改，界面也不得假装知道写盘结果——所以成功话术反而是不诚实的，静默才是。
- **`warn` 级不是提醒色**：模块想提醒正常状态，走 `""` 级或摘要，不许染警告。

**被否方案**：

| 方案 | 否决理由 |
|---|---|
| 「已保存」改措辞（如「配置已保存」） | 仍占用反馈通道；切档位这类零风险操作不需要确认，且改措辞治不了它说谎的那两种情况 |
| 只在慢网络/批量改时显示回执 | 引入按时序决定反馈的规则，判据比静默更难解释，也没有可机检的边界 |
| 容器卡按最坏级别挂徽章 | 前端从内容推导状态，ADR-0017 已否；本条只改展开默认值，不翻这条案 |
| 日志读侧改成只放 ERROR 及以上 | 藏掉取证信息；级别裁剪属于读侧工具（导出、Studio），界面不做二次裁剪 |
