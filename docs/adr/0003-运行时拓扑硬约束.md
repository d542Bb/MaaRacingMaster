# ADR-0003：运行时拓扑硬约束——帧只从中心缓存来，动作只从队列走

- **状态**：`accepted`
- **日期**：2026-09-08（宪法定稿）/ 2026-09-13（帧供给独立于决策段）
- **决策者**：用户拍板，AI 落实施
- **相关**：[宪法 §1](../NAVKIT_V4_PLAN.md) 第 6 条 · MAAFW_GUIDE §9 第 15 条

## 背景

v4 把执行权交给 MaaFramework Tasker 后，运行时有**三条物理资源**必须独占：截图（WGC 采集）、输入（虚拟手柄）、以及帧的消费时序。

若不加约束，会自然长出多条通路：引擎为图省事自己截一帧、模块在决策路径里再起一个截图线程、动作绕过队列直接调手柄。这些在单线程原型里看不出问题，一旦引入并发就会出现**同一轮识别吃到不同帧**（半帧偏差）、**输入竞争**（两处同时动手柄）、以及**帧源不明**（出问题时不知道这帧哪来的，无法定位）。

另有真实事故佐证：帧供给曾挂在决策段上（`_tick_once`），导致大厅类 dwell 阶段整段零帧——表现为「调试截图开关开着但保存帧数 0/0」，因为决策段在那些阶段根本不跳。

## 决策

**帧只从中心缓存来（WGC 单生产者），动作只从队列走（submit / 结果槽协议），引擎只做调度。**

四条具体约束：

1. **WGC 采集线程**：常驻单生产者，写 immutable 帧快照。**引擎永不自截帧。**
2. **引擎线程**：读缓存调度（零阻塞），**同一轮所有候选识别共享同一帧**，禁止逐候选取帧。
3. **导航线程**：虚拟手柄独占，**引擎永不直连手柄**，主循环只经 submit/结果槽控制。
4. **帧新鲜度守卫**：帧时间戳超过阈值（默认 500ms）报「采集链路故障」，**绝不拿旧帧识别**。

停止 = `abort_event` 沿全链传播。

## 后果

**收益**：
- 同一轮识别的帧来源唯一，消除半帧偏差；
- 帧供给与决策段解耦——`treasure-observer` 线程独立产帧（`OBSERVE_INTERVAL_MS=150`），大厅类 dwell 阶段不再零帧；
- 问题可定位：帧源唯一，异常时能查是哪条链断的。

**代价与约束**：
- **真源里的 action 只能是 Custom（或无副作用内置类型）**。框架内置输入动作（`Click`/`Swipe`/`Key`…）在 v4 控制器里全是**成功占位**——会假成功而屏幕上什么都不发生。故节点必须走 `MaaRM_Click`（点识别框中心）或 `MaaRM_Input`（固定坐标/手柄按键）。此约束有机检（见证据）。
- 新增消费者时**必须复用中心缓存**，不得新起截图通路（`ctx.capture.screenshot` 是只读多消费者，收尾链的轮询也走它）；
- 观察线程权限边界：不调决策入口、不碰检测/OCR/状态机，HUD 状态由决策段整体替换引用发布到 `_last_debug_kwargs`，观察线程只读引用（两侧无锁的前提）；
- 停止序有先后要求（`_stop_observer()` → `_stop_io_worker()`，反了会漏收尾帧）。

**被否方案**：
- **决策路径内直接截图**（v3 形态的按需截帧）——破坏单生产者模型，且与缓存帧时序不一致；
- **引擎直连手柄**——两处竞争输入，且绕过结果槽后无法判断动作是否真生效；
- **观察任务挂在决策 tick 上**（`_tick_once` 内产帧）——大厅类 dwell 不挂 `policy_loop` 时该段整段零帧，实证事故见背景。

## 证据

- **宪法原文**：[docs/NAVKIT_V4_PLAN.md](../NAVKIT_V4_PLAN.md) §1 第 6 条 + §4.2「线程拓扑」。
- **机检**：[`tools/navkit/check_truth.py`](../../tools/navkit/check_truth.py) `action_checks`（校验器第 8 条）——真源出现框架内置输入 action 即报错。
- **协议依据**：MAAFW_GUIDE §9 第 15 条——`FramePool/PrintWindow` 的伪最小化会改写目标窗口样式，与自研窗口管理是同一批状态的写入方，不得混用。
- **实证（帧供给解耦）**：A7 真机验收——鉴宝 GUI 大厅静置，新会话 raw 从 0 增至 95 张/15 秒（约 158ms/帧，与 `OBSERVE_INTERVAL_MS=150` 吻合）；关键结论「厅类 dwell 不挂 `policy_loop` 时存图仍正常」正是本次拆分要解决的问题。
- **帧源复用实证**：彩蛋收尾链（`_run_egg_claim_chain`）轮询复用 `ctx.capture.screenshot` 的 WGC 中心缓存，不新起截图通路。
