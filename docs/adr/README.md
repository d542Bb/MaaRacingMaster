# 架构决策记录（ADR）

> **本目录是什么**：记录**已板上钉钉的架构级决策**——改了什么结构、为什么这么定、代价是什么。
> **本目录不是什么**：不是方案库（方案在 `docs/plan/`）、不是知识库（事实在 `docs/CODE_WIKI.md` / `docs/MAAFW_GUIDE.md`）、不是待办清单。

## 准入条件（硬门槛，不满足一律不收）

一条决策要进 ADR，必须**同时**满足：

1. **充分验证** —— 有下列证据之一，且可被复核：
   - 一手协议/源码核查（附出处与版本）
   - 机检背书（`check_truth` 校验项、CI 测试）
   - 真机/实验实证（附取证脚本或落盘数据位置）
2. **板上钉钉** —— 已落地实施，不是提案、不是"打算做"、不是待定。
3. **架构级** —— 影响跨模块结构、分层、协议或运行时拓扑；**实现细节与域内坑点不收**（归对应 `CODE_WIKI`）。
4. **有长期约束力** —— 后续开发者会因它而不能做某些事（即它是"约束"而非"历史"）。

**不够格的处理**：

| 内容 | 归宿 |
|---|---|
| 提案、备选对比、未拍板的方案 | `docs/plan/` |
| 纯行为守则 / 工作方式（如"先对齐需求再动手"） | `AGENTS.md` |
| 域内定案与坑点（鉴宝出价、OCR 等） | 对应 `<module>/CODE_WIKI.md` |
| 版本方向与不变量（最高级层） | `docs/NAVKIT_V4_PLAN.md` §1 宪法 |
| 一次性的技术选型过程 | `docs/plan/archive/` |

> ⚠️ **禁止复制真源**。ADR 正文只写"决策 + 理由 + 后果"，事实细节**引用不重述**（如"见 MAAFW_GUIDE §5.6"）。ADR 若与宪法/CODE_WIKI 冲突，以那两者为准并回头修 ADR——ADR 是决策的**索引与状态**，不是新的平行真源。

## 文件格式

- 命名：`NNNN-短横线小写标题.md`（四位序号，从 `0001` 起，**只增不改**）
- 结构：状态 / 背景 / 决策 / 后果（含被否方案与代价）/ 证据
- 模板：`template.md`

## 状态机

| 状态 | 含义 |
|---|---|
| `accepted` | 当前生效 |
| `superseded by ADR-NNNN` | 已被新决策取代（保留原文，不改写历史） |
| `deprecated` | 已失效且无替代 |

**推翻旧决策的唯一方式 = 新写一条 ADR 并标注 superseded**。禁止原地改写已 `accepted` 的正文——历史理由是决策记录的价值所在。

> 反例警示（2026-09-14 实证）：`docs/plan/doc-knowledge-baseline-plan.md` 里一条已失效的定论（`file:///` 链接是"IDE 可跳转约定"）因缺少状态标注，被后续 agent 当作有效前提转述，导致错误结论。**无状态标注的断言就是定时炸弹**——这正是本目录存在的理由。
