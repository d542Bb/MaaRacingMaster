# 架构决策记录（ADR）

> **本目录是什么**：记录**已经稳定、且对项目架构有持续影响的决策**——为什么在重要取舍中选了这一边、带来什么长期约束；每条带**状态**，是「这条决策是否仍生效」的唯一依据。
> **本目录不是什么**：不是方案库（方案在 `docs/plan/`）、不是知识库（事实在代码真源、模块 `CODE_WIKI.md`、`docs/MAAFW_GUIDE.md`）、不是待办清单、不是第二套 Git 历史——实现过程由提交记录承载，这里只收代码还原不出的取舍与它们的状态。
> **信源等级**：L1 —— 可作「**架构级决策**定了什么、为什么这么定、现在是否仍生效」的直接依据；不得作为实现细节与取值的最终依据（回 L0/L2 核对），也不承载各业务层的知识（各层知识在其 `CODE_WIKI.md` / 子系统 `README.md`）。
> **真源路由**：宪法条款 → [`PIPELINE_V4.md` §1](../PIPELINE_V4.md)；协议事实 → [`MAAFW_GUIDE.md`](../MAAFW_GUIDE.md)；实现现状 → 各模块 `CODE_WIKI.md`。
> **继承**：通用协作与信源规则见 [`AGENTS.md`](../../AGENTS.md)；本目录只补充 ADR 特有的准入条件与状态机。

## 准入条件（硬门槛，不满足一律不收）

ADR 记录的是**决策**，不是实现改动。一次跨层改动、接口变化或新增约束，单独看都不自动构成 ADR。记录前必须**同时**满足以下条件：

1. **充分验证** —— 有下列证据之一，且可被复核：
   - 一手协议/源码核查（附出处与版本）
   - 机检背书（`truth` 校验项、CI 测试）
   - 真机/实验实证（附取证脚本或落盘数据位置）
2. **决策已收敛** —— 重要取舍已确定并落地，不是提案、待验证方向或仍在连续调整的实现。一个决策在同一轮试用、反馈和修正中尚未收敛时，不要每轮都新建 ADR；用提交记录保留实现过程，必要时用 `docs/plan/` 工作台整理待验证事项，待结果稳定后再写一条最终 ADR。
3. **架构上重要** —— 影响跨模块结构、分层、协议或运行时拓扑，并对后续工作形成持续约束；**实现细节与域内坑点不收**（归对应 `CODE_WIKI` / 子系统 `README.md`）。
   **自检问句**：这个决定会让哪个***别的***模块 / 层的人做不了什么？**答不出就不进本目录**（粒度判据与迁出实例见 [ADR-0006](0006-meta-adr-决策粒度只收跨模块约束.md)）。
4. **有真实取舍** —— 曾有至少两种可行方向，且选择会带来有意义的长期后果；纯粹顺着现有模式补齐、没有值得解释的取舍，不必写 ADR。
5. **值得留给未来读者** —— 若没有这条记录，维护者很可能无法从现状推知为何选择此方向，且误选另一方向会造成有意义的返工或破坏约束。常规补齐、低成本调整且不留下持续约束的改动不收。

**最短准入判断**：有重要且真实的架构取舍，结论已经稳定，并留下了未来维护者需要遵守的长期边界。只满足「改动跨层」或「接口发生变化」不够。

**不够格的处理**：

| 内容 | 归宿 |
|---|---|
| 提案、备选对比、未拍板的方案 | `docs/plan/` |
| 纯行为守则 / 工作方式（如"先对齐需求再动手"） | `AGENTS.md` |
| 域内定案与坑点（鉴宝出价、OCR 等） | 对应 `plugins/<id>/CODE_WIKI.md` |
| core 层定案与坑点（导航、日志、采集、调试等） | `maaracing_master/core/CODE_WIKI.md` |
| 版本方向与不变量（最高级层） | `docs/PIPELINE_V4.md` §1 宪法 |
| 一次性的技术选型过程 | git 历史（PR/commit） |

> ⚠️ **禁止复制真源**。ADR 正文只写"决策 + 理由 + 后果"，事实细节**引用不重述**（如"见 MAAFW_GUIDE §5.6"）。ADR 与宪法冲突时以宪法为准并回头修 ADR；与事实真源（代码 / 资源 JSON / 模块 `CODE_WIKI.md`）不符时，说明该决策已失效、或落地与决策不一致——两种都要查清后修其中一侧，不得两存。ADR 是决策的**索引与状态**，不是新的平行真源。

## 文件格式

- 命名：`NNNN-性质-影响模块-主题.md`（四位序号从 `0001` 起，**只增不改**；序号之后的三段与提交信息 `type(scope): 主题` 同构，正文标题行同样带 `（性质-影响模块）`）
  - **性质闭集**：`arch`（结构与拓扑约束）/ `ownership`（能力与真源归哪一层）/ `contract`（跨层接口契约）/ `choice`（技术选型与形态）/ `criteria`（判定标准与门槛）/ `meta`（本目录治理规则）
  - **影响模块**：与提交 scope 同一套词汇（`core` / `shell` / `log` / `perf` / `speedrush` / `adr`）；约束跨全部层的用 `global`
- 结构：状态 / 背景 / 决策 / 后果（含被否方案与代价）/ 证据
- 模板：`template.md`

## 状态机

| 状态 | 含义 |
|---|---|
| `accepted` | 当前生效；适用范围有边界时括注写明 |
| `amended by ADR-NNNN` | 决策**部分**被后续 ADR 取代或收窄，**其余仍生效**——括注写明被取代的具体范围与仍生效的部分 |
| `superseded by ADR-NNNN` | **整条**决策已被新决策取代（保留原文，不改写历史） |
| `deprecated` | 决策已失效且无替代 |
| `archived` | **记录**不再是本目录的现行约束——典型为按粒度规则迁出本目录（决策仍生效，现行住户见括注）；正文保留为历史 |
| `merged into ADR-NNNN` | 与另一条记录实为同一决策，已合并到指定条目；保留本文件作为旧编号的跳转页 |

**关键词给扫读者的必须是正确第一印象**：标 `amended` 的条目仍具现行约束力，不得当作整体失效引用；标 `superseded` / `deprecated` / `archived` 的条目不再约束现役实现。精确边界靠括注，但不能指望每个读者（含 agent）都读括注——先让关键词站对，括注只做精读层的补充。判定「整条还是部分」时逐条对决策清单，不凭整体印象。

**改变已接受的决策**：新写一条 ADR，不把新的取舍写回旧正文；旧条目按范围标状态——整条被取代标 `superseded by`，部分被取代或收窄标 `amended by`。

**合并重复记录**：只有多条记录实际描述同一项决策、拆分后反而难以判断共同边界时才合并。保留最合适的现有编号作为主条目；其他文件不删除、不复用编号，改成指向主条目的简短跳转页，并标为 `merged into ADR-NNNN`。不同决策不能只为减少条目数而揉成一条。

**拆分混杂记录**：一条 ADR 实际混有多项独立决策时，可把其中一项拆为新编号的独立条目；原条目保留、括注划清两边范围。拆分与合并同判据：以边界更清晰为准，不以条目数为准。

**更正文案**：已接受条目的拼写、链接、可核实事实错误与表述歧义的澄清可以直接修正，但不得借此改变其决策含义、理由或适用范围——改完必须仍是同一条决策。接受后的实质性变更必须走新 ADR。

> 反例警示（2026-09-14 实证）：一份已清的 plan 归档里一条已失效的定论（`file:///` 链接是"IDE 可跳转约定"）因缺少状态标注，被后续 agent 当作有效前提转述，导致错误结论。**无状态标注的断言就是定时炸弹**——这正是本目录存在的理由。

## 与既有文档的关系

```
L1  docs/PIPELINE_V4.md §1 宪法     ← 最高级不变量（六条）
         ↑ 引用
L1  docs/adr/*.md                      ← 决策记录 + 状态（本目录）
         ↓ 引用
L2  模块 CODE_WIKI / MAAFW_GUIDE.md    ← 对象当前知识与协议口径（细节承载）
         ↑ 索引
L3  docs/CODE_WIKI.md                  ← 项目地图与导航（东西在哪、从哪进）
```

上图里的箭头是**引用**，不是**统辖**：ADR 只索引"决策与状态"，各层的知识仍在各自的住户里（模块 `CODE_WIKI.md` / 子系统 `README.md`）——**ADR 出现某模块的名字，只意味着那条决策约束到它**，不意味着该模块的知识在这里有第二份。

等级定义与路由规则唯一载于 [`AGENTS.md`](../../AGENTS.md)「知识路由」。
