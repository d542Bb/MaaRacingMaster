# ADR-0012：日志归属强制与内容定界

- **状态**：`accepted`
- **日期**：2026-10-29
- **决策者**：维护者（契约批准并要求「先立判据、再改行为」）· AI 落实施
- **相关**：[ADR-0007](0007-日志记录为唯一事实源双投影.md)（记录唯一事实源与双投影）· [ADR-0010](0010-记录流分类与玩法流水汇.md)（三分立户）· [ADR-0011](0011-性能数据单一采集与判级.md)（「卡片不是调试面板」的同型裁定）· [core/CODE_WIKI.md §1.5.2](../../maaracing_master/core/CODE_WIKI.md) · [tests/log_sites.py](../../tests/log_sites.py)

## 背景

GUI 日志面板有两条渲染路径：带组号的记录进卡片，不带组号的裸行直接铺在面板上。组边界由业务层声明（ADR-0007 决策 2），但「必须归组」此前只是插件的自觉：core 自己的日志没有归组规定，插件内的「有组走组」包装也各有各的写法。结果是一部分日志进卡片、另一部分是裸行，且裸行里混着逐帧读数与状态跃迁。

内容侧，ADR-0010 已把记录流三分（日志 / 玩法流水 / 性能），但「一行日志该承载什么」没有定界：逐拍细节既可走流水也可走日志，取决于写日志的人。ADR-0011 已对性能面板裁定「卡片不是调试面板，事件型、要毫秒精度的诊断走模块自己的流水」；本条把同一裁定落到日志面板。

## 决策

1. **归属强制（机检）**：`maaracing_master/**` 内 INFO 及以上级别的直接日志调用，必须显式传 `group_id`（或经「有组走组」的包装传入），否则必须命中站点登记表。登记单元是**日志站点**（文件 + 限定函数 + 消息模板 + 级别），逐条附理由与内容类别；`group_id=None` 显式传参一律红。扫描按目录发现，插件增删自动伸缩；别名（`lg = logger`、`log = logger.log`）与循环体内的直调一并追踪。
2. **白名单按站点而非按文字**：消息模板只是站点的匹配特征，不是身份。同一 `(级别, 消息模板)` 在登记表内必须唯一——运行时记录不带调用点，这是「级别 + 模板」能对应唯一站点的前提；同一模板出现在多个调用点必须拆模板或合并登记。
3. **内容定界**：日志只承载三类内容——**阶段起止**、**状态变化**（含终态与原因；降级/超时原因行是状态跃迁本身）、**在册跨切面事件**（用户操作回显、启动前提、worker 生命周期、落盘失败）。逐拍/逐帧读数、周期心跳归玩法流水；资源读数归性能流；图与帧证据归调试目录。机检不判语义，只强制登记完备（类别齐全、`pending_migration` 清零、循环体内站点不得登记为阶段边界）；「这行是不是状态变化」由登记理由与审查裁定。
4. **组只由业务层两处开**：controller 的运行生命周期组，以及插件的 `session` / `phase` 组。core 其余模块不得调 `logger.group()`；需要归组时由调用方把捕获的组号透传下来。动作桥与常驻 worker 使用**派发时刻捕获的组号快照**，不读线程局部「当前组」，也不在对象构造时永久保存跨运行组号。
5. **关闭时序有界且可见**：`sidecar.close()` 依次拒绝新任务 → 停止信号 → 有界 join 模块 worker → 关 logger。join 上限与伴随写手排空同阶；超时不阻塞退出，但 join 后必须复查 worker 是否仍存活并写一条 WARNING，未收尾组再由 `incomplete` 兜底——只靠 incomplete 分不清正常中断与关闭卡死。未知/已收尾组号的降级按调用点分项计数（跳过包装器帧），聚合计数形状不变。
6. **前端零改动**：裸行/卡片的渲染规则不变。前端是契约的忠实消费者；需要改前端才能承接，说明生产者改错了方向。

## 后果

**收益**：

- 面板只剩一种排版语义：卡片是有始有终的工作正文，裸行是登记在册的跨切面事件。
- 新增裸 INFO 日志在提交前即红；插件增删不需要改锁文件。
- 逐帧重复不再刷面板：WGC 帧回调异常、录制写帧失败改为首次 WARNING/ERROR、其后 DEBUG，文件仍全量。
- 运行收尾前模块 worker 有界排空，迟到日志的降级来源可按调用点定位。

**代价与约束**（后续开发者会因此做不了什么）：

- **不能随手写裸 `logger.log`**。要在面板上出现，必须归组或登记；登记要写清内容类别与理由。
- **不能复用宽前缀兜多个站点**。登记放行的是调用点，不是一类文字；同模板多处出现必须拆开。
- **core 不能自己开组**。需要卡片时由业务层开组并透传组号；core 侧新增阶段感知会被机检拦下。
- **逐帧细节不能回日志**。要进面板的只能是状态跃迁；读数与心跳走模块流水。
- **关闭不能无限等**。worker 排空有上限，超时后进程照常退出，未收尾组记 `incomplete`。

**被否方案**：

| 方案 | 否决理由 |
|---|---|
| 只靠插件自觉、不加机检 | 现状已证明会回潮；新增裸 INFO 永远绿，验收无法证明「零漏网」 |
| 按文件白名单 / 按消息前缀豁免 | 前缀会兜住多个不同站点，新增调用点借旧前缀逃逸；登记必须落到站点 |
| core 自己按阶段开组 | 违反 ADR-0007 决策 2：core 不枚举、不感知业务阶段 |
| 日志只留阶段、其余全迁流水 | 玩家报障的一手材料会消失；状态变化与跨切面事件必须留在日志 |
| 无上限 join worker | 把「关不掉的 worker」放大成「关不掉的进程」；监控自身成为故障源 |
