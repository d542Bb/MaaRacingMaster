# ADR-0020（contract-core）：内置步骤配置面只放用户可决项，游戏窗口定位收进单一顺序

- **状态**：`accepted`
- **日期**：2026-11-05
- **决策者**：用户（拍板「这几个开关都是设计性质，不该作为可选项」）· AI 落实施
- **相关**：[ADR-0013](0013-ownership-core-内置步骤与游戏进程归属.md) · [ADR-0018](0018-criteria-core-启动步骤的完成判据与自有资源.md)（部分取代，并更正其一条事实性错误）· [ADR-0016](0016-contract-core-模块配置面板由插件声明宿主渲染.md) · [core/CODE_WIKI.md §1.17](../../maaracing_master/core/CODE_WIKI.md)

## 背景

「启动游戏」步骤的面板上原有四个开关：已在运行则跳过、独立进程、启动失败时回退到启动器、进入游戏大厅。逐个查关掉以后的实际行为，三类问题同时暴露：

- **关掉只会更糟**：「已在运行则跳过」关掉意味着明知游戏开着还要再拉一个客户端；「回退到启动器」关掉只让本来就失败的启动失败得更早。两者的旁注都写着「推荐开启」——界面自己在告诉用户反方向是错的。
- **声称的行为不成立**：「独立进程」的描述说本程序被结束时游戏照常运行。壳侧关停后端走的是整棵进程树终止，而那两个进程创建标志只管控制台与进程组归属，不改父子关系——两种设置结局相同。
- **它挡的不是灾**：「进入游戏大厅」开着时的降级路径本来就成立——认得出就进大厅；认不出就是「游戏已打开 + 未进入大厅」这条可读错误，整轮中止，用户手动点进大厅后重跑即可。关掉它换来的是同一步骤直接报「完成」，把失败推给下一个模块，错误反而更难懂。**ADR-0018 代价节写的「界面改版时的逃生开关是关掉进入大厅」因此是事实性错误**，不是被新决策取代的旧选择。这个开关唯一真实的收益是少等一次超时，而超时本身有独立时限参数承担。

## 决策

1. **内置步骤的配置面只承载用户能决定的事**：程序路径、启动参数、两个时限。怎么起进程、起不来时怎么办、窗口怎么认，属于步骤自己的实现，不进面板，也不留隐藏开关。
2. **按标题找窗口只能作为最后一级回退，出现在控制器的唯一入口里**：顺序为 已接管的句柄（且仍有效）→ 按进程名 → 按窗口标题关键词；连接、音量、采集等调用点不得绕过它自行按标题找。顺序不可调换：标题是同名窗口场景里最不可靠的一级，但**不得删除**——按进程名只认默认发行渠道的主程序包名，非标准安装、别的渠道、以及画面由模拟器进程承载的环境都会在那里落空，标题是这些场景里唯一的线索。按进程名找仍由知道主程序名的调用点直接使用（启动与关闭步骤按配置路径的 exe 名匹配），这一级不属于要收口的重复。
3. **界面改版导致启动链过不去时的应急路径改为**：把「启动游戏」临时移出任务列表，手动把游戏点进大厅，后续模块照常从大厅起跑。错误提示按这条写，不再指向配置项。

## 后果

**收益**：

- 面板上不再有「推荐开启」式伪选择；步骤行为只剩一条主路径，配置面、测试面与文档面同步收窄。
- 手动开游戏时先按进程名认窗口，认不出才落到标题——不再因为「谁起的游戏」而得到两种准确度（非默认渠道仍由标题级承接）。
- 用户配置里遗留的四个键由配置回填的白名单自动丢弃，无需迁移代码。

**代价与约束**：

- 没有了「只开游戏不导航」这个选项。它原来被当成排障出口，实际只会把可读的超时错误换成下游的困惑失败，因此**不记为能力损失**；嫌等太久改大厅时限参数就够了，那本来就是独立参数。
- 固化「已在运行则跳过」后，接管一条没有窗口的残留进程会变成整轮失败，且用户再无开关可绕。因此跳过分支必须自己等到窗口或如实报错（决策 1 的隐含代价：实现要接住开关原来遮住的场景）。
- ADR-0018 的决策 3（资源需求按本次配置声明）随配置项一起失效；其代价节「逃生开关是关掉进入大厅」是**事实性错误**，由本 ADR 更正而非取代。该 ADR 其余决策（完成判据、启动链归属、执行态与资源所有权）仍生效。
- 以后要给内置步骤加配置项，先答「这是用户能决定的事吗」——答不出就不进面板。
- 若将来真需要「本程序被强杀后游戏仍存活」，得改用作业对象或独立进程托管，那两个标志不承载这个承诺。

**被否方案**：

- **把开关收进折叠的「高级 / 排障」区**：位置变了，伪选择还在；而其中一条声称的行为根本不成立，留着等于给用户一个假的控制感。
- **保留「进入游戏大厅」作为排障开关**：它声称要排的障（改版超时）在开着时本来就降级成可读错误并中止整轮，关掉只会把这份可读性丢掉。保留等于把一条写错的建议继续摆在界面上。
- **写一次性迁移清 profile 旧键**：回填路径已按声明的键做白名单过滤，再写一遍是第二份真相。
- **用作业对象兑现「独立进程」的承诺**：没有任何用户需要这个行为，为它加一层内核对象是凭空造需求。

## 证据

- **一手核查**：.NET `Process.Kill(Boolean)` 参考页——`entireProcessTree=true` 按后代进程树终止，仅跳过无权查看详情的进程；本仓 `apps/MaaRacingMaster.Shell/PythonSidecar.cs` 的关停与析构路径均走 `Kill(entireProcessTree: true)`；`maaracing_master/core/game_process.py` 的两个标志为 `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`，属控制台与进程组范畴。
- **既有事实**：启动器窗口标题与游戏窗口同名（[ADR-0013](0013-ownership-core-内置步骤与游戏进程归属.md) 证据节，游戏文案表 `T_STANDARD_GAME_TITLE`）。
- **降级路径的代码事实**：步骤失败即中止整轮（`maaracing_master/core/sidecar.py` 运行队列的收尾分支），而启动进程与交付窗口发生在导航之前——所以「进入大厅」认不出时游戏已经开着、错误可读、下游不再盲跑。这是背景第三条的依据。
- **机检**：`tests/test_controller_step_link.py`（三级顺序、进程名命中即停、接管句柄优先）；`tests/test_builtin_launch_hall.py`（已在运行不拉第二个进程、进程在而窗口未到时等到窗口或如实失败、等窗口超时回退官方启动器、资源需求按点击方式与运行模式）。
- **独立复核**：干净上下文的对抗复核跑了一次本地进程树终止模拟（带 `0x208` 标志与不带标志的孙进程均被终止），佐证决策节第 2 类问题；该模拟未落盘为仓库脚本，可复核部分是上面的 .NET 参考页与本仓壳侧代码。复核同时打穿了「固化跳过分支无损失」这一说法——进程在但窗口未到时旧实现直接放行，已由上述用例锁住。
- **全仓回归**：本机 `.venv` 全量 `pytest` 绿（2026-11-05），用例数以 `tests/test_builtin_launch_hall.py`、`tests/test_controller_step_link.py` 为准，不在本文记数。
