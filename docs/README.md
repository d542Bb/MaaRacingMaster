> **继承**：通用协作与信源规则见 [`AGENTS.md`](../AGENTS.md)；本文只补充文档写作特有的约束。

## 文档写作规范

### 文档头

正式知识文档（L1 / L2）在文件开头声明自己：

```markdown
> **本文是什么**：承载哪类知识、以什么问题为对象。
> **本文不是什么**：哪些内容不在这里建立第二份真相（指向其 home）。
> **信源等级**：Lx —— 可作哪类问题的直接依据；不得作哪类问题的最终依据。
> **真源路由**：本文依赖的事实，其真源在哪。
> **继承**：通用协作与信源规则见项目根的 `AGENTS.md`（**按本文所在层级修正相对路径**）；本文只补充本对象特有约束。
```

L3 / L4 导航型文档可省去「真源路由」一行。**只声明与指向，不复制** AGENTS 的通用规则——同一规则抄在许多份文件里，就是许多份会各自腐坏的真源。

### 不得抄录可机检的真源数值

凡能被 JSON / 代码单向算出的值（阶段数、计数、清单长度），prose 只写**指向真源的路径**，不写数值本身；枚举清单同样换成指向，写指针时也不带数量。手抄数字没有守卫就必然腐坏。
机检形态：[`tests/test_doc_no_copied_numbers.py`](../tests/test_doc_no_copied_numbers.py)。

### Why 归属

**对象决定文件，不是 Why 决定文件**：项目级架构为什么这样定 → [adr/](./adr/README.md)；模块为什么这样实现 → 该模块 `CODE_WIKI.md`；子系统为什么这样施工 → 其 `README.md`；局部代码为什么不能改成另一种写法 → 代码注释 / 结构。

### 指针纪律

跨文档只给指针，不复制真源。改路径时**链接文本与 URL 两侧都要核**；章节号会漂，指针写「去哪个文件的哪一类内容」比写死节号更耐用。

### update_log 收录判据

[`update_log.md`](./update_log.md) 是**面向玩家的更新说明**（Release 正文信源），不是开发日志；唯一读者是玩家。

**写每一条前自问：玩家装上新版后能看到、感到什么不同？** 答得出就写，答不出就不写。

- **写**：新功能、界面与交互变化、行为变化、操作更跟手、启动更快、包更小、报错更清楚、新增可选开关。
- **不写**：内部重构与模块拆分、测试与 CI、文档与规则、实验与探针、内部协议与接口、代码整洁、性能测量值本身（玩家能感到时改用感受描述）。
- **不出现**：文件路径、类名 / 函数名、测试计数、commit 哈希、实验代号、统计量（AUC / p 值 / 中位帧间隔）。
- **组织**：按「新增 / 改进 / 修复 / 移除」分组，每条一句话，用玩家的语言；没有的组不写。
- **未发布改动不进本文**（它还不是「更新」）：发版时从 `git log <上个 tag>..HEAD` 提炼——过程细节已在 commit message。
- **纯内部版本**保留小节标题并写「本次为内部调整，玩家无可见变化」，版本序列不断档。

## plan 规范（`docs/plan/`）

`docs/plan/` 是**工作台，不是知识库**：AI 生成的实施计划、方案对比、验证报告落这里，gitignore 不入库。

- **只能向上产出**：plan → ADR / CODE_WIKI / 指南 / 实验 / issue / 生产实现。长期价值只存在于
  被提炼的产出里；plan 本身不是任何知识的住户。
- **禁止反向引用**：正式文档（L0~L3）与生产/运维代码不得引用 `docs/plan/` 下的具体文件
  （机检 [`tools/check_repo_hygiene.py`](../tools/check_repo_hygiene.py) R3）；实验引用 plan
  只作过程指针、不作事实依据。
- **退役即删除**：产出提炼完成后删除工作台文件（走回收站——它没有 git 历史，删除不可经
  git 回撤）。**不设 `plan/archive/`**：gitignored 的"归档"既不可追溯又暗示"仍属项目知识"，
  是第二个垃圾场；plan 的历史若重要，应把结果留在它产出的 issue / commit / 最终文档里。
- 较大改动的 plan 以行为契约开头：依次写「目标行为 / 不变量 / 验收条件」，先定行为再谈技术方案；跨层、新模块、并发与资源类改动必写。
