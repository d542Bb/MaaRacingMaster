status: active

> 超时 / 车因撤销 / 空间作废”四类拆换道结局，并统计权限覆盖、计划/PD
> 一致性、线融合误差。用于给行为契约的验收提供可复算分母。

> **完成判据判定稿**：「并线是否完成」的只读判定口径（证据类 / 三值结论 /

## 口径

- 换道段 = `route.phase` 连续为 `merging` 的拍；结束拍取离开 merging 的那一拍。
- 成功只认 `verdict=finish` 且 `why=arrived`；`merge_timeout` 是独立 `timeout`
  结局，不算成功。
- **实动到达** = 到达段内 `executed_lane` 位移 ≥0.3 道。低于此的“到达”是参考道与
  实测道不同步时的空动作（车本来就在目标道带内），不是换道，单列不混入。
- `cancel/rebuild` 目标道的 blocker 优先读 `route.blk`（阶段 0 新列）；旧 trace
  回退到 `coarse.cand`。
- 时长分到达段与全部段两套，不混用；到达时长只统计实动到达。
- 计划/PD 一致性只在计划有效且机动的拍上算；PD 按 `x_target/executed/v_lat_est`
  复算（0.7/0.2，前瞻 0.25 s，上限 0.85）。

## 阶段 1 A/B（普通车不撤销）

- 只改 `decision.json [route].soft_car`（false→true），其余键、模型与路线不变；
  `route.control` 保持 true。
- 两组各 4 局（初赛/决赛沿用 p1/p2 后缀）；基线的 4 局已在
  `probe_merge_baseline.py` 的 `RUNS` 里列明，阶段 1 的新局同法加进去或走
  `--runs`/`--session`。
- 读法：`cancel` 应为 0（目标道普通车不再撤销）；到达率要同时看**实动到达**，
  空动作增长不代表换道成功；同时看新出现的 `timeout` 与擦撞时间损失。
  `space` 作废不属本阶段验收。
- 2026-10-25 结果（基线 4 局 vs soft_car=true 4 局）：原始到达 16/36 → 25/41，
  但实动到达 10/36（27.8%）→ 11/41（26.8%）；多出的 8 次到达全部落在空动作
  口径（车已在目标道带内，含原会被“车因撤销”取消的那类）。`space` 作废
  12/36 → 13/41。结论：车因撤销不是真实换道的约束，开关默认保持关闭。
- **做计划 vs PD 的执行器 A/B 前先有承诺期修正**（2026-10-25 已落库）：并线期
  选择/计划都只认路线承诺道（机会层关闭、决策 slew 绕过）。旧 4 局 897 个并线
  拍里，248 拍目标与承诺道差 >0.5 道——其中 155 拍是 slew 滞后、93 拍是目标
  来源偏离；不先修，A/B 会同时改变目标与执行器。

## 噪声估计（probe_lateral_noise.py）

- 方法：每局按时间切 5s 连续块，会话内**按局分层**对块有放回重采样
  （B=1500），得到会话均值的 95% 区间；两组独立抽样的差值区间跨 0 即
  该差值落在车流/驾驶相位噪声内。块自举保留同一会话的 4 局构成，跨组
  比较的是"同赛道集、不同车流"。
- 4 局一组时的可检出下限（差值 95% 区间半宽）：墙边 ±7~8 点、压墙 ±4~5、
  带内 ±10、离缘<1.0m ±1.5~2、离缘<1.5m ±4~5、状态滞后 ±4。小于这些
  量级的组间差不要归因于改动。
- 2026-10-26 四组实测（shadow 参考帧 / live 参考帧 / 盲区修正 / 贴边回带）：
  墙边、压墙、带内、离缘的组间差**全部跨 0**。只有两项显著：live 参考帧组
  比 shadow 组状态滞后多 5.7 点（+1.1~+10.0）；盲区修正把它压回 5.5 点
  （−10.0~−0.7）。即盲区修正的真实效果在"状态滞后"，不在墙指标上。
- 贴边回带组与上一组无任何显著差，且该规则实跑激活 0 次（贴边拍全是
  机动授权或计划接管）——那一组墙指标的改善属噪声。
- 判读：5 点级的墙改进需要 8~12 局一组，或改用机制计数（规则激活次数、
  单次贴边事件时长）作为主判据。

## 贴边停住的结构性原因（2026-10-26 晚，probe_segment）

- 贴缘（<1m）+ keep 拍（15:51 局 52 拍）：60% 的 `|target−exec| ≤ 0.5`
  （保持死区），83% 是车停在目标的外侧（贴墙侧）。其中不少拍的计划是
  `plan:infeasible_corridor`（自车已压在走廊边距内）——计划无效被丢弃，
  退回 PD 后又落进保持死区，杆值不再修正。实拍：s2#4 21.6s 目标 0.93、
  车位 1.19、杆 −0.18、离右栏 0.25m。
- 修正：走廊不可行时执行计划里的"最快脱离侵入"候选杆值（空可行集第一
  项），不走保持死区/维护杆幅。激活：各组 63~105 拍/组，其中离缘<1m
  37~63 拍；候选杆幅中位 0.85、91~98% 朝路内。
- 验收：本刀有确定激活，下一组看"走廊不可行拍后的离缘<1m 停留时长"与
  逐局离缘占比；仍按噪声口径（4 局只看方向，8 局以上才看均值）。

## 横向运动学 v3 重辨识与三刀修正（2026-10-26 晚，人工局对照）

**动机**：s1#3 8.1~8.5s"过完币突然打方向"逐帧取证（probe_segment + 调试图
像素级黄线提取）——计划 L3 追选择层拒掉的 −2.2 道肩币满杆左打 0.5s，横速
冲到 −1.5 道/s；计划翻回中心后限速+车模乐观让车又滑 0.9 道，压左黄线骑
路肩 ~0.5s（80m/s 下 ~40m）。位置估计同期滞后 0.5~1 道（线重锁被停用、
深度在 memory 保持），贴边逃生门全程没触发。

**车模重辨识**：录制模式 pads.jsonl 原始摇杆（/32767，与 trace 同钟）对齐
人工局 20261026_201546_1 四局——a 中位≈5（产线 6 保留），**横速自衰减撞
上界 ≥12s：松杆不衰减，停住靠反打**。程序局拟合的 2.0s 被证实是污染产物
（19 段 17 段贴墙；程序闭环下衰减时间不可辨识）。维护者"撞墙段混进变道
统计"的怀疑方向正确，且实际偏差更大。

**人工驾驶手法画像**（35 个变道事件）：满杆进（0.98）、中途满杆反打
（0.98，换向时横速还有 0.94 道/s）、反打 0.55s 后回中；速度过零 0.68s →
**反打有效减速 p50 1.3 道/s²**（进入段 ~5.5——刹车比加速弱一个量级，因为
反打要先转过车头）；过终点冲出 p50 ~0.5 道。人工局贴线率 1.2~6.3%
（程序局 17~24%）。

**三刀**（已落库，待实机 A/B）：
1. `tau_align_s` 0.5→12.0（松杆不衰减；模型状态与计划仿真同步生效）；
2. 刹停预算 `brake_decel_lane_s2=0.8`：PD 路径横速预测停止点越过目标带
   远侧缘 → 升级全权反打（人工 bang-bang 手法），v→0 自退出；
3. 计划层币门与选择层同源（`coin_pick_tol_lane`）：够不着的肩币不作计划

  响应更大）；程序当时的速度无法得知，两边辨识出的车模参数因此不可比。
- **速度确实不可知**：`lat_ctrl.speed`（线斜率/线角比值在线自标定）在程序
  trace 里 53~77% 的拍等于默认 45 m/s（横移期 46~76%），横移期 p10~p90
  =30~74 m/s、个别拍到 188 m/s——不是可信的回归量。自标定只在"有横速+
  有航向偏角"时出样本，直行时不更新。
- **人工可能真的更快**：游戏"得分速度"（分数增速，人工/程序都录）人工 p2
  中位 130~162、p90 251~311；程序 p2 中位 39~41、p90 128~182——约 3~4 倍。
  但该指标混入倍率（金币/近距等），只能当"人工更快"的弱证据，不能当速度。
- **速度依赖无法检验**：取"速度估计非默认且 |Δ真值|>0.25 道"的激励段
  （三局 n=84），按单位增益核反解每段等效增益——p25~p75 跨 −9~+9 道/s²，
  与速度估计相关系数 r=−0.08，噪声完全压倒信号。
- **撤回一条线索**：上节"正向 4/反打 6 好 21%"不成立——位移拟合对增益有
  结构性偏置（8 局逐局拟合，最佳档全是测试下限 2），不能用来辨识车模。
- 结论：横向车模在"前向速度未知"时物理上不可辨识（a_lat 应随 v 变）；在
  拿到直行期的速度信号之前，车模保持现状、不再做参数辨识。
- 下一步候选（需择一）：①直行速度估计（车道虚线周期/路面光流）——也是
  该假设的检验前提；②不依赖速度的项（路心稳定化、决策目标逐拍翻转）。

## 感知加权估计器实验：标准卡尔曼未胜出现行 α-β（2026-10-27）

- 出发点（用户提出）：不追求绝对前向速度；把模型加速度当**不确定输入**，
  感知按不确定度加权修正——"预测下一步 + 相对修正"的协同。这正是现行
  ⑥b（α-β + 线互证 + 跳变重基）已经在做的事，问题是能否做得更好。
- 实验（`probe_kf_state.py`，工作台）：同一杆值流 + 同一份新鲜路心观测，
  三臂对比——A=实录产线状态；B=1-D 卡尔曼（过程噪声 ∝ |杆值|，线性化
  协方差传播，换档拍不喂观测、连续 2 次确认重基）；C=B + 把相邻干净观测
  差当作速度测量（噪声 2σz²/gap²）。
- 结果（8 局中位，p90）：位置 A 0.44 / B 0.62 / C 0.67；横速 2.81 / 2.93 /
  3.03；**下一步预测 0.25s 0.72 / 0.81 / 0.83**；0.5s 三方持平。A 全面
  不劣。参数（sg/sz/qd）在合理范围内扫过，未出现反转。
- 判读：现行 α-β 的重基/互证机制相当于重尾鲁棒滤波，卡尔曼的高斯假设
  反而更吃观测噪声；**在同一份深度观测上换融合律不会带来新信息**。瓶颈
  是观测速率与质量（深度 2~5Hz），不是加权方式。
- 未试的唯一"新信息"：车道线通道是 ~20Hz 的位置观测，目前只用于否决/
  偏置对账，没有作为状态测量的高频证据源。下一步若继续估计器方向，应做
  "线+深度"双源卡尔曼（线按锁线/龄/跳变门控，偏置走既有对账），而不是
  再调深度单源的权重。

## 目标翻转不重要；41 m/s 上限是真的但不是精度瓶颈（2026-10-27）

- **目标逐拍翻转**（上一节列的候选②）已量化，**否掉**：最近一局 3165 拍里
  目标相对自车的误差方向翻转只有 35 拍（1.1%）；302 次杆值反向中只有
  18 次（6%）在之前 2 拍内有翻转，随机基线 3%——不是"莫名其妙打方向"的主源。
  我此前把 0.6s 内 ±0.3 道的极端窗当成了普遍现象，撤回优先级。
- **41 m/s 上限**（维护者确认；`RULES.md` §4.8 已记"巡航纯里程底值恒为
  41 分/秒，1 分 = 1 米"）：最近两局 trace 全拍里，`lat_ctrl.speed` 恰为默认
  45 的占 61~77%；>41（物理不可能）的占 86~94%；>60 的占 11~13%，最大
  173/188 m/s——航向横速的尺度项里有大量不可能值。
- **但把尺度夹到 41 不改善精度**：以线横位 0.25s 位移为尺（噪声约
  0.1 道/s），同一份 trace 上模型/航向/融合三臂的横速误差 p50
  =0.67/0.63/0.58 道/s；把航向尺度乘 min(1, 41/speed) 后融合臂 0.58→0.59
  （激励段 0.76→0.80）——略差，在噪声内。故 45/41 是卫生问题，不是精度所在。
- 结论：速度数值得夹（物理上限），但它不是当前误差的主项；横速状态本身
  误差 0.6 道/s（大于信号 p50 0.3~0.45），这才是控制抖动的来源。

## 标线掩码逐帧位移：精度已在线拟合里，光流不加分（2026-10-27）

- 用户方案：用标线分割掩码做光流 + 透视修正，拿相对横向位移。实现为
  `probe_lane_flow.py`：逐行取左右最近标线段的横坐标变化，对行号线性
  回归——斜率 = 横向位移/cam_h，截距 = 航向；只用垂直向位移，虚线相位
  只决定该行有没有线、不决定它的横坐标，故不受前向速度与虚线混叠影响。
- 结果（两局 500 帧，生产分割权重）：有效帧对只有 22~28%（rms>3px 或
  |航向项|>30px 或左右不一致 >0.25 道）。有效对里：左右两条线独立估的
  同一横向位移差 p50=0.014~0.019 道；与单帧线拟合的差分 corr=0.99、
  MAE=0.014~0.015 道；二阶差分高频噪声 flow 0.41~0.60、单帧拟合
  0.37~0.65 道/s——**两者同精度**。
- 判读：掩码的精度已经被现有单帧线拟合吃到了（拟合本身就是多像素加权），
  逐帧光流没有带来新信息；低有效率来自弯道/换路段/腾空时地面平面不成立，
  加 (x−VPX) 缩放项虽把 rms 从 16.6 压到 1.1px，但三量共线、缩放项会飙到
  ±100%/0.1s（物理不可能），不能采用。
- **真正的缺口不是测量**：线横位的帧间位移噪声约 0.02~0.05 道/0.1s，
  比深度路心（0.15 道/次）细 3~10 倍；而控制器横速与它差 0.6 道/s。
  旧"线速"拆除是因为用 0.6s 因果斜率窗——在 bang-bang 反打处结构性滞后/
  反号，不是线测量本身不可用。
- 下一步：短窗（0.15~0.25s）线位移速度作为观测，按锁线/重锁/位移上限
  门控后进 ⑥b 或控制横速，离线回放看能否把 0.6 道/s 压下来；有增益再上
  实机。掩码光流留作"需要更高帧率"时的升级路径，不作为第一手。

## 短窗线位移横速：不可用；上节的"精度"是共模假象（2026-10-27）

### 复核修正：出跨度机会不得占目标位（2026-10-27，干净上下文对抗复核）

- 复核打出的真 bug（已复现后修）：`select()` 按字典序短路，而带请求的
  `_pick_reward` 返回**非 None**，于是擦边/让位层整拍不被调用。复现输入：
  邻道奖励车 +1.0 道、同时一辆正压自车 0.0 道 → 修复前 `layer=4 target=+0.17`
  （只让开 0.17 道，车半宽 0.27＝撞）；去掉奖励车同输入 → `layer=2 target=+0.65`。
  这正是被点名的红线「抵消微调导致撞车」，且最长持续整个起意计分窗（6 拍）。

  出跨度只留请求、不占目标位；让位拍不发请求，路线侧计分漏一拍（泄漏式 −1，
  不清零，下一拍机会还在就继续累计）。回归锁
  `test_pending_request_does_not_preempt_yielding`（奖励车/币组两种机会各一例）
  + `test_request_resumes_after_yielding`。
- 复核质疑「起意后不可打断」，用两局实机定案分布回答（本次改动前）：

## 2026-10-27 追加：机会换道 0 触发的真实拦点=**请求道号契约不一致**（只读追踪，未改码）

后果（可枚举）：承诺道 = 0 时相对与绝对重合，机制正常；承诺道 = ±1 时，
`req=+1` 查绝对道 +1 == `lane_ref` → 命中 `_try_request` 首条
`s.req_lane == s.lane_ref` **静默拒绝**（返回 `(None, None)`，不落原因码）；
`req=−1` 查绝对 −1 → `|−1 − 1| = 2 > 1.5` 同样静默拒绝。**即：机会换道只在承诺道
为 0 时才可能起意**——实跑里车长期贴右（ego +1.6、ref +1），故 0 次。

**为什么 12 条回归锁全绿**：`tests/test_speedrush_route.py` 全部机会换道用例都在
默认初始态（`lane_ref = 0`）上喂 `request=±1`，两种口径在 0 道重合，锁不住契约。

**证据边界**：① 只有一局带新代码、5 拍 `crc≥6`，属**定性定位候选拦点**，不外推；
② 但"两份 docstring 互斥 + 无换算 + 测试全在 0 道"是代码级事实，不依赖样本量；
③ 修好契约后这一批请求仍未必起意——该窗口请求指向的绝对 +2 道在粗层是
`space`（不合格），下一个拦点是它。**不要把"修契约"当成"机会换道就会工作"。**

**处置**（按审查给的表，落在第 1+2 行）：单一条件长期阻塞 + 请求道号与路线层解释
不一致 → 先定契约（选择层出绝对道号，或路线层 `lane_ref + request` 换算），
并补一条"承诺道非 0 时请求仍指向相邻道"的回归锁；本轮未改任何代码。

## 2026-10-28 追加：换纪门长帧误触发的离线反事实（`reanchor-dt-check/1`）
