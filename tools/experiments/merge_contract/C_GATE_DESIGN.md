# C 到达位置门：实现方案审查（未实施）

> 本文件只定接口、状态、观测与验证方案，不改生产控制。结论来自代码与
> 四场 trace 的核对；与审查意见不一致的地方在 §1.3/§1.4 单独标注。

## 0. 结论

- C 可以进入实现方案评审；本轮不写实现、不改默认行为。
- **C 不修复完成判定的整体可靠性**：它只排除「用换档读数确定到达位置」这
  一类位置证据；速度项仍由保持值商承担的问题原样存在（64 个完成里仍只有
  3 个是「位置新鲜 + 前拍保持」，0 个是两端都新鲜）。
- 推荐接口：路心读数序列上算一个显式的「到达位置归因」，经引擎边界传入
  路线；路线只消费枚举，不复制分类器、不比较不同帧的数值。

## 1. 已核对的事实

### 1.1 时序

`module` 主循环的顺序是：走廊更新与 `road_offset` → **`engine.update`（路线在
这拍推进）** → `road_offset_hold/new` 与 `ro_hop`。也就是说，路线层今天看不到
新鲜度与换档标注；标注块在引擎推进之后才产生。这是审查意见里最关键的一条，
代码核对成立。

### 1.2 标注语义

`classify_ro_hop` 只比较**相邻两次新鲜读数**：间隔超过 1 s 记 2（黑视）；
否则 |Δ| > 3.2 道/秒 × 间隔 + 0.25 道记 1（换档），其余 0（运动）。
它标的是**这次读数差**的性质，不是「新读数不可用」；保持拍不更新谱系
（`ro_hop=None`）。长帧用的是新鲜读数间隔，不是单拍 dt——长帧不会因为 dt 大
就被当成换档，间隔超过 1 s 则直接进黑视类。

### 1.3 帧差（与审查假设不一致的地方）

路线位置项用的是**粗层 ego（场景帧）**，原始 `road_offset` 与它相差一个
`c0`（本次数据 p99≈0.185 道）。四例完成拍上：

| 段 | 完成拍粗层 ego | 该拍 road_offset | 差 |
|---|---|---|---|
| `083410` 1445 | 1.297 | 1.3654 | **0.068** |
| `171845` 3557 | −1.015 | −1.0151 | 0.0001 |
| `175557` 3253 | 0.965 | 0.9649 | 0.0001 |
| `183009` 8034 | −1.175 | −1.1755 | 0.0005 |

如果把原始 `road_offset` 当谱系值、拿路线 ego 去比，`083410` 会因 0.068 的
帧差漏判。结论：**归因必须在路心读数序列内部完成**（同为 road_offset 帧），
或者用粗层 ego 序列单独维护；不能跨帧比数值。前者更简单，见 §2 方案 A。

### 1.4 归因在 road_offset 序列上可行

四个完成拍的 `road_offset` 与上一次新鲜读数**完全相等**（1.3654 / −1.0151 /
0.9649 / −1.1755），且那次新鲜读数的 `hop=1`。反例 `083410` 的 1441 拍：
保持值 1.0086，上一次新鲜读数 0.5917，不相等 → 不归因（放行）。所以
「保持值 == 上一次新鲜读数」（带极小容差）是一个可落地的归因判据，且不会被
帧差破坏。

### 1.5 下游窗口样本

C 让承诺期多停 4~12 拍；这期间下游会关闭机会层。看生产（A，已完成、处在
keep）在这四个窗口里实际做了什么：

- 选择层四段全部是 L4 居中（`center:coarse`，末拍 `center`），没有机会层目标；
- 运动计划在这些窗口里始终没有产出（`plan=None`）：多数拍 `veto=plan:frame_shift`，
  少数拍 `veto=None` 但同样没有计划；
- 请求列只有 `083410` 在 1450（换纪拍）出现一次 `req=-1`，其余全空。

这是**样本**，说明这四例的暴露面小，不构成对其他场景的保证。

## 2. 规则定义

每拍给路线一个「到达位置归因」枚举 `attribution_hop`：

- `0 / 2`：本拍位置项来自新鲜读数（或其 hop=0/2 的保持值）→ 不拦；
- `1`：本拍位置项是 hop=1 新鲜读数的保持值（或本拍就是 hop=1 新鲜读数）→ 拦；
- `None`：无法归因（首帧、缺读数、保持值已变、还没有新鲜读数）→ **不静默
  当 0**：默认放行并在 trace 里记为 `unknown`，供统计；是否改为拦截留作评审项。

只作用于 `finish`：撤销优先、超时、换纪、重建全不动。拦住的拍路线继续
merging（`why=merging`），不新增语义分支。

## 3. 接口契约

### 方案 A（推荐）：引擎边界传「位置证据」

`module` 在 `engine.update` **之前**算好：

```
PositionEvidence:
    attribution_hop: int | None   # 本拍位置项可归因到的 hop
    fresh: bool                   # 本拍是否新鲜读数
    last_fresh_ro: float | None   # 上一次新鲜读数的 road_offset
    last_fresh_fid: int | None
    d_ro: float | None            # 本拍 road_offset 与该读数的差
```

`engine.update` → `decision` → `route.tick_route` 逐层透传；路线只在 finish
条件上加 `attribution_hop == 1` 的否决，**不持有谱系状态、不做帧换算**。

可行性：标注块依赖的 `dgeo_new`、`corridor`、`road_offset`、`ts_ns`、
`ro_hop_prev`、`corridor.source` 在 `engine.update` 前都已就绪；把该块前移
（或先算一份证据再保留原块）不改变引擎输入，只改变同拍内计算顺序。需要一个
「前移不改变其他列」的回归测试。

### 方案 B：只传 fresh/hop，由 decision 维护谱系

decision 在粗层 ego 序列上维护 `last_fresh_ego/hop` 并算归因。可行，但多一份
状态，且必须用粗层 ego（不能拿 road_offset 直接比，见 §1.3）；不如 A 单一。

### 缺失、黑视、长帧、首帧

| 情况 | 归因 | 行为 |
|---|---|---|
| 首帧 / 还没有新鲜读数 | `None` | 放行 + trace `unknown` |
| 缺 road_offset / 无走廊 | `None` | 路线本就 `needs_init`，不会完成 |
| 保持值已变（换源） | `None` | 放行（位置项不是那本读数） |
| hop=2 黑视（新鲜间隔 >1 s） | `2` | 放行 |
| 长帧但新鲜间隔正常 | 按分类器结果 | 不额外加 dt 规则 |
| 本拍就是 hop=1 新鲜读数 | `1` | 拦（本拍完成需要商 ≤0.4，数据里不会发生，但规则完整） |

容差 `d_ro`：保持值相等用 1e-3 道（0.3 cm）作初值，实现时用生产浮点验证；
超过容差记为不可归因，不做近似匹配。

## 4. 开关、状态与观测

- 开关：`route.reject_shift_arrival`，默认 `false`（`decision.json` + config）。
- 关闭：路线逐拍与今天一致；新增的只应是 trace 列。验收 = 9514 拍 A 版回放
  0 处不符。
- 开启：只加 finish 否决；60/64 完成不变、4 段按已记录变化。
- 回滚：关开关即可；不依赖完成判定器、换纪门、B/D。
- 观测：route trace 增 `attribution_hop`、`last_fresh_fid`、`d_ro`，以及被拦
  完成计数（`blocked_finish`）；`why` 不新增控制语义。
- 状态迁移：路线无新持久状态；decision/module 的谱系只随读数更新，不随承诺
  道变化。非巡航拍不推进路线，谱系照常随读数更新；跨非巡航间隔后的第一次
  完成若归因到间隔前的 hop=1，按规则拦截一次，下一次新鲜读数自然清除——记
  为边界行为，需要一条测试。

## 5. 下游暴露面与验证计划

路线层重放不足以放行生产：C 多停的 4~12 拍里，下游选择/计划的机会不同。
必做的下一步是**影子模式**（A 控制，C 只算不接管）：

1. 逐拍记录 would-be 的 `ph/vd/why`、`attribution_hop`；
2. 记录同拍 `sel_layer/sel_why/sel_dbg.req/plan_gate/veto/goal/maneuver`；
3. 覆盖现有四场 + 新场；验收：4 段复现、60 段不变、承诺期窗口里没有
   「A 实际使用而 C 会抑制」的机会/计划动作；
4. 影子通过后再评估 live A/B（开关 on/off），默认仍关。

## 6. 已证明 / 未证明 / 开放问题

- 已证明：C 在路线层只影响 finish 的位置项；4 段的分歧都从被拦的完成拍开始；
  60/64 不变；后续换纪/重建在 A 版同拍也发生；A/C 的接控制道号相同。
- 未证明：承诺期延长对下游选择/计划的实际差异；生产浮点下「保持值 == 上次
  新鲜读数」的容差取值；更多场次里 `unknown` 归因的比例。
- 开放：`unknown` 是放行还是拦截；`d_ro` 容差；是否先上 trace-only 相位
  （只记归因、不接开关）再做影子。
