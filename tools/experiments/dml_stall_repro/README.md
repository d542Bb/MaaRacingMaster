# dml_stall_repro — 开车中 1 秒级推理停顿的离线复现台

## 背景（2026-11-07 流水诊断）

最近多场 speedrush 对局出现 1 秒级整体停顿（11:05:56 / 12:08:40 / 14:55:30 各一次，
0.9~1.3s）：停顿拍感知单次推理从 ~8ms 冲到 0.8~1.1s（持 DML 锁期间），深度观察同拍
缺位（锁被占、Busy 跳帧），调试图落盘 143~303ms（正常 ~15ms），采集链 1.24s 零新帧。
游戏侧计时与场景照常推进。常态 20Hz 拍 p95 72~78ms（预算 50ms）。

用户补充事实：游戏是手机游戏（模拟器/客户端负载极小）→「游戏抢满 GPU」假设降权，
嫌疑转向本进程内部（DML 会话互斥、显存水位、CPU 饥饿、盘 IO）。

已知前科（代码内注释）：
- 并发 DML run 段错误（2026-09-25）→ 全局锁串行，感知阻塞持有、深度 Busy 让锁；
- 显存吃紧时普通 run 触发显存分页，单帧 59→136ms（2026-10-01，8GB 卡水位逼近上限）；
- 一次深度前向 ~54ms 不可分割，错峰节拍（TICK_BEAT）压伸出量。

## 待复现问题（判据）

复现成功判据：**离线（无游戏、无采集）单进程内，感知会话单次 run 耗时 > 500ms**
（生产观测 799~1071ms；正常 ~8ms），且可稳定重复出现。100~500ms 记为弱复现。

## 方法

`repro.py` 自包含重建生产调用面（不 import 业务代码）：
- 感知会话：与 `core/yolo_detector.py` 同参构造（图优化全开、内核缓存、intra/inter=4、
  DML→CPU），输入 640×640 letterbox，持锁 run；
- 深度会话：与 `plugins/speedrush/depth_geo.py::load_session` 同参（自由维折叠 1×720×1280，
  DML→CPU），普通 run（生产 IO binding 是条件路径，先复现普通路径）；
- 锁协议：threading.Lock + 错峰节拍（感知放锁记拍，深度 worker 等新拍后开工，
  抢不到锁弃帧）；
- 节拍：感知 20Hz（50ms 预算），深度默认 160ms 间隔；
- 帧源：真实对局 raw 帧（debug 目录 720×1280 JPEG）循环喂；
- 独立标尺：nvidia-smi 500ms 轮询（利用率/显存/温度/频率），与停顿时刻对齐。

### 机制取证（V7b 停顿窗口，nvidia-smi 0.5s 轮询独立标尺）

- 停顿前 1 分钟：GPU 利用率顶死 94~99%、显存 7457~7487/8188MiB、功耗 77W；
- 停顿瞬间恰逢一次 churn（显存 7458→6852→6894MiB）：GPU 利用率归 0、功耗塌至
  25W、显存频率掉档，**外部 nvidia-smi 采样也被卡 2.3s**——驱动级内存管理停摆，
  不限于本进程；
- 压力球在显存最高水位（7572 / 7461MiB）churn 后**两次段错误**（exit 139），
  与 2026-09-25 生产段错误同型——停摆的升级形态。

### 结论（C 类，条件成立）

**8GB 卡显存逼近上限（实测 >7.4GB）时，~600MB 级显存分配/释放 churn 触发驱动级
停摆 0.4~2s**：本进程全部 GPU 上下文（两个 DML 会话、WGC 采集）冻结，停顿打在
当刻持锁/排队的那个会话上（感知或深度随机），停摆窗口内采集断流；可升级为
用户态驱动段错误。稳压（无 churn）只翻倍基线不打尖峰；CPU/GIL 压力非必要条件。

### 生产观测与解读撤回记录（2026-11-07 晚，gpu.jsonl 实测）

显卡采样上线后首场（20261107_185206）captured 停顿一次，生产解读据此两次修订。

**观测事实（保留）**：

- 对局全程显存 3.75~3.8GB/8188MiB，与离线无游戏基线几乎一致 → 游戏/模拟器
  基本不占本独显；
- 停顿拍：感知单次 1160.9ms（常态 7.7ms）；同刻 SM 频率 2775→210MHz、功耗
  52→7.5W、外部 nvidia-smi 调用 62→844ms；CPU 侧（落盘/控制）正常；
- 整场 139 拍 134 拍满频——事件一场一次，多在发车后 13~35s；
- 生产五次以上停顿零内核 nvlddmkm 记录；全天唯一一条（17:59:48，Id 153
  "Error occurred on GPUID"）恰为离线 V7b 复现停顿时刻。

**已撤回的解读（留痕，均为归因错误）**：

1. ~~「显存近上限分配突发触发」~~——生产显存无压力，出局；它只是离线复现的
   构造条件，不是生产触发条件；
2. ~~「独显深低功耗态转换（打盹）」~~——机器级解释，与「其他游戏/计算任务
   从未出现 ~1s 冻结」的经验事实矛盾；且离线复现的是硬失败形态（内核事件 +
   段错误），生产是无痕软停顿，触发器不同、未复现；
3. 频率/功耗塌陷的因果方向存疑（原因 or 停顿的无负载后果，210MHz 上 93% 利用率
   不似正常打盹）——不再作为结论使用。

**现存方向性事实**：问题在「NVIDIA 驱动 × 我方 DML 负载形态（计算型、无
present）」一层；生产触发器未明。归因瓶颈 = 案发中证据缺位（0.5s 常规采样
只能拍到恢复期）。已装现场抓拍（commit afb96fc）：在飞 run 超 200ms 即存证
节流原因位 / 每进程 GPU 引擎占用 / 全线程栈 → trace/stall_*.txt，待一场
停顿判决（节流类型 / 他进程占卡 / 我方线程卡点 三选一）。

缓解方向随之作废：~~独显保活~~（基于已撤回的打盹假设，未实施即废）；显存
减压降级为次要。

### 后续验证与缓解方向（未实施）

- 生产验证：流水加 nvidia-smi 500ms 轮询（显存/利用率/功耗），下一场停顿时刻若
