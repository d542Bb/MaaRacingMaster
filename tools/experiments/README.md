# experiments — 平台事实最小实验（活跃实验区）

回答「**这个外部系统事实到底成立不成立**」的实验脚本之家。实验与生产代码分离：
实验回答事实，生产代码回答事实成立之后系统该怎么实现。

> **本文是什么**：本目录的准入、生命周期与退役规则——实验**怎么进来**、**怎么出去**。
> **本区定位（一句话）**：`tools/experiments/` = **当前仍有未闭环问题的活跃实验**；
> 它不是归档区，历史档案是 **git log**。
> **信源等级**：L4（过程与证据）—— 可作「这个外部事实当时怎么验的」依据；**不得**作为
> 当前实现与规则的依据，正式知识（L0~L3）对具体实验路径的引用一律以 **commit 指针**替代。
> **继承**：通用协作与信源规则见 [`AGENTS.md`](../../AGENTS.md)（红线 6 是本区契约的守则侧表述）。
> **机检**：[`tools/check_repo_hygiene.py`](../check_repo_hygiene.py)（R1~R5，存量棘轮基线
> [`repo_hygiene_baseline.txt`](../repo_hygiene_baseline.txt)）。

## 适用范围：问题分级（A / B / C）

先判问题属于哪一级，再决定要不要实验：

- **A 类（纯设计**：拆分、命名、目录结构）——直接做，不需要实验。
- **B 类（谁创建 / 谁持有）**——grep 代码回答，不靠回忆。
- **C 类（外部系统行为**：是否阻塞 / 释放 / 污染 / 默认取值）——**先查官方文档**；文档不载时在这里落一个最小实验，**未经实验不得写成结论**。涉及面：Win32 / WGC / XInput / ViGEm / WebView2 / 游戏窗口行为等。

### C 类实验的两条硬约束

1. **留痕 = 过程进 git 历史 + 结论进 home**，不是"目录永久留在当前树"：
   实验至少有一个可追溯提交；结论兑现到 RULES / CODE_WIKI / ADR 等 home 后，
   本区目录按下方生命周期退役。**没有痕迹就没有基线**约束的是"进历史"，不约束"留在树里"。
2. **标尺独立于待验证对象**——用待验证的实现生成判据是循环论证（拿自己刚写的转换函数去生成对照图，等于让被告当法官）；标尺只能来自权威文档、独立工具或已知真值。

### 判决统计前置检查（裁定前必查，立规 2026-09-20）

统计量出判决结论前，四问缺一即不得提交裁定（来源：speedrush 标定滚动分叉多轮失效复盘）：

1. **同层吗**：判决量与期望量必须在同一变量空间（速度对速度、步长对步长）；
   端点比与段均值比混用等于拿苹果比橘子。
2. **归一了吗，缺口在哪端**：含时间/尺度步进的统计量必须除以步长（dt 归一）；
   数据缺口落在统计窗口首/尾会单向压低/抬高判决值——逐样本打印缺口位置，
   与判决偏移做**判据核对**后才可归因于对象/关联器。伪重复（观测对数当样本数、
   轨内趋势与轨间散布池化）同此问：n 按独立单位报，SE 按独立单位聚类。
3. **身份先于统计量**：每个进入判决表的样本必须有对象身份验证（叠图/实测），
   人眼判读要标注「非机检判据」；未验身份的样本不得进判决表，被自判污染的
   窗口不得同时充当判决。顺序不可倒：**对象身份 → 判决统计量 → 判决**。
4. **这个量变不变**：凡「按某个量取窗/取线/取阈」的地方，先问该量在适用范围内
   是否变化、变化幅度与容差之比多少——把参数当常量而它实为变量，是比「统计量
   不对」更一般的一类错误（实例：固定高通窗 vs 周期∝d²；固定 a 线 vs 扫描峰
   锁错线族）。容差须写成硬约束入条目（如 Δa < 段半宽/d_max），且归因竞争假设
   用**零成本判别测试**定（序列自相关分噪声/慢漂/系统变），不靠论证。

**资产与临时产物的分界**：换个人能否**复算出同一结论**——能，靠的是"git 历史 + 结论 home +
（如有长期价值的）提升后仪器"三件套，不是靠目录永存；不能复算的中间文件，用完即清。

**委托研究（外部 LLM / 人工调查报告）**：原文**不进树**（留在工作台或外部上下文），
进树的只有实验 README 里的**采纳清单、更正清单与理由**——防止未来读者把"被采纳的结论"
与"原始材料"混为一谈；溯源写"见 commit <SHA>"。

## 生命周期

### 入口（新建主题）

- 一个主题一个子目录：`experiments/<主题>/`。
- **必须有 `README.md`，文首含 `status: active` 行**（机检 R1）。status 是给 agent 与
  检查器看的**入口护栏，不是状态数据库**——不存在 "closed 但留在树里"：在树即 active，
  退役即删除。禁止给来历不明的存量目录批量补 status（见下方 legacy 分诊）。
- 实验脚本**自包含、可直接运行**，不 import `maaracing_master` 业务代码；需要的能力在脚本内最小自建。
- 结论同时按触发清单写入项目记忆库。

### 出口（实验关闭 = 四步，顺序不可换）

1. **结论迁 home**：成立/不成立/条件成立的最终结论写进其归属（`RULES.md` / `CODE_WIKI.md` /
   ADR / 指南），证据指针写 **commit**，不写本区路径。
2. **仪器提升**：仍被消费的探针/脚本换住户——移入 `tools/` 正式位或直接进消费它的插件，
   并把引用改指新址。判据同"第二个使用者"：今天真实存在才提升，否则随目录删除。
3. **拔引用**：全仓 grep 本主题名，把 L0~L4 各层引用逐一换成 commit 指针或新址
   （机检 R2/R3/R4/R5 就是这一步的验收）。
4. **删目录**：`git rm -r tools/experiments/<主题>/`。历史即档案，`git log -- tools/experiments/<主题>` 可查回全过程。

### 两类污染（机检覆盖的违规形态）

- **知识引用污染**：正式文档（L0~L3）或实验 README 把"去某实验目录看结论"当知识路径
  （R2/R3）——临时资产被引用一次就升格成永久依赖，这正是本区只进不出的病根。
- **运行依赖污染**：生产代码 / 测试 / 运维入口直接调用实验脚本或读其产物（R4）——
  这类要先走"仪器提升"再谈退役，**不允许为了过检查而删掉在用的工具**。

### legacy（立规 2026-09-18 时的存量）

无 README / 无 status 的存量目录**不批量盖 active 章**——那等于给未知资产发居住证。
它们全部记入基线豁免；**每次触碰某个 legacy 主题时先分诊**：
A 仍在用 → 补 README + status；B 仪器被消费 → 提升 + 拔引用 + 删；C 结论已在 home → 删；
D 已废弃 → 删。基线只减不增。

## 归档语义澄清

`archive/`（gitignored）只用于**真正需要保留的已退役生产资产**（如旧数据集、被替换的实现），
**不是**"实验做完先丢进去"的垃圾桶——gitignored 的归档对 git 历史不可见、对 agent 可见，
与 `docs/plan/` 是同一类黑洞。实验的过程档案在 git 里，不需要第二份。

## 先例

- `cursor_refactor` 探针 → 事实沉淀 → 生产化为 `core/gamepad_cursor.py` +
  `core/resources/stick_speed_model.json`（工具本体属"已退役生产资产"，归档 `archive/cursor_refactor/`）。
- 新实验照此路径走：**实验 → 结论入 home 与记忆库 → 仪器提升或随目录退役**。
