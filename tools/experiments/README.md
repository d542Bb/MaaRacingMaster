# experiments — 平台事实最小实验

回答「**这个外部系统事实到底成立不成立**」的实验脚本之家。实验与生产代码分离：
实验回答事实，生产代码回答事实成立之后系统该怎么实现。

> **信源等级**：L4（过程与证据）—— 可作「这个外部事实当时怎么验的、结论与复现命令」的依据；**不得**作为当前实现与规则的依据（结论兑现后已上提到 L1/L2）。
> **继承**：通用协作与信源规则见 [`AGENTS.md`](../../AGENTS.md)。

## 适用范围（C 类问题）

凡涉及 Win32 / WGC / XInput / ViGEm / WebView2 / 游戏窗口行为等外部系统的
「是否真正释放」「是否全局污染」「是否阻塞」「行为是否可控」类疑问，
**未经实验不得写成结论**，先在这里落一个最小实验。

纯函数拆分、接口命名、目录结构等设计问题不需要实验（A 类）；
「谁创建 / 谁持有」类问题先 grep 代码（B 类）。

## 目录约定

- 一个主题一个子目录：`experiments/<主题>/`（如 `xinput/`、`wgc/`、`titlebar/`）。
- 实验脚本**自包含、可直接运行**（`python tools/experiments/<主题>/<脚本>.py`），
  不 import `maaracing_master` 业务代码；需要的能力（截图/手柄）在脚本内最小自建。
- 每个主题目录内放一个 `README.md`：记录**实验结论**（成立/不成立/条件成立 + 复现命令），
  结论同时按触发清单写入项目记忆库。
- 大型探针工具（需要采集数据/训练模型的）完成后移到仓库根 `archive/<名>/`——本机归档目录，
  `.gitignore` 已排除。

## 先例

`cursor_refactor` 探针（cursor_monitor 三态识别 + 连续 P 趋近 + 速度模型标定）
→ 事实沉淀 → 生产化为 `core/gamepad_cursor.py` + `core/resources/stick_speed_model.json`，
工具本体归档 `archive/cursor_refactor/`。新实验照此路径走：
**实验 → 事实入记忆库 → 生产实现 → 工具归档**。
