# frame_delta — 路心/执行位帧差与参考系分账（活跃）

status: active

**问题**：生产计划在「场景路心位置」与「执行位」差超过 1 m 时整拍失效
（`plan:frame_shift`）。本实验只读地量化：大差窗口由哪类路心来源产生、哪些
窗口确实关联计划否决/换道中断、能否定位到具体数据源或接口边界。

**只读**：不 import 控制链、不改生产数据；只读 trace 与 policy JSON。

## 运行

```bash
.venv/Scripts/python.exe tools/experiments/frame_delta/probe_frame_delta.py \
    [--manual 20261028_225902] [--session NAME ...] [--root DIR] [--selftest]
```

默认读 `%APPDATA%/MaaRacingMaster/logs/*/trace/speedrush.jsonl`；`--manual`
把指定会话标为人工局（trace 里没有驾驶模式字段）；`--csv PATH` 输出 94 次
重基的逐次事件（本地分析用，不入库）。

## 口径

1. **帧差** `fd`（米）：优先 `plan.fd`（生产同一量）；无计划但有场景时用
   `scene.ego_m - executed_lane*lane_w` 重建；缺任一侧记未知。
2. **大差**：`|fd| > motion.frame_delta_hold_m`（当前 policy = 1.0 m）。
3. **窗口**：相邻大差拍**最多夹 1 拍**非大差（桥拍）即并入；夹 ≥2 拍断开；
   `fd` 未知拍断开并单列（不冒充非大差拍）。
4. **来源**：`ro_source` × `dgeo_new`（本拍是否有新深度）× `ro_hold`
   （planner 是否按历史保持消费）。窗口同时记首拍来源、主导来源与切换史；
   不按结束来源归类。
5. **计划**：`none`（未生成）/ `veto`（生成后被否，按 reason）/ `valid`，
   前两者分开计数。
6. **冻结中心**：窗口内同一 `road_offset` 连续 ≥3 拍、且执行位移动 >0.3 道。
7. **重基事件**：`lat_ctrl.rebase` 非空的拍；exec 跳变 = 本拍 executed 与
   上一拍之差。
8. **线观测只作辅助**：`lane_fuse.trusted` 且 `sm` 非空时比较
   `|road-sm|` 与 `|exec-sm|`；线也参与 executed 融合，不是独立裁判。
9. **映射核验（重基参考系）**：把「尺子动没动」和「车动没动」分开：
   - 尺子：`Δro = ro(i) − ro(i−1)`；`|Δro| ≤ 0.4`（供数链自己的跳变门容限）
     记 stable，否则 moved。`Δc0 = c0(i+1) − c0(i)` 是场景分带中心（换纪
     触发 ①）在下一拍参与比较的变化。
   - 物理证人：跨拍配同色同侧的 `lane_obs.lines[].L`（自车系物理量，不随深度
     锚点重编号）与 `dgeo_left/right`（原点=车）；正=自车右移。位移达到
     `0.6·|Δro|` 记「由运动解释」。
   - 新值复核：同拍 `lane_obs.x`（锚定横位，量化 ±0.5 道）或双侧深度缘中心
     与 `post` 的差。
   - 结论口径：尺子 stable → 恒等（参考系未重编号）；尺子 moved + 证人无位移
     + 平移量为整数道（±0.25）+ 新值被复核 → 平移-确认（旧道号 = ref +
     round(Δro)）；moved + 保持/记忆源或证人矛盾 → 陈旧可疑；其余 moved →
     平移-未确认。证据量 = 物理证人 + 同拍复核，两项=双证、一项=单证、无=无证；
     线值与深度中心同源，双证不等于「新中心绝对正确」。

- **因果（源码级）**：调用顺序是 `engine.update`（吃重基前 executed）→
  `plan_motion`（同前）→ `planner.update`（重基改 executed）；下一拍
  `_ruler_epoch` 拿新 executed 与上一拍比，超过 0.5 道就 `epoch+1`，
  `tick_route` 随即 `_rebuild(... "epoch_reset")`。94 次里 **83 次满足
  |Δexec|>0.5 且下一拍换纪**（机械因果，不只是时间相邻）；1 次换纪但非重基
  引起；10 次无换纪（|Δexec|≤0.5 或缺计划输入）。
- **承诺**：重基前在并线 22 次，其中 10 拍内 ref 变化 **19 次**，10 拍内
  重新起意并线 8 次——并线期重基几乎必然改写承诺。
- **陈旧只占少数**：A+B 共 17/94；C 里 64 次是新鲜 wall 源的 `jump_confirm`。
  也就是说，主导问题不是「陈旧路心算法」，而是**任何约 1 道的重基修正都会
  撞上 0.5 道的换纪门**，不论修正是新鲜跳变还是陈旧纠正。
- 具体样例（`20261028_210938` fid 4029–4138，54 拍 / 2.7 s）：wall_occl/
  memory 保持的路心卡在 −1.6 道，车实际从 +0.49 移到 +0.20；重基前帧差从
  −2.8 涨到 −6.2（4060 拍）；4062 拍 `hold_stale` 把 executed 从 +0.197
  拽到 −1.637（1.83 道）；4064 拍换纪（ref 0→−1），并线被结束。该事件在
  严格口径下是 B（路心值在 −1.60/−1.64 间小幅摆动，未达 1e-3 冻结），
  但 hold_age=11、adopt 差=0——「采用了一个长期保持的旧值」这一点成立。
- **坐标映射（已核验，见下节）**：所有等级 adopt 差都是 0.00——重基把
  executed 直接设成当前路心观测。22 次并线期重基里，18 次**路心观测本身
  只变了 ≤0.4 道**（尺子 stable），是执行位状态追平观测；20 次换纪触发里
  `c0`（场景分带中心，触发 ①）**一次都没跳**——都不是参考系重编号，而是
  executed 单跳触发了 ② 号门。

## 并线期重基：坐标映射核验（22 次）

对 22 次 `route.ph=merging` 的重基逐次核验（全表由探针输出；`--csv` 导出
`map_*` 列）：

| 结论 | 次数 | 含义 |
|---|---:|---|
| 恒等（参考系未动） | 16 | 尺子 stable + 执行位跳变 + 旧 ref 在下一拍候选道表 |
| 平移-确认 | 1 | 尺子动了整数道、物理证人无位移、新值被线值复核 |
| 平移-未确认 | 2 | 尺子动了，但证人缺失或新值未被复核 |
| 陈旧可疑 | 1 | 尺子动 + 保持/记忆源 + 证人位移只有尺子位移的约四成 |
| 无换纪 | 2 | `|Δexec| ≤ 0.5`，门不会动 |

- **换纪门实际触发 20 次**：`c0` 跳超半道 **0 次**，全部由 executed 单跳
  触发；其中 16 次尺子 stable 且旧目标道仍在下一拍候选道表——清空的是
  **参考系没变、旧目标道仍存在**的承诺。
- 物理证人（同一条线的 `L` 变化）在 stable 事件里最大 0.44 道（fid 3661），
  其余 ≤0.19 道；而同拍 executed 跳 0.75~3.19 道。**车不可能在一拍内横移
  一道以上**，所以这些跳变是状态估计追平，不是车辆位移。
- **例：fid 4062（hold_stale，B 级）** 不是坏重基：路心 −1.637 与线锚定
  横位 −1.733、单侧深度缘 −1.761 相差 ≤0.12 道（线值锚定深度中心，只算
  同源一致），而 executed 停在 +0.197——重基把状态改到观测处；换纪随后
  把 ref 0 改成 −1。
- **唯一平移-确认：fid 4275**。路心从 +0.407（memory）跳到 −0.796（wall），
  平移 −1.20 道；同拍右侧线 `L` 只动 0.09 道（车没动）、线值复核差 0.28。
  旧 ref +1 在新参考系为 0（残差 −0.20 道）。实际下一拍路线重建到 −1，
  10 拍内又向左并到 −2——承诺不只是被清空，方向也反了。
- **平移-未确认 / 陈旧可疑**：fid 1785（−0.99 道，换线后无可配对的物理
  证人）、fid 2327（+0.91 道，证人只 +0.34、线复核差 0.55）、fid 3420
  （hold_stale/memory，+0.80 道，证人 +0.33）。这 3 次不宜按道号平移。
- **证据边界**：稳定子集里的「恒等」只说明参考系没有重新编号，不说明路心
  观测本身正确；线锚定横位与深度中心同源，不能当独立真值；`L` 只证明车
  没有位移。要判「新中心对不对」还需要与路心链独立的第三源，目前没有。

## 并线期重基：米制目标与消费时序（22 次）

对同样的 22 次逐次核验「清空承诺前后，目标与 ego 的实际消费值是否连续」。
消费时序（源码顺序）：`engine.update` 吃 **pre-executed** 与 `road_offset`
→ 决策/选择/路线；`plan_motion` 吃同一 pre-executed；`planner.update` 先按
旧状态控杆、再重基 executed；下一拍换纪门比较新 executed。trace 对应：
`plan_ego[0]`=pre、`executed_lane`=post、`x_target`/`goal`=决策目标、
`road_offset`=实测 ego。

口径（全部米制，选择帧）：

- `e_y = (x_target − road_offset)·lane_w`：目标与实测 ego 的相对横向误差；
  重基拍与下一拍都取同一公式，Δe ≤0.10 道算连续。
- 旧目标道占用：同拍 `coarse.cand` 里旧 `ref` 的 blocker/free，t 与 t+1 对比；
  出现车/空间 = 恶化。
- 合并几何：回溯本段 `merge_start`，比较「承诺时的目标距离」与「修正后的
  目标距离」。修正后已越过目标（目标落到车后）或变远 >0.7 道 = 前提变化。
- 下游：下一拍计划是否有效（`plan.valid`）。

结果（统计限 16 次恒等事件；探针全表另含平移/陈旧/无换纪）：

| 结论 | 次数 | 含义 |
|---|---:|---|
| 米制通过 | 5 | 恒等 + 旧道未占 + 几何未坏 + 下拍计划有效 + 误差连续 |
| 已越过目标 | 4 | 修正后目标已落到车后 |
| 目标占用恶化 | 3 | 旧目标道在下一拍出现车 |
| 目标前提变化 | 3 | 修正后离目标变远 >0.7 道 |
| 计划仍无效 | 1 | 下拍计划仍被否，无法验证可执行性 |

- **评审候选（恒等 ∩ 米制通过）= 5 次**：fid 1787、4482、2488、3700、
  2149。它们满足：参考系未重编号、旧目标道未被占、下拍计划有效、下拍尺子
  稳定、相对误差变化 ≤0.10 道。**只有这 5 次**支持把「清空承诺」作为
  可评审的误清；其余保持现状。
- **失效不是瞬时目标跳变**：这 5 次的 `x_target` 在换纪后先驻留约 0.5 s
  （选择器 dwell），随后移到新 `ref`；所以代价是**约 1 s 后放弃原目的地**，
  而不是下一拍方向盘突变。同拍计划反而因为 executed 追平而恢复有效
  （这 5 次下拍 `plan.valid` 全为真，2488 为 `ok_uncertain`）——重基修的是
  计划帧，换纪误伤的是路线承诺，两者在同一拍发生。
- **机制证据仍然成立**：16 次恒等事件里换纪门清掉了仍然存在的目标道；
  但把米制目标、占用、几何和下游计划一起看，只有 5 次是「纯状态修正
  造成的无意义失效」的合格候选。
- 被排除的例子：fid 3661/3391/3599 修正后车已越过原目标（保留承诺会让车
  回头）；fid 4062 下一拍尺子又跳 1.12 道（陈旧路心被后续读数纠正）；
  fid 2233/3169 修正后离目标远了 1.4/0.9 道；fid 3332/3817/3859 旧目标道
  下一拍有车；fid 2396 下拍计划仍然不可行。
- **尚未核验**：跨道路径的**中间道**占用（本次只查目标道，候选表不含路径）；
  `lane_from` 不在 trace 里，合并源道无法逐次复核。因此 5 次全部通过也
  **不能**无条件跳过换纪门。

## 三问的回答

1. **哪类来源产生大差窗口**：wall_occl 与 wall 各占 40%（各 264 个首拍）；
   按主导来源 wall_occl 49%。wall_occl/memory 合计约 50%——**保持读数是
   半壁江山**；wall 是新深度跳变。共同点是来源交接，而不是单一算法。
2. **哪些窗口导致计划否决/换道中断**：所有窗口都机械地触发帧差异否（同一
   个量）；26% 窗口与并线重叠；并线结局前 10 拍有窗口 64% vs 基线 50%，
   **关联弱**。真正锐利的是重基：94 次里 83 次满足 |Δexec|>0.5 且下一拍
   换纪（机械因果），并线期 19/22 次改写承诺。
3. **能否定位到数据源/接口边界**：能定位到**参考系交接与重基/换纪的接口**：
   - 窗口首拍 90% 在来源/状态切换的 2 拍内（基线 62%/68%）；
   - 冻结中心窗口 124 个（19%），wall_occl/memory 占大头；
   - 重基把路心修正写成约 1 道的执行位跳变，路线换纪门（0.5 道）随即作废
     承诺——**修正与换纪在互相打架**。
   - 线观测更像支持执行位（79%），但线参与执行位融合，只能当线索，不能
     据此判「路心算法错」。

## 结论与边界

- **已确认**：大差 = 计划整拍失效（25% 拍）；窗口集中在来源交接；重基修正
  与路线换纪形成**源码级**高频链路（83/94 机械因果），单次约 1 道执行位跳变；
  并线期重基 19/22 次改写承诺。并线期 22 次重基中 20 次触发换纪，`c0` 跳变
  0 次——换纪来自 executed 单跳（②），不是参考系重编号（①）；其中 16 次
  旧目标道仍在下一拍候选道表、参考系未动。再按米制目标/占用/几何/下拍计划
  核验，16 次里只有 5 次（fid 1787、4482、2488、3700、2149）是「纯状态修正
  误清承诺」的合格候选。
- **未确认**：大差是否导致大部分换道中断（基准校正后关联弱）；是否是选择
  目标错（ref 只变 7.4%）；哪一侧估计器真的错（线不独立）。因此不能把
  「开得不好」直接归因到路心算法。
- **失败形态更像**「修正把承诺冲掉、计划被拿掉」，而不是「选错道」。它对
  得分/安全的影响还需要单独的度量（计划失效期间的避让/贴线表现）。
- 人工局与程序局：大差拍占比相近（21% vs 25%），但重基 5 vs 89——差异在
  **修正响应**，不在失配发生率；赛道不同，不能当因果。
