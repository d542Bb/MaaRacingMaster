C · 缩放基准 —— 区分系统 DPI 与页面缩放（读数见页面顶部）。

页面缩放（Ctrl + 滚轮）会并入 devicePixelRatio；visualViewport.scale 反映视口缩放（桌面端通常为 1）。判读协议：先按 Ctrl+0 归零页面缩放，再读顶部数值。

判读指南（逐层排除，不跳步归因）

第一步 · 字体层：② 中若某个字体在同等字号下明显更清晰、更顺眼 → 字体族方向成立。改 --mra-font-sans 真机验证；正式分发需打包字体文件（本机装了 ≠ 玩家装了；思源/Noto 为 SIL OFL 许可可再分发，属第三方资产，落地前确认）。

第二步 · 参数层：③ 与 ④B 中若某个字号 / 字重 / 间距组合明显改善 → 排版参数方向成立，改 token，改动小、零依赖。

第三步 · 渲染链：仅当字体与参数实验均无明显改善、且不同字号下文本呈一致的软化特征时，才进入渲染链排查——系统 DPI → WebView2 viewport → 页面缩放 → CSS 布局 → 字体选择 / fallback → 文本栅格化 → 屏幕像素。④A 几何读数与顶部 DPR / scale 只提供线索，不单独定因。

对照原生软件的观感差异，本页不做成因预设；若走到第三步仍无法解释，再另行设计渲染链专项实验。

在 Shell 宿主内看：F12 → Console → 把 location.href 指向本页在本机仓库中的 file:// 绝对路径，读数即真机宿主值。在浏览器里看请先 Ctrl+0 归零缩放。
