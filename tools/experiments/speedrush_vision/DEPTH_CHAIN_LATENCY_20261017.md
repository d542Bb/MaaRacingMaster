# speedrush 深度供数链路：时间口径与几何块时延（2026-10-17）

**它是什么**：本轮「先让时间对得上，再让链路变快」的预登记、改前基线与改后实测记录。
**它不是**：设计稿或结论汇总——锚点策略结论在 `docs/plan/`，这里只放本轮的测量与验收。

## 1. 改前核查（与任务前提的偏差，两条）

### 1.1 锚龄钟已经是采集钟，不是到达钟

车锚链一路都是采集时刻，自 `b385d4b`（2026-10-07 落产线）起未变：

`push(frame_ts_ns)` → `anchor_sheet_from_detections(ts_ns=frame_ts_ns)` →
`DepthAnchorSheet.ts_ns` → `t.anchor_ts_ns = sheet.ts_ns` →
`age_ms = (per.ts_ns − anchor_ts_ns)`、`dt_s = (sheet.ts_ns − anchor_ts_ns)/1e9`、
EXPIRED 判据。

数据侧（`probe_anchor_clock.py`，20261017 四局 2937 拍）：**401 个新锚 ingest 样本，
实测 age / 预期内容龄 = P50 0.95（P10 0.85 / P90 1.11）**。到达钟应≈0.1。

### 1.2 「投影残差 86~113px」是口径伪影

`probe_hold_cf` 的残差式 `|cy − (y_h + VPX·cam_h/m)|` 用 **VPX=640.7 当焦距**、
把**框心当接地点**。实际焦距是 `dgeo_focal`（P50 589.7），接地点是框底 `cy+h/2`：

| 5-10m 段（近场轨 n=71） | 残差 P50 | m − m_pix P50 |
|---|---|---|
| 原口径（VPX＋框心） | 103px | −3.72m |
| 换框底（仍用 VPX） | 73px | — |
| **焦距＋框底** | **3px** | **+0.05m** |

框心偏移两处独立印证：`cam_h_eff=(cy−y_h)·m/vpx ≈ 1.08` vs `cam_h=1.90` → 半车高
0.82m；`h·m/f ≈ 1.49m` 车高。近场残差大是 1/m 放大的几何偏置，不是陈旧度；
B1 外推反事实的 +4280% 也是拿这个偏口径量的。近场真实误差是离散度（P10 −3.1m /
P90 +4.9m，z 与框抖动），不是系统性偏大。

## 5. 改后实测

### 5.1 离线（`probe_geo_decimation.py`，产线同路径 observe_debug，26 帧）

|---|---|
| GEO_DS=1（旧全幅） | 175.9ms |
| GEO_DS=2（2×2 抽取） | 113.9ms |

分段（同一台机器、同时段，机器负载偏高故绝对值高于产线 trace）：plane 51.1→11.9、
edges 实段 50.1→15.8、grid 50.1→15.0 ms。

读数一致性（预登记第 6 项）：sides 同判 26/26；左右缘车道差 P50 = 0.000 lane、
P90 = 0.004；栅格近场裁决带同判 99.6%、blocked→drivable 漏判 0.000 —— 全部达标。

**已知代价（如实记录）**：左缘在 4/26 帧与全幅不同（差 0.37~0.62 lane），逐帧跳变
8/25 vs 全幅 6/25——「最近一致边界」在车道级/护栏级两种语义间换选（`_side()`
注释记录的既有不稳定面），抽取后 x 格点数降至 1/4 使 EDGE_MATCH_M 判定的临界帧
更容易翻边。右缘 26/26 完全一致。行抽取（只减行、保列）实测更慢（18.3 vs
12.8ms）且换选帧更多（5/26），故不采用。

**回滚**：`GEO_DS = 1` 即逐位回到旧路径（带区/焦距/像素诊断在 ds=1 时恒等），
无需改其它代码。

### 5.3 为什么 `fid_lag` 停在 6：地板分析

observe 的**非几何地板**（与抽取无关、不可压缩）：pre 5.8 + forward 45.4 +
reconstruct 6.3 + upsize 5.4 = **62.9ms**。加 cap_pick 12.3 + det 9.7 + 控制拍量化
（结果发布落在 take 之后就要等满一拍，均值 ~25）= **≈110ms ≈ 4.4 帧**。

即：几何块即使归零，`fid_lag` 也只能到 ~4.4 帧；≤4 帧要动模型输入或消费时序，
不是这条链路能挤出来的。

本轮实测 `pub`（发布→消费）从 32.2 涨到 **58.9ms**，把 observe 省下的 35ms 吃掉
大半——直方图双峰（0~25ms 208 次 / 50~75ms 504 次）：observe 93ms 与拍 50ms 不成
整数比，多数结果发布在 take 之后、要等下一拍。这是**控制拍量化**，不是推理延迟。
（§6 追加一个成因：调试落盘的 90ms 周期踢动把发布相位搅乱，已修。）

要继续往下压只有三条路（都不在本轮授权内）：① 降 MoGe 输入分辨率（1280×720 →
960×540，forward 约 −20ms，动深度质量）；② 消费改事件驱动（省掉 ~25ms 拍量化，
动控制循环结构）；③ 锚点路径与路面几何解耦、几何降频（省 ~10ms，road_offset
供数节拍变化）。

## 6. 追加：调试落盘一直占着 worker 周期（2026-10-17 复查发现，已修）

代码原状：`_write_debug` 在 **worker 线程内联**做渲染 + 编码 + 写盘。它自己的
docstring 写着「debug 绝不干扰主路」，实际不成立——取证局（debug 全开）每 0.5s
付一次：

| 环节 | P50 |
|---|---|
| `render_depth_debug`（三行堆叠渲染） | 78.4ms |
| 两张 JPEG 编码 | 7.0ms |
| 写 jpg（~0.5MB） | 1.8ms |
| `np.savez` 证据包（1.3MB） | 3.0ms |
| **合计** | **90.1ms** |

用 stub 固定 observe=93ms、节流 0.5s 照旧，量发布间隔：

| 臂 | P50 | P90 | 平均 |
|---|---|---|---|
| 内联写盘（原状） | 95ms | **206ms** | **118ms** |
| writer 线程（改后） | 94ms | **96ms** | **93ms** |

即被调试落盘顶住的那一拍结果凭空老 ~90ms，周期 P90 翻倍；且 90ms 的周期踢动
把 worker 的发布相位搅乱——与 §5.2 的 `pub` 双峰（0~25 / 50~75）同源。

**修法**：渲染/编码/写盘整段搬进 `speedrush-depth-dbg` writer 线程，worker 只做
「要不要写」的节流判定与入队（µs 级）。队列上限 6 包（每包≈帧 2.7MB + 原生点图
2.4MB），满了丢新包并计 `health()["debug_dropped"]`——debug 绝不反压推理。停机
排空式退出（已入队的包照写，收局取证包不丢）。events 模式仍保留 worker 内联编码：
它的 ring 存的是已编码字节（~2-3MB/包），改存原始帧会涨到 ~5MB/包 × ring 长。

顺带修一处潜在坑：`start()` 未清 `_stop`，复用同一实例重启时新线程会立刻退出
（当前调用面每阶段新建实例，未触发）。

**预测（待实机验证，未计入 §5）**：发布相位不再被踢，`pub` 应向 ~25ms 附近回落，
`fid_lag` 均值再降约 0.5~1 帧。这条是预测，不是结论。
