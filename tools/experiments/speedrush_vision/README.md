# speedrush 视觉可行性（C 类实验，2026-09-18）

> **本文是什么**：旧检测模型在**新录帧**上还能不能用的一次测量——结论、证据与复跑命令。
> 它是收益模型（`docs/plan/speedrush-control-route.md` 阶段 C）与感知层（阶段 B）的**前置事实**。
> **本文不是什么**：不是控制方案，也不是"该用哪个模型"的选型结论；域内实现与规则真源归
> [`plugins/speedrush/RULES.md`](../../../maaracing_master/plugins/speedrush/RULES.md) 与
> 各 `CODE_WIKI.md`。
> **信源等级**：L4（过程与证据）——可作"这个事实当时怎么验的"的依据。
> **继承**：实验规范见 [`tools/experiments/README.md`](../README.md)（C 类两条硬约束、资产分界）。

## 素材与方法

- **模型**：`archive/racing/resources/onnx/model.onnx`（旧赛车栈的 **YOLO11n**，2026-07-21 训，
  3 类 `coin / car / bonus_car`，输入 640 letterbox，ONNX 元信息里有 `names`）。构建产物里也随包分发。
- **帧**：`data/speedrush/demos/` 的新录帧（1280×720），4 个会话 × 15 帧（掐掉首尾 10%）。
- **口径与旧栈运行时逐项对齐**：RGB、`min(640/h, 640/w)` 缩放 + 114 灰边、`/255`、NCHW；
  推理 ROI = `(0, 201, 1280, 561)`（旧栈 `loop.ROI`）。探针自建这份预处理（实验自包含约定，
  不 import `core`，也不碰仓库里的 ort 优化缓存）。
- **判据：不设阈值看 class 原始分**。"零检出"有两种成因——**模型不认**（要重训）与
  **画面里本来没有**（换采样即可），只看 >0.35 的框数会把两者混成一句结论。故按类统计
  原始分的 中位 / P90 / 最大。

## 结论（60 帧，2026-09-18）

| 类别 | 最高分中位 | P90 | 最大 | >0.35 框数 | >0.15 框数 |
|---|---|---|---|---|---|
| `coin` | 0.027 | 0.742 | 0.907 | **59** | 88 |
| `car` | 0.765 | 0.876 | 0.927 | **360** | 466 |
| `bonus_car` | 0.000 | 0.863 | 0.897 | **65** | 74 |

**三类都活，旧模型可用**：

- **街车最稳**：中位 0.765，60 帧里 360 个高置信框。
- **金币与奖励车**：中位低、P90 高、且有 0.8–0.9 的高置信框——即"**画面里有目标时认得出**"，
  只是多数帧画面里没有币/奖励车。**故不是域漂移**。
- **一处必须记住的教训**：本实验第一次冒烟只抽了 24 帧，金币**零检出**，差点被判成"金币类失效"。
  实际是采样不巧——`coin` 的原始分中位只有 0.027（多数帧没币）。**判"模型失效"之前先确认
  画面里有没有目标**，与域文档「读数正确 ≠ 语义正确」同源。

**对收益模型的硬缺口（旧模型给不了，与"能不能用"无关）**：

1. **两类奖励车被合并**成一个 `bonus_car`（旧训练的口径，见 `RULES.md` §7#16），
   而**跳台车（木桶旋转 / 浮空金币组）与磁暴车（退场社会车辆）的机制与收益不同**——
   收益表要分开它们。
2. **没有"金币组"这个结构**：组内 3 枚（平地）/ 4 枚（半空）、组间接续规律（§7#3）未知，
   而这是决策层"预判 vs 反应"的分水岭。
3. **自车外观依赖未验证**：不变量要求"换车 / 换皮肤不影响表现"（`speedrush-control-route.md` §〇），
   旧模型的训练集是否做过自车区域遮挡增强**未查证**，故该条对旧模型是**待实测项**。

## 远景检出与开销：分辨率扫描 + 延迟预算（2026-09-18，维护者质疑驱动）

维护者两点质疑：**"远处的东西 YOLO 标不出来，深度至少能返回『有个东西』"**、
**"用最新模型/最新训练方式能不能降开销"**。两条都先量再答。

**配对设计**（随机采样 18 帧里只有 1 帧有币，组间比较会被"这帧有没有币"主导）：
先在 `640×360` 切片下**扫全场找出有币的帧**，再在**同一批**帧上比四种配置。

扫描（`640×360`，2 次推理/帧，DirectML）：四场共 2463 帧，**有币帧占 21% / 33% / 42% / 50%**
——金币是**常见**目标，此前"零检出"纯属采样不巧。含读盘与 JPEG 解码约 15–16 ms/帧。

配对（取币最多的 12 帧）：

| 配置 | 有效缩放 | 每帧推理 | 币框合计 | 最远检出 y | 每帧纯推理 ms |
|---|---|---|---|---|---|
| 全帧 | 0.50 | 1 | 128 | 214 | **5.4** |
| 640×360 切片 | 1.00 | 2 | **196** | 213 | 10.9 |
| 426×240 切片 | 1.50 | 6 | 117 | 213 | 33.1 |
| 320×180 切片 | 2.00 | 8 | 16 | 274 | 43.9 |

**四条结论**：

1. **有效分辨率是杠杆，但不是越大越好**：翻倍到 1.00 时币框 **+53%**（128→196，成本 5.4→10.9 ms）；
   再往上（1.5×/2×）检出**反降**——切片会切断跨界目标，且远超训练时的尺度域（旧模型见过的
   是 1920×1080→640 = 0.33 与 1280×720→640 = 0.50 两档）。
2. **"远处标不出来"这个前提在本作不成立**：三种配置的最远检出都落在 **y≈213**，即贴着地平线
   （币在那里只有几像素）。**距离上限是"小目标下限 + 地平线"，不是 letterbox 也不是模型盲**——
   把分辨率再拉高也没有更远的东西可检。⚠ 本测试的路面带从 y=180 起，故"更远"这一侧被截断过。
3. **算力不是约束**：单次 640 推理 **5.4 ms**（DirectML），检测只占 15 Hz 帧预算（66 ms）的 **8%**；
   连切片方案（2 次/帧）也只到 16%。旧栈"每 N 帧才推理一次（≈10 Hz）"是 **CPU 时代（30 ms 级）**
   的尺寸，照搬到今天等于白扔分辨率。
4. **深度要解决的问题，可能不是"看得更远"**：远景币在贴地平线处已无可检之物，而单目深度在
   **几像素的小目标**上同样弱（合成场景里路面平面还主导整幅深度图）。真要验，最便宜的做法是
   拿 `yolo26n-depth` 在一小批帧上出图，看它是否真在远景给出可用信号——**但那要新增依赖与权重
   下载，按纪律先问维护者**。

**关于"换最新模型/最新训练方式能不能降开销"（一手核实 Ultralytics 官方文档）**：
`yolo26n` = 2.4 M 参数 / 5.5 GFLOPs（我们的 YOLO11n 为 2.6 M / 6.5 G），官方称 CPU ONNX 路径
比 YOLO11n **快至 43%**，且可选 **NMS-free 端到端**（`nms=False`，省掉我们现在在 Python 里做的
逐类 NMS）；七任务含深度（`yolo26n-depth.pt`），T4 TensorRT 下 1.7 ms。**判读**：换架构能省的
是「CPU 路径 + 后处理」，**而我们的瓶颈根本不在这两处**（DML 已 5.4 ms、NMS 是毫秒级）；
"用最新训练方式**重训**旧模型"更不改变推理开销——同一结构 = 同一 FLOPs，训练方式只影响精度。
**要省开销只能动**：架构尺寸 / 量化 / 输入尺寸 / 推理次数 / 执行 provider。

> 顺带一句（不属本实验）：维护者指出"游戏是立体的"——对，本作是 3D 渲染，"路面近似平面"只是
> 说行车交互面在固定相机下可标定。垂直维度真实存在（跳台、浮空金币、桥面），但决策要用到的
> 垂直信息是"**这东西是不是跳台 / 该不该飞**"，那是**分类**问题——旧模型的 `bonus_car` 类
> 就在做这件事（只是把跳台/磁暴合并了）。故垂直维度的正解更可能是**补类别**，而不是整幅深度图。

## 预训练单目深度「伪遥测 lite」可行性（2026-09-23，维护者提案驱动）

WorldObservation 信息面（护栏语义=R2 门④、地面切分、目标远近序）？判据四项：
切分对不对（①）、稳不稳（②）、序对不对（③）、贵不贵（④）。

**方法**：`probe_depth.py`。候选 = onnx-community 官方转换的 Depth Anything V2

**读数**（DA-V2-Small@518，RTX 4060 Laptop（注册表伪装 1050 Ti）/ DirectML，机器专属口径）：

## 性能尸检（2026-09-23，维护者/GPT 质疑驱动）

**问**：small@280=99ms 是"模型贵"还是"实现慢"？

**证据**（一次性 bench：p50/p95、25 迭代、纯 `session.run`，无预处理无可视化）：

1. **99ms 确为纯推理**——`lat` 模式计时只包 `session.run`，"可视化混入"嫌疑排除。
2. **DML 落在真实 4060 上**：bench 期间 nvidia-smi 时钟 390→2370MHz、功耗 10→32W；
   但**利用率仅 20–35%** → 非算力受限，GPU 在等主机侧（等谁见下节尸检）。
3. **非适配器错选**：device_id 0–3 全部 ~100ms 同速；id 4/5 枚举即败（名称编码
   异常，为虚拟显示适配器）。
4. **DML 侧无免费午餐**：`dml_gpu_device_filter=1`（禁 WARP）→ 164ms；
   `dml_execution_mode=1`（graph capture）→ 163ms；fp16 权重导出 → 139ms（I/O 仍
   fp32，纯 cast 开销）。默认配置已是 DML 最优档。
5. 前节 @336=260ms 非单调为 5 迭代噪声；25 迭代复测曲线单调：
   **280=110ms / 392=204ms / 518=355ms**（p95−p50 <5%，稳定）。

**本节边界**：以上只排除了「算力不足 / 适配器错选 / DML 配置欠优化」三类，**未回答
「慢在哪一环」**——主机侧占比与时延构成见下节实测（结论：单个 CPU 回退算子占六成
以上）。注意：**生产包可分发的执行栈就是 DML**（A/I/N 兼容），CUDA 上限只有次要决策价值。

**复跑**（.venv Python，仓库根）：

```bash

python $P infer --model small --set bad && python $P infer --model small --set ctrl \
  && python $P infer --model small --set stab
python $P stats --model small && python $P sheet --model small && python $P lat
```

## 时延构成尸检：单个 CPU 回退算子（2026-09-23，性能尸检续）

**问**：上节的"实现慢"慢在哪一环——EP 图切分？CPU 回退？拷贝？top-k 算子？

**方法**：ORT 自带 profiler（`SessionOptions.enable_profiling`）取 **node 级 provider
归属与耗时**；图结构用**自写最小 protobuf 解析器**读（本仓 `.venv` 无 `onnx` 包，
不为一次性尸检引入新依赖）。纯 `session.run`、13 次/档、短边定长，与 `lat` 同口径。

**口径（关键）**：每次推理以 profiler 的 `model_run` 会话事件切段，**剔除 run0**——它
含 DML 内核首次编译（该次 DML 节点累计 207 ms），并入均值会把 DML 列抬高近三倍。
稳态三列相加 = wall（误差 <1%）。

**读数**（DA-V2-Small，4060 Laptop / ORT 1.24.4 / DirectML）：

| 输入档 | wall p50 | CPU 累计（其中 cubic Resize） | DML 节点累计 | GPU 空档 |
|---|---|---|---|---|
| 28×42（6 token） | 17.4 ms | 2.8 ms（1.0） | 9.6 ms | 4.8 ms |
| 56×98（28 token） | 20.9 ms | 6.3 ms（4.6） | 9.5 ms | 5.3 ms |
| 280×490（700 token） | 108.2 ms | 74.9 ms（**73.2**） | 8.8 ms | 24.6 ms |
| 392×686（1372 token） | 224.5 ms | 152.0 ms（**150.2**） | 10.6 ms | 60.5 ms |
| 518×910（2405 token） | 390.5 ms | 249.6 ms（**247.5**） | 11.0 ms | 130.2 ms |

**三列各是什么（不可混算）**：
1. **CPU 累计**＝CPU EP 节点耗时之和。同步执行、阻塞调用线程，**可与 wall 直接相减**；
   除 cubic Resize 外只剩 1.7–2.0 ms（标量形状计算）。
2. **DML 节点累计 8.8–11.0 ms，6 → 2405 token 只涨 1.4 ms**——它是**逐节点派发开销**
   （约 421 节点/次），**不是 GPU 实算**，故"DA 在 DML 上很快/很慢"不能由这一列得出。
3. **GPU 空档**＝wall − CPU − DML，即主机侧无事件、在等 GPU 的时间；**它才是随规模增长
   的算力部分**：4.8 → 24.6 → 60.5 → 130.2 ms。

**根因链**：图里唯一一个 `mode=cubic` 的 `Resize`（其余五个 Resize 均为 `mode=linear`）
→ **DirectML 的 resample 只支持 nearest / linear，DML EP 整体拒绝该节点** → 落到
CPUExecutionProvider → ORT 的 CPU 三次插值路径约 270–360 ns/输出元素（未向量化），
且它在**关键路径**上（位置编码须先加到 token 上才能进主干，无法与 GPU 重叠）。

**该节点的身份**：输入是 initializer `/Transpose_output_0`，dims `[1,384,37,37]`
（37 = √1369，即 DINOv2-S/14 在 518² 下的 patch 网格）＝被常量折叠的 pos_embed 经
reshape+permute；输出按实际输入 patch 网格插值。**即 `interpolate_pos_encoding`。
它是输入形状的纯函数，与帧内容无关——可离线预计算为常量。**

**同时解释了尸检的两个反常读数**：① "GPU 利用率仅 20–35%"＝GPU 在等这个 CPU 算子；
② "曲线近似线性于 token 数"＝该算子成本正比于输出网格。

**去掉该算子后的时延（残差估计）**：它同步阻塞在调用线程上，故 **wall − cubic** =
@280 **35.0 ms** / @392 **74.3 ms** / @518 **143.0 ms**。**该估计已由下节的实测取代**
（26.1 / 72.5 / 167.9 ms）——**残差法可判断量级，不可作承诺**。

**本图的固定开销地板（动态 shape / 未融合口径）**：即使退化到 6 token 的输入，wall 仍有
17.4 ms（DML 派发 9.6 + 空档 4.8 + CPU 2.8）。**这个地板本身也来自动态 shape**——固定
shape 后 DML 会把整图融合成单节点，派发开销随之消失（见下节实测：地板降到 2.6 ms）。

## 折叠验证：常量折叠路线的实测（2026-09-23，尸检续）

**问**：上节推出的「去掉该算子后 @280 ≈ 35 ms」是否成立？能否**不动权重文件**达成？

**方法**：ORT 的 **free-dimension override**（`SessionOptions.add_free_dimension_override_by_name`）
把 `batch_size`/`height`/`width` 固定成编译期常量。固定后该 Resize 的两个输入（常量
pos_embed 与由 Shape 链算出的 sizes）都成为常量 → 触发 ORT 的常量折叠。**零图手术、
零新依赖、权重文件不变。**

**读数**（真帧 `20260922_113724_p1/000100.jpg`，同 4060/DML；A/B **交错**测量抵消漂移）：

| 档 | A 基线 p50/p95 | B 折叠 p50/p95 | 加速 | max 绝对差 | 输出量程 | 相对差 |
|---|---|---|---|---|---|---|
| 280（700 token） | 107.2 / 108.5 ms | **26.1 / 26.9 ms** | 4.1× | 1.8e-05 | 6.18 | 2.9e-06 |
| 336（1008 token） | 250.5 / 251.7 ms | **39.8 / 40.7 ms** | 6.3× | 2.5e-05 | 6.87 | 3.6e-06 |
| 392（1372 token） | 213.1 / 218.9 ms | **72.5 / 75.0 ms** | 2.9× | 2.2e-05 | 7.29 | 2.9e-06 |

### 合成自检：结构性盲区与 θ 的位置污染（`selftest`）

  低于任何 θ。**这是结构不是数据**：θ 调到多低都检不到墙脚。

## 消失点的可辨识性：深度能给行、给不了列（2026-09-23，维护者提问驱动）

**问**：射线写法为什么非得靠"边界候选点"？能不能直接从深度趋势拟合消失点？

**列（横向）不可辨识，是结构不是方法**。平地面 + 针孔相机：y − Y_H = fH/Z 且
d = α/Z + β（DA 出的是相对视差，α/β 未知），合并得

> **d = α·(y − Y_H)/(fH) + β —— 只依赖行，与横向位置 x 无关。**

⇒ 任意消失点横坐标都产生**同一张地面视差场**，拟合再细也问不出 x。实证就在本节自己的
读数里：g(y) 对行的线性相关 **0.9977**、残差占量程 **0.2%**——"地面视差几乎是纯行的
函数"这一拟合得极好的事实，正是"该场不含横向信息"的定义。那 0.2% 残差不预留可挖的横向。

**行可辨识，且已经拿到**：g(y) 零点 = 深度模型自己的地平线行（连续段内 std 1.4px）。
它比冻结值准——`gate0.json` 的 Y_H=324.2 系统性偏 **−18.3px**，全批仅 14/140 帧落在 ±10px 内。
注：该零点混有 DPT 头仿射 offset，是"模型的地平线"而非相机地平线；几何既建在该模型上，
锚点就该取它，**不与 2D 车道线层共用 `gate0.json` 常数**（两个对象、两个真源）。

**列的估计器生产侧早已存在，本探针此前用错了东西**：`boundary.py` schema 2 输出逐帧
`vp_x`（左右两条边线交点列，`sides==2` 才给数，曲率主导的假交点不给数），且其相对校准
vpx 的横偏 ∝ 车头航向角（航向观测量，非误差）。探针全程用的是 38 场**总中位** 640.7
⇒ 上节"冻结 VP 只覆盖一成五帧"里，有一半是本接线缺陷造成的。

**现成 vp_x 的实测覆盖率（18 个 trace、14129 帧）**：有值 **2656 帧 = 18.8%**，
按场次 0.7%～60.7% 极不均（真机常单侧黄线可见，见 `boundary.py` 单侧容忍注记）；
有值时 |vp_x − 640.7| 中位 113px、p90 362px——**这是航向信号不是估计误差**，
不得当作"估计器不准"的证据（口径与 `gate0.json` 注记的"场内 MAD 12–19px"不同：
那是场内散布，这是相对总中位的横偏）。

⇒ **决策一由此改写**：真问题不是"射线写法 A vs B"（两边都缺同一个输入），而是
**横向参考用哪一层、各覆盖多少、冲突时信谁**——2D 黄线层（现成、覆盖 19%、
隧道/夜间/雨天黄线褪色属未验证域）与深度墙脚（不依赖黄线可见性，但须先剔车底污染）
是**互补候选**，不是替代关系。

### 已定：台阶看得见，且门的正确归一是**相对量**（`kerb`，2026-09-23 当日结案）

上一节的三条候选解释定死为 **③ 我的定位不可信 + 测错了边**，"约 2cm / 深度看不见"
那条读数**撤回**。维护者指认边界是黄线外侧的矮路缘（暗带=其前立面、亮面=人行道顶面），
按亮度分带直接测顶面的台阶比 h/H = (M−g)/g：

| 帧 | h/H 逐行（y=520→680） | 跨行中位 | 极差 |
|---|---|---|---|
| 1340 | .043 .040 .044 .048 .049 | **+0.045** | **0.008 ⇒ 恒定，真水平抬升面** |
| 1280 | .053 .055 .063 .063 (−.003) | +0.055 | 末行为孤立 32px 误带，剔除后极差 0.010 |

排除自车带（scan 宽度收到 440px）后 1340 读数不变 ⇒ 亮面未被白车身污染。
立面（暗带）h/H 仅 +0.009~+0.031 且乱 ⇒ **信号源是顶面**，与几何一致。

但门该用相对量）。按 RULES 纪律保持比值口径，不换算成米。

### 门定多细：连续段噪声底给出可计算答案（`noise`，2026-09-23）

维护者指出两件事，都成立并已实测：① **绝对亮度/颜色阈值跨侧不可迁移**——同一帧左侧
人行道顶面亮度分位 50/90 = **143/160**，右侧同位置 = **63/86**，`L>130` 在右侧只占
0~7%（光照与反照率不同）。故 `kerb` 的亮度分带只是**一次性诊断**（回答"深度看不看得见
台阶"），不得进生产；同一批评也适用于黄线层本身（绝对颜色阈值，R2 已声明褪色属未验证域）。
② 稳定连续段的正确用途是**测噪声底**，从而让"门开多细"变成可计算量，不需要任何标注。

相邻帧（31 帧 / 1.5s，`noise`）：

| 区域 | 时间 σ（跨帧） | 空间 σ（帧内） |
|---|---|---|
| 路面（真值应为 0） | **0.0039** | 0.0143 |
| 人行道顶面 | 0.0107 | 0.0239 |

⇒ 台阶读数 h/H=0.045 相对**自身**时间噪声 **4.2σ**、相对路面地板 11σ ⇒ 可检，且余量不大。
⇒ **门的取值：1.5~2%（相对量 (M−g)/g）**；低于约 1.2% 与噪声不可分，此前建议的 3% 偏保守，
15% 量程门则整整高了一个数量级（"台阶稀少"的来源）。
⇒ 一条硬限制：**空间 σ（每像素 1.4~2.4%）远大于时间 σ** ⇒ 单像素不可信，边界必须是
**区域级聚合判决**（数千像素取中位），不得逐像素定界。

**方法自纠**：首版用 19 帧跨 9 秒测得顶面时间 σ=0.026，是固定图像块随车移动**扫过不同
表面**灌进去的，不是传感器噪声；改相邻帧后降到 0.011。凡"跨帧稳定性"读数必须先问
**采样窗口内几何是否真的没变**。

### 逐行深度定边：三种规则全部失败，根因是缺跨行区域结构（`edges`，2026-09-23）

按维护者指示"不要奉旧记录数据为圭臬，自己抽帧看"，做了逐行并排图（青=HSV 黄线 run、
品红=深度边缘、黄绿=跨行连线），**三版规则各暴露一个缺陷，都是看图看出来的、不是看数看出来的**：

| 规则 | 结果 | 看图发现的根因 |
|---|---|---|
| ① 从 x=640 向外走，首个持续超门处 | 差 94~332px | **扫描带下半段就是自车尾翼/车顶**，第一下撞自车轮廓（连线画在车周围） |
| ② 同上 + 先剔自车列段 | 差 50~122px | **路上任何近物都劫持**：前车、货车、金币、坡道结构——"第一个更近的东西"根本不是路边缘 |
| ③ 从画面边缘向内走，"近区终止"处 | 检出数崩到 1~34 行、差 209~571px | 远带行画面边是**天空/远处建筑（比路面更远）**，入口判据即失败；且该规则也不排除宽于 hold 的内部物体 |

⇒ **结构性结论**：路边缘的判别力不在"某一行上哪里变近"，而在**跨行的连续性**——
边缘是一条贯穿多行、朝消失方向收敛的线，而车/金币是行跨度有限的团块。这正是 HSV 层
用"聚类 + 路宽配对"在做的事，也是本节"空间 σ ≫ 时间 σ ⇒ 必须区域级聚合"那条结论的
具体失败形态。**逐行阈值行走不通，不再试第四种。**

⇒ 下一步（`edges` 之后要做的前型）：把深度边缘做成**区域**——取"与画面侧边相连、
且跨 ≥N 行持续"的近区连通块，再对其拟合；拟合形式按可辨识性结论取
**逐帧地平线行为锚、横向不绑冻结 VPX**。做完直接回答那张该回答的表：
**在 HSV 已知会塌的弯道帧上（`bnd_residual` 中位 1.27 vs 直道 0.53），深度是否真的更好。**

**待维护者答的一条事实**（决定 ③ 类规则能否复活）：画面最外侧那一横条，是否**永远**在路面
之外？若存在宽路肩/停车带这类"线外仍是可行路面"的路段，则"从外向内找近区终止"在那些
场景是**正确地失败**，规则必须换。

### 跨帧抖动（jit 定义复核）

记录表的 jit=0% 是**帧内相邻检测列的行差**——按列 argmax、相邻列常落同一行，
0% 是构造必然，**不能当 P3**。真跨帧量在唯一连续段（100..140，41 帧）上测：

| 变体 θ | 侧 | 识别帧 | 射线角 1 阶 std | 2 阶 std |
|---|---|---|---|---|
| rel 0.06 | 右 | 41/41 | 0.14° | 0.24° |
| rel 0.06 | 左 | 29/41 | 0.15° | 0.25° |
| mask 0.06 | 右 | 41/41 | 1.08° | 1.84° |
| mask 0.06 | 左 | 5/41 | 0.57° | 0.96° |

2 阶差分去掉匀速运动后才是抖动：rel ≈0.24°（近场约 1.5px）、mask ≈1.84°（抖 7 倍）。
⇒ mask 召回高但位置稳度差、rel 反之——第一关要的是**掩码下沿定位 + 时序平滑**的组合，
不是二选一。141 帧里真连续帧对只有这 40 对，P3/P5 的其余形态仍需补录。

**判定：预验证通过，但通过的方式变了**——台阶可检（墙读作更近、抬升面定位无偏、
静默错误类缺席），而"检不出"的锅在**检测器的定位方式**（窗对比度对墙结构性失明、
mask 位置被 θ 污染）与**候选点集不干净**（车底缘与 UI 混入），不在阈值、不在遮挡、
不在模型选型。金标投入成立，且第一关的正设计起点据此改写：
① 定位用非地面区下沿、θ 仅作验证（钉 0.06 保召回）；② 几何锚点的**行**取逐帧 g(y)
零点（连续段内 std 1.4px，可用）、**列**不得沿用冻结 VPX（逐帧估或放弃 VP 约束）；
③ 车底缘与墙基的分离用射线几何（沿/跨射线），不靠提高阈值；④ 时序平滑为必需项；
⑤ 输入侧需要"是否行驶画面"哨兵（结算界面会被判成非地面）。

**遗留到第一关**：① 候选点先剔车底再重判 VP 前提（决策一在此前不作）；② VP 列的可靠
估计器，或放弃射线约束改拟一般线；③ 金标帧同时标注障碍物存在性；④ 弱路缘（抬升路缘类）
的对比度分布按金标量化（门降到 2~5% 后路缘几乎每帧都在，此前"仅 23 帧"作废）；
⑤ C3 贴墙帧（20 帧，含 1 帧结算界面）
的处置——墙脚在画面外时是否直接判"不可越界"而不走检测。

## A 方案联合覆盖：黄线锚定 + 深度台阶验证（`verify`，2026-09-23，维护者裁定 A）

## 金标规模与统计口径（2026-09-23，第一关投入前定死，免得事后挑口径）

## A 实验：CNN 结构深度模型 × DML（2026-09-23，维护者批准，边界锁死）

**唯一问题**：Windows 通用 GPU 执行栈（ORT-DML，生产可分发口径）下，结构更适合实时的
轻量深度模型能否进逐帧预算（66ms）。对照物是 DA-V2-Small（同帧集、同口径、同机）。

**素材（零训练零导出）**：Ultralytics 官方 release v8.4.0 直接发布 `yolo26n/s-depth.onnx`
（GitHub 一手核实存在，元数据 `task=depth, head=Depth` 确认深度模型非名推断；AGPL-3.0
与现生产 model.onnx 同规；**原生输入固定 768×768**，dynamic=False——低分辨率档需重导出，
但 768 档已进预算，未做）。torch+ultralytics 一次性 venv 建毕即删（官方 ONNX 使导出路线
作废）。预处理混淆排除：letterbox vs 拉伸 resize 目视无差（三联图 `lb_vs_st_*`）。

**读数**（30 迭代、warmup 3、纯 `session.run`、同 4060 同 DML 口径；输出为 log 距离
"大=远"，指标换算 1/d 成视差与 DA 同向）：

| 模型 | DML p50/p95 | ②稳定 IoU | ③序一致  | 质量目视（12 格拼图） |
|---|---|---|---|---|
| yolo26n-depth@768 | **9.4 / 11.9ms** | 0.920 (p10 0.871) | 1.000 (n=7) | 序/稳定过线；**墙基-路面边界模糊**（DA 的蓝色楔形不重现），远带小车弱，自车=矩形章 |
| yolo26s-depth@768 | **11.6 / 12.1ms** | 0.942 (p10 0.904) | 1.000 (n=7) | 与 n 无可见差——**家族差异，非尺寸差异** |
| （对照）DA-V2-Small@280 | 98.2 / 166.5ms | 0.968 (p10 0.827) | 1.000 (n=7) | 墙基楔形/大车团块清晰 |
| （对照）DA-V2-Small@768² 等像素 | ~350ms(@518 档) | — | — | — |

**四问四答**：
1. DML 纯推理 p50/p95 = **9.4/11.9ms（n）与 11.6/12.1ms（s）**@768 原生。
2. 与 DA-V2 同口径差 = **约 10× 且输入像素多 4.3×**。**该差不能归因于 ViT 算子形态**：
   上节尸检把 DA 的时延定位到单个 CPU 回退的 cubic Resize（占六成以上），DA 的 DML
   侧逐节点派发累计仅 8.8–11.0 ms；yolo26 无位置编码插值这一步，故无此回退。
   **执行侧的真实约束是"图里有没有 DML 不支持的算子"，不是"CNN 还是 Transformer"。**
3. 质量最低要求 = **部分达标**：近远序、时序稳定过线；**R2 主消费者（墙基判别）不达标**
   ——边界模糊恰是 DA 强项。①黄-地残差指标跨模型不可迁移（1/d 非线性），如实弃用。
4. 是否继续研究逐帧深度通道 = **延迟侧已成立**（深度+检测 ≈15ms ≈ 预算 23%），
   **瓶颈从执行后端转移到模型质量**；n→s 不解决，CUDA-B 实验降级为次要（只答 NVIDIA
   上限，不改"家族差异"结论）。下一变量（不锁家族）：**"实时友好的计算结构 ×
   R2 所需空间判别"是否存在**——表征形态（分割/边界直出/其他）开放。

## R2 消费者需求审查（2026-09-23，A 实验后续——维护者裁：先定义真需求，不模型考古）

**审查推导（从消费链，非从模型能力）**：`detect_boundary` 的契约是
`validity` 一票否决 + `road_offset` 喂闭环（boundary.py:128-129、module.py:626-627）。
R2 的失败是"墙基被配成路缘"，故它对视觉层的真问题 = 对**已选黄线簇**问一句
"你在路面上还是墙面上"——**簇尺度的序数对比**（墙面像素系统性比该行地面更近）。
关键：边缘位置由颜色层给（黄像素 x_lane 即位置），**不需要深度重画边界**——
yolo26n"边界模糊"打在 R2 不消费的量上。所以需求定档 =
**"地面/非地面局部对比 + 时序稳定"，不是"高质量深度图/精细边界恢复"**。

**分支检验**（现有资产直接测，零新依赖）：复刻 v2 选择器取配对簇（≥20 像素），

vs 对照。视差统一大=近（yolo 输出 log 距离经 1/d 换算）。

| 模型 | 坏簇 p50/p90 | 控簇 p50/p90 | AUC |

| yolo26s@768 | +0.132 / +0.465 | +0.063 / +0.210 | 0.634 |

1. **需求分支判定：粗序数对比即可**——DA 控簇残差≈0（真路缘在面上）、坏簇系统性
   偏正（墙在面上方），正是判别器要的形状；不需要精细边界。
2. **DA 过质量线、yolo26n/s 不过**：yolo 系控簇也偏正 +0.063（模糊场把墙面抹进

   家族性）。
3. **诚实边界**：AUC 0.786 ≠ 门控就绪——badframes 标签混有非墙基污染物（白虚线簇

4. **下一变量由此收紧（不锁家族）**：问题不是"找更快的 DA"也不是"找更准的 CNN 深度"，

   16.4ms）——约束是"~10ms 级纯推理"，不是"CNN"。

## 道路范围替代测试（2026-09-23，维护者关键事实修正驱动）

**背景修正（差分证据，非临时起意）**：黄线检测的**本意**即"离墙多远/道路范围"，
而这条路线两代都工作得不好——旧 racing 从未让标线当闭环燃料（`_detect_lane` 只
单边返回、标线丢失是常态需 `wall_memory` 兜底、防撞独立三区体系；坑点表 HSV 阴影
调参史与本作同剧本），本作 v1/v2 让黄线喂 road_offset 后直接产出 R2。机制解释：
黄线=细 1D 结构+颜色歧义（车道线/墙基/反光同色系），路面=2D 连通区域——**区域
比线可检**。据此，上一节"分割边界偏离黄线 0.42 车道即否决"用错了尺：偏离一个
反复失效的 incumbent 不构成否决，**正确的尺 = 判死 HSV 的物理性检验**。

**测试**：road mask（cls==6）逐行最左/最右像素 → x_lane → 路中心/路宽；
扫描带同 v2（y_h+30~+230，步 4）。判决量 = |中心| 越 2.4 车道物理界的比例
（HSV 在坏帧上冲到 2.8 的那把尺）+ 相邻帧中心抖动 + 对照帧符号偏置。

| 读数 | 结果 | 对照 HSV 病灶 |
|---|---|---|
| 72 坏帧（全部为 HSV 出过假值的现场） | \|中心\| p50=1.02 / p90=1.69 / **max=1.82**，**越界率 0%** | HSV 同批帧 max 2.8（物理不可能） |
| 稳定窗 41 帧 | 相邻帧 \|Δ中心\| p50=**0.007** / p95=0.095 / max=0.113 车道 | HSV"醉驾"=大跳 |
| 对照 31 帧 | 带符号中心 p50=−0.03（无系统偏置） | — |
| 路宽 | mask 宽 p50=3.12 车道 | 名义 4 车道——差值待归因（a_x ~18% 标度误差可解释 4.0→3.3，或路肩归属；未决） |

**判读**：现成 road mask 在**判别**（AUC 0.874）与**道路范围**（物理性+稳定性全过）
两个角色上同时通过 incumbent 死掉的测试。方案 B（RGB→语义→道路边界，黄线链降级
为验证器/可弃）自此有实测支撑，不再是设想。
**〔修正：本节"道路范围过线"只过了物理性尺——下节 a 实验 ⑤ 以叠图裁决发现 mask
中心有系统性右偏（本作右侧宽路肩被纳入、左侧无），范围角色不成立。最终判决
（判别器 ✓ / 尺子 ✗、黄线位置 × mask 语义的组合架构）以 a 节为准。〕**

**未决（进生产判决链前必须答）**：① 路宽口径 3.12 vs 4.0 归因；② mask 含路肩的
语义与 RULES"路肩不额外占宽"是否冲突（路肩可驶性无 RULES 条目）；③ 黄昏/雨景
覆盖仅坏帧样本，留出集未跑；④ 许可未审；⑤ 方向正确性（offset 指向远离墙侧）
无逐帧真值，仅由物理性+无偏间接支持。

## a 实验：完整离线判决链（2026-09-23，维护者批准，三段分离记录）

**方法**：①范围=前节已测；②归属=坏/控帧黄线簇落在 road mask 内的占比（硬版）；
③闭环=mask 边线喂**真实** `_EgoRoadObserver`（import 生产类，不复刻）；⑤符号=24 帧
盲标基准（先标后算）+ 双传感器互比 + 叠图目视裁决。**盲标为人工判读，非机检判据。**

**读数**：
- ② 簇在 mask 内占比：坏 p50=**0.10** vs 控 p50=**1.00**——硬版归属判别近乎干净。
- ③ 65 坏帧：observer 拒绝 26（护栏 fail-closed 生效）；通过的 39 帧 |offset|
  p50=0.62 / max=1.26，无越界；但**包含性仅 44/65**——1/3 黄昏坏帧自车不在 mask 路面内。
- ⑤ **不过，且抓到系统性缺陷**：mask 中心 vs 盲标仅 4/18（盲标本身有缩略图误判，
  已弃为裁决依据）；决定性证据是叠图（`overlay_*_212.jpg`）——**本作右侧有宽灰色
  路肩、左侧没有**，mask 右缘推到墙基而左缘贴黄线 → mask 中心系统性右偏 ~+0.5
  车道。当居中燃料会把车往右墙带：物理性合格 ≠ 方向正确。
- ⑤ 附带发现：生产黄心与 mask 心在 94% 帧互差 >0.3 车道、生产黄心在相邻帧间
  ±3 车道乱跳——incumbent 的 center 输出同样不可信（与 R2 同源），两传感器互证失败。

**判决修正（覆盖前节"方案 B 有实测支撑"的过强表述）**：
1. mask 的能力边界由数据划出：**判别器/验证器 ✓（②近乎干净），尺子 ✗（方向性
   偏差 + 路肩语义）**。"road mask 直接替代黄线链产出 road_offset"不成立。
2. 收敛架构（零新训练）：**黄线给位置、mask 给语义**——mask 用于验证黄线配对
   （簇的地面性/外侧证据，替代逐缘质量门里颜色+几何做不到的部分），配对通过才喂
   observer。黄线留任尺子的理由不再是"它准"（⑤证明它也不准），而是"位置精度上
   没有替代品，且它的错误恰是 mask 能抓的"。
3. 黄昏包含性 44/65 与路肩语义是现成模型的两个真实缺口——**b（微调）的靶子由此
   具体化**：标注口径 = "驾驶边界"（黄线为界）而非"材质路面"。是否启动 b 待裁。
4. 实时性口径收敛（维护者刹车）：现有证据 = "SegFormer-b0 在当前机器、当前 DML、
   当前输入设置下满足逐帧预算"，**不是**"15MB/16ms 是问题的充分条件"——生产价值
   由模型×输入×场景×后处理×闭环共同决定，后四者多数未过。

## A2-0 误差结构 / 可纠正性：yolo26n ↔ DA-S（2026-09-23，维护者裁决"先验证锚定为什么能修，再谈融合"）

**问题**：yolo26n 相对 DA-S 的误差是 A 型（全局尺度/偏移——低频锚定可修）还是
B 型（局部结构/秩错误——锚定救不了）？答不出这个，"yolo 高频 + DA 低频锚定"就
没有立项依据。全部为缓存图上的离线分析，不建融合、不改生产
（[`probe_a2_correctability.py`](probe_a2_correctability.py)；锚定仿真 = 每帧拟合
仿射参数再按 N 帧冻结沿用，非真融合）。

**① M1 尾部重算（修正矩阵读数）**：矩阵 yolo26n "p10=−1.00" 在读数③同口径下
**不复现**（临时脚本已清，无法归因）。干净重算（255 帧全 union，框坐标夹紧图界
——出画框 x1<0 会被 numpy 负索引回绕成空切片，旧读数对此敏感）：≥3 框 6 帧，
两模型全部 ρ=1.00；≥2 框 50 帧，yolo26n 6% 的双车帧序反 vs DA-S 4%。struct 侧
按分离度过滤后（|Δ深度|>5% 路面量程，n=39 对）**0% 错序**——全部倒置发生在两车
深度差 <5% 路面量程的贴身对里。结论：**方向性风险降级为贴身近 tie 的不确定性**，
幅度小、且参照系 DA-S 自己也有 4%。

**② 误差结构分解（bad+ctrl 103 帧，地面轮廓域，帧内 p1-p99 归一空间）**：
z→伪视差三个单调变换族里 1/z 最优（中位 R² 0.989，exp(−z) 0.876、−z 0.648）——
给锚定"最有利变换"的宽容界，秩指标不受族选择影响：

| 读数 | 数值 | 含义 |
|---|---|---|
| A 型：全局仿射 R² | p50 **0.989** / p10 0.960 | 归一后单一尺度+偏移解释 98.9% 方差 |
| A 型：仿射校正 nRMSE 降幅 | p50 **90%** | 值域误差几乎全是全局标定问题 |
| 秩结构 Kendall τ | p50 0.998 / p10 0.942，τ<0 帧 **0 个** | 无系统性局部倒置 |
| B 型：轮廓分离点对序错 | θ=5%: 1.11% → θ=20%: **0.69%** | 随分离度增大而**降**＝细尺度噪声特征，非结构错误 |
| B 型：他车框分离对序错 | θ≥5% 全部 **0%** | 分离足够的车不会排错序 |

**判定：A 型压倒性主导，B 型只剩 ~1% 且集中在贴身对——锚定救不了的那部分很小。**

**③ 低频锚定保持性仿真（连续 161 帧窗，族=1/z）**：

| 项 | 读数 |
|---|---|
| 锚参 a（斜率） | p5-p95 = 0.861~0.934（中位 0.884），**逐帧相对跳变 p50 1.6% / p95 5.2%** |
| 跨帧框漂移 \|Δv\|/路面量程（n=80 匹配） | DA 本底 0.0103/0.0905；yolo 裸奔 0.0250/0.1043；**逐帧锚 0.0221/0.0916；冻结 N=41 帧 0.0219/0.0931** |
| 锚频等价性 | **N=41 ≈ N=11 ≈ 逐帧锚**——锚参慢到 2 秒刷一次与每帧刷同效 |
| 锚频摊销（435/N + 检测 5.4 + yolo 11，预算 66ms）〔**已失效**：折叠实测后 DA-S@280 逐帧 26.1 ms 全额可负担（30fps 预算内），无需摊销——下行数值仅作 y26n 误差结构证据的历史口径保留〕 | N=41 → 27.0 ms/帧；N=11 → 55.9；N=5 → 103.4 |

**④ 融合能买到什么、买不到什么（给 A2 立项裁决）**：
- **买到：绝对标定。** 仿射校正把值域误差砍 90%（A 型主导），即 yolo26n 的深度
  值经 DA 低频校准后可当"准过标定的相对深度"用——这是 A1 秩类指标测不到的收益。
- **买不到：逐帧噪声。** 框漂移只降 ~12%（0.0250→0.0219），残余是框内中位的逐帧
  抖动，属时间平滑（EMA/滑窗）的职责，不是锚定的——两件事、两层机制，别指望
  一层修两样。
- **不改变：贴身对不确定性。** <5% 路面量程的双车近 tie 两模型都不可靠，消费者
  侧（C 层）需自带"近 tie 不决策"的余量。
- 维护者验收口径下的剩余短板：遮挡识别未测（B 层留白）。
- **A2 剩余（2026-09-23 重估）**：融合原型不再待批——DA-S 逐帧进预算后锚定调度失去
  预算理由，本节结论转为 yolo26n 误差结构证据；视频深度与光流同批降级（见 Pareto
  读数 3）。
