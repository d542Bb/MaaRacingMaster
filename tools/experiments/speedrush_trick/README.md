# speedrush 极限动作触发反查（C 类实验，2026-09-18）

status: active

> 用逐帧事件时钟把每次超车与得分事件配对，再测"升级为极限"与"只是普通超车"在框级特征上能否分离。
> 这是收益模型（`docs/plan/speedrush-control-route.md` 阶段 C）与感知输入规格（阶段 B）的**前置事实**。

> 本文只提供实测证据供其回填复核）；不是控制方案。

## 要回答什么（判据先写死）

上一轮把方向定成"贴车刷分"（贴近社会车触发极限动作，120 分/次），但**"贴近"是我从面额推出来的假设，
不是测出来的触发条件**。本文把它当待验证假设，先定判据再看数：

1. **每次超车是否都产生得分事件**？若是，"要不要超"就不是决策，决策只剩"怎么超才升级成极限"。
2. **极限超车 vs 普通超车，在框级特征上能否分离**——
   分离 → "贴车"有可观测的决策量，感知规格据此定；
   不分离 → 要么触发条件不是贴近（回到 `RULES.md` §7#2 的"速度差/被超车型"分支），要么现有感知看不见它。

## 方法：把事件时钟从 0.5 s 换成逐帧

**关键改进**（这也是本文与上一轮配对验证的分水岭）：比分显示每 0.5 s 一跳，作事件时刻有 ±0.5 s 模糊——
上一轮个体配对"不成立"很大程度是这个模糊造成的。HUD 左上「极限超车 ×N」连击计数器的**翻转帧**
是**逐帧**（21 fps ≈ 48 ms）时钟，故本文：

- **标签通道 = banner 翻转**（全帧 OCR `event_banner` 区，解析连击数与"超车/变道"类型）；
- **候选触发单元 = 超车 pass**：全帧跑旧检测模型（[`speedrush_vision/probe_old_model.py`](../speedrush_vision/probe_old_model.py)
  同口径），贪心最近邻跟踪街车框，"由远及近、终点贴近画面下部（被自车超过后出画/遮挡）"的轨迹 = 一次超车；
- **配对窗口** `pass 结束 ∈ [翻转−0.8, 翻转+0.4]`（实测翻转滞后超车完成约 0.3 s）；
- **兜底/交叉验证 = 比分跳**：未配到极限翻转的 pass，看它是否落在 k=1~3 的比分跳上（30 分档 = 普通超车）。

三通道（比分 / banner / 检测）各自缓存于 `%TEMP%/sr_trick/`，换会话名即复用。**标尺独立性**：
事件时钟来自画面 OCR，超车来自检测框，两者独立；分离度用**置换零模型**（打乱极限/普通标签 2000 次）
给 p 值，不靠"看起来分得开"。

## 结论

### ① 每次超车都得分，约 55~60% 升级为极限（三场 138 s 合并，39 个 pass）

| 会话 | pass | 极限翻转（配到 pass） | k≥4 比分跳 | 未配极限的 pass 中落在 30 分档 |
|---|---|---|---|---|
| 220750_p2 | 22 | 16（12） | 21 | 7 / 10 |
| 220453_p1 | 9 | 7（5） | 8 | 4 / 4 |
| 200445_p1 | 8 | 8（5） | 11 | 2 / 3 |
| **合计** | **39** | **31（22）** | **40** | **13 / 17** |

**39 个超车 pass：22 个配到极限翻转（120 分），13 个落在 30 分档（普通超车），4 个两者都不挨着。**
即"超车"这个动作本身**必得分**（120 或 30），区别只在**升级与否**。
→ **"要不要超"不是决策点；决策点是"怎么超才升级成极限"**——与上一轮"感知要看车不是看币"同源，
但这里进一步收窄到"看**贴得多近**"。

（4 个未配对 pass 是跟踪碎片或翻转 OCR 漏读，量级 <11%，不影响比例结论。）

### ② 极限 vs 普通超车：横向贴近程度**不可分离**——首轮"可分离"结论是透视假象，已撤回

**撤回声明（2026-09-18 同日复核）**：本节初版报告 `min_gap`（最近接近时 |cx−640|）在极限/普通
两组间 AUC 0.226、置换 p=0.003，判"贴近可分离"。**该结论作废**，三条独立证据都指向它测的不是贴近：

1. **锚敏感性**：把 640 换成 600，AUC 塌回 0.50（p=0.98）；620→0.35、640→0.23、680→0.27。
   真"离自车近"的判据不该在挪 40 px 时整个消失——它跟着的是**消失点**，不是自车。
2. **min 取在远处**：min_gap 那一帧的 by 中位 **388**（框高仅 60 px，远在透视收敛区），
   而最近接近帧 by 中位 494、框高 144 px。`min` 系统性抓到的是"车还远、压在消失点附近"那一拍。
3. **车根本不从自车列穿过**：最近接近帧的 cx 分布**双峰**——极限组 [453,459,498,501, 757…1081]、
   普通组 [317…485, 784…1147]，**640 附近是空的**。超车都发生在左道（~470）或右道（~850），
   没有一辆"贴着自车中线"过。所谓"极限组 gap 更小"只是两组**左右道占比不同**的副产物。

**改用无透视偏置的判据后，贴近不可分离**：`gap_close`（最近接近帧横向差）AUC 0.39、p=0.25；
`dhdt`（速度差代理）AUC 0.50；`max_h` AUC 0.50——**全部无信号**。

### ②b 自车锚验证（撤回过程的副产品，是条硬事实）

初版把"gap 锚在画面中心非自车框"列为待修。实测**追车相机把自车钉死在画面中央**：
模板匹配与底带白块两种自建锚都不可信（前者锁护栏、后者 8% 命中且锁邻车），但**偏移最大的
6 帧逐一目视——绿线（640）全部穿过自车正中**，变道时车身横移 <40 px（82% 帧 |偏移|≤40）。
→ **640 本就是合格自车锚**，"以自车框重标"这个前提不成立；真正的坑是②里的透视收敛，与锚无关。

**判读**：`RULES.md` §4.2 的"横向间距足够小触发极限超车"**既未被证实也未被证伪**——
现有框级判据（原始像素横向差）测不到它，因为"横向间距"必须在**同一深度**上比，
而原始像素差被透视主导。要判这条，需要**透视归一的横向距离**（以消失点/地平线标定，
把 cx 差除以 1/(by−y_h)）——那是独立工程（planning 实验试过时间轴透视标定、未独立验证成功），
**不在本轮范围**（维护者指示：结果不可信即停）。

**顺带一条未解释的观测（不作结论）**：极限组最近接近 cx 明显偏右（18/22 >750），普通组左右对半。
可能是"右侧超车更常判极限"，也可能只是本局走线的巧合——样本 39、单局风格，**不足以立题**，
留作透视归一后第一件要重看的事。

### ②c 透视归一重测（2026-09-21，A1 尺子定档后的第一个下游判决）

**仪器**：`probe_trick_pxnear.py`（复用本实验 pass/配对；首轮 `track_passes` 同日增补保留
`pts` 逐帧点）。**预注册判据（跑前写死在仪器 docstring）**：观测量 = 近距帧域
（by>380，与首轮同域）归一最近横向间距
`ΔX = A_x·min |(cx−vpx)/(by−y_h) − (640−vpx)/(v_ego−y_h)|`；
主检验 v_ego=716 的 AUC+置换 p（2000 次、双侧、rng(3)）——p<0.05 ∧ AUC<0.5 ∧
敏感性档 v_ego=680 同向 → 分离成立。vpx/y_h 逐场取标定 Gate 0 缓存中位
（220750：vpx 638.9/y_h 324.2；220453：647.5/335.1；200445：644.8/326.1）。

**结果**：极限 22 / 普通 18——v_ego=716：中位 0.648 vs 0.812 车道，AUC 0.265，p=0.008；
v_ego=680：AUC 0.268，同向，p=0.008；极限组 q25/q75 = 0.63/0.72 车道。
（A_x=0.587 系标定冻结口径，只影响阈值数值，等比缩放不影响检验；真源 = 已归档的标定
实验「A1 定档轮」与 globalL 冻结裁定，溯源 [`db7a3fe`](https://github.com/d542Bb/MaaRacingMaster/commit/db7a3fe78973d9d155d350feac581d7530f5138a)。）→ **分离成立**。

**判读**：首轮撤回判的是「量法被透视污染」，本轮换量法重判——是对原问题的新定案，
不是翻撤回依据的烧饼；「贴得近」是**概率性信号而非二值开关**（AUC 0.265 ≈ 单对比
正确率 73%），阈值候选 ~0.7 车道。:92 的「极限组最近接近偏右」仍未解释，一并留档。

**残留**：阈值稳定性（n=40、三场、仅干景巡航直道，雨天/高速/弯道未覆盖）；
速度差要求未检验（本局全油门）。两条均维持 §7#2 `[实测·待复核]` 不升权威。

### ③ 对阶段 B/C 的输入规格（一句话）

**已定**：超车必得分（普通 30 / 极限 120），收益表主项 = 超车频次；事件时钟用 banner 连击翻转（逐帧）。
**已定（2026-09-21 重测更新）**：升级与否在**归一化横向距离**上有可观测信号（见②c）——
收益模型「升级概率」的输入量 = 与目标街车的归一最近横向间距（A1 尺子），可按贴近程度
条件化（阈值候选 ~0.7 车道、待稳定性复测前保留「超车即按期望面额 55%×120」作保底折算）。
**未定**：阈值稳定性与速度差要求（见②c 残留）。
