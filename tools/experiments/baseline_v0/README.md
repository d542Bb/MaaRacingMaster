# baseline_v0 — 固定协议的可比驾驶基线（活跃）

status: active

**问题（可证伪）**：同一版本、同一协议下，第二阶段得分与运行稳定性的
局间波动有多大？在这个波动量级没有测出来之前，不做任何版本比较。

**只读**：探针只读 `logs/<token>/trace/speedrush.jsonl` 与
`speedrush_summary.jsonl`，不写生产数据、不改控制。

## 协议（冻结）

**固定项**：代码 commit、机器、感知/深度配置、比赛回合与车组、程序驾驶、
开局流程。每次会话开始前记录 commit 与回合，写入会话备注（本地，不入库）。

**不可固定项**：赛道路径。游戏没有选图机制，路径每场随机生成（RULES §4.7）；
路径差异计入方差，**不允许事后挑选“看起来同赛道”的局**再做比较。

**重复次数**：10 局，分两段会话各 5 局（同一版本），用于区分局内与跨会话波动。

**碰撞**：v0 不测。当前没有碰撞数据源（血量格未读、胜负在结算屏）；异常局
保留录像供后续另立口径，**不得用“速度骤降”之类未校准代理冒充碰撞率**。

## 指标（跑之前定义，跑完不改）

| 指标 | 定义 | 来源 |
| --- | --- | --- |
| 主：得分速度 | 阶段 2 `score / (dur_s/60)`（分/分钟）；`score` 取最后 20 个有效 HUD 读数的中位（v0.1） | trace `hud_score` + 局汇总 `dur_s` |
| 辅：得分 | 阶段 2 末次 HUD 读数（对账用，不参与统计） | 局汇总 `score` |
| 辅：时长 | 阶段 2 `dur_s` | 局汇总 |
| 稳定性：拍间隔 | 决策拍 `dt` 的 p50 / p95 | trace `dt` |
| 稳定性：计划失效率 | `plan.valid=false` 拍数 / 有计划拍数 | trace `plan` |
| 稳定性：保守段 | `CONSERVE/FAULT` 拍数与连续段数 | trace `state` |
| 稳定性：转向抖动 | 相邻巡航拍 `abs(Δsteer_norm)` 的 p95 | trace `steer_norm`、`state` |

阶段 1 只报不判：现有六局里它的变异系数约 42%（最低 242、最高 2633），
不足以稳定区分版本；主判据固定在阶段 2。

## 停止规则

1. 每段会话结束后先算中位数 / 四分位距 / 最小最大 / 变异系数，不先做版本解读。
2. 主指标变异系数 **> 25%**：停下来查路径、车组、感知供数差异，**不加局**。
3. 两段会话的主指标中位与四分位距明显重叠之前，不比较任何两个版本。
4. 0 分或异常短的局不剔除，单独列出并注明原因；剔除会掩盖失败模式。

## 运行

```bash
.venv/Scripts/python.exe tools/experiments/baseline_v0/probe_baseline.py \
    --tokens 20261029_XXXXXX_1,20261029_YYYYYY_1
```

输出：逐阶段指标表、阶段 2 的汇总统计、冻结记录（commit 与策略文件摘要）。
`--json out.json` 可导出同口径结果。同一会话多轮时，按「阶段号变化或
>2 s 断档」切成一段一轮，再与局汇总按顺序配对（拍数不一致会告警）。
注意：输出里的 commit 是**分析时** HEAD，不等于运行时代码；运行时必须另行
记下当时 commit。

## 首轮试点（2026-10-29，6 局单会话，非冻结基线）

来源 `20261029_133951`：6 轮 / 12 阶段，程序驾驶。

**执行偏差（先于结果）**：

1. **局数**：6 局、单会话，不是协议的 10 局 5+5——跨会话波动仍未知。
2. **代码**：运行在 `a70ad0d`，不是冻结的 `9ecc71a`。并行会话在开跑前 39 秒
   提交；已核对该提交对 `module.py`/`hud.py` 只做日志组号透传，不涉控制与
   得分语义。但协议意义上它仍是另一次提交，本轮只作试点。
3. **探针**：初版按阶段号聚合，会把 6 轮合成 2 段；已改为按轮切分，下表是
   修正后的结果。

**结果**（n=6）：

| 指标 | 结果 |
| --- | --- |
| 阶段 2 得分速度（主判据） | 中位 6,241；四分位 [5,965, 6,940]；范围 [5,465, 8,049]；CV 14.5% |
| 阶段 1 得分速度 | 中位 3,368；范围 [2,724, 4,248]；CV 18.0% |
| 决策拍间隔 p95 | 73–83 ms |
| 计划失效拍占比（阶段 2） | 25–44%，几乎全部是 `plan:frame_shift` |
| 转向抖动 p95 | 0.15–0.28 |
| 保守段 | 1 段（第 2 轮阶段 1） |

上表为末次读数口径；v0.1 修正后六局得分速度变化 ≤1.4%，量级不变，不重列。

**相关（n=6，只记假设）**：末次读数下计划失效率与得分速度 Spearman −0.77；
扩到 11 局后降到 −0.34（见下节），不再作为待验假设。

**与旧六局对比**：阶段 2 的波动量级一致（旧 14% vs 本轮 14.5%），说明
「阶段 2 得分速度波动约一成半」不是偶发；阶段 1 从旧 42% 降到 18%，更像
是旧样本混了不同代码状态，而不是本轮更稳。

## 第二批与合并（2026-10-29，5 局新会话）

来源 `20261029_140039`：5 轮 / 10 阶段；运行在 `4f6514c`（在 `a70ad0d`
之上，只增实验文件，生产代码未变）。

**停止规则先触发了一次**：11 局按原口径（末次 HUD 读数）合并后，阶段 2
得分速度 CV 29.7%，超过 25% 线。异常点是一局 8,980 分：末 0.4 秒读数从
3,849 跳到 8,980（+133%），同一时刻速率从 41 跳到 131 并冻结到局末——
是结算/弹窗污染了末次读数，不是跑出来的分。其余各局在稳健口径下与末次
读数差 ≤1.4%。

**口径修订 v0.1（统一应用于全部 11 局，不是剔除某一局）**：阶段得分取
**最后 20 个有效 HUD 读数的中位**；末次读数保留在表里，差值超过 5% 打 `!`。
探针已按此实现（`probe_baseline.py`），复核命令不变。

修订后的合并结果（n=11）：

| 指标 | 结果 |
| --- | --- |
| 阶段 2 得分速度（主判据） | 中位 6,302；四分位 [6,044, 7,390]；范围 [5,409, 8,188]；CV 14.1% |
| 会话 A（6 局） | 中位 6,212；CV 14.3% |
| 会话 B（5 局） | 中位 6,645；CV 14.4% |
| 会话间中位差 | +7%；四分位区间重叠 |
| 阶段 1 得分速度 | 中位 3,041；CV 21.9% |
| 决策拍间隔 p95 | 72–83 ms |
| 计划失效拍占比（阶段 2） | 24.8–44.1%，几乎全部是 `plan:frame_shift` |
| 转向抖动 p95 | 0.21–0.28 |
| 保守段 | 1 段（首批第 2 轮阶段 1） |

**相关（n=11，修订后）**：计划失效率与得分速度 Spearman −0.34；转向抖动
−0.07。首批 6 局里的 −0.77 没有在新增 5 局里复现，**「计划失效导致失分」
不再是待验假设**。

**结论**：阶段 2 得分速度的局间波动约 14%，跨会话中位差 7%、区间重叠——
这就是当前版本的可比噪声底。任何版本改动需要带来明显大于此量级的变化，
才值得再跑对照。

## 下一步

1. 基线到此可用：11 局、两个会话、主判据 CV 14.1%。不再为「测波动」加局。
2. 下一次跑局应当对应一个具体的版本改动，用同一协议与同一条命令对照；
   若改动预期收益小于约两成，先不要用这套样本量去判。
3. HUD 末次读数不可靠已记录在案；若以后要改局汇总本身，需要单独的回归锁，
   不在本实验内动生产代码。
