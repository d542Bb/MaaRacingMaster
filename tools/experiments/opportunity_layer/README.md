# opportunity_layer — 中心层时间的去向分账（活跃）

status: active

**问题**：巡航期约 88% 的时间选择层停在 L4（回中/承诺）。这 88% 里，
多少是路上真的没有机会、多少是看见了没进来、多少是请求没能起并、多少是
承诺期按合同关闭？本实验只读地分账，**不评价得分收益**，也不改控制。

**只读**：探针只读 trace 与 policy/calibration JSON，不写生产数据。逐拍复算
import 选择层纯函数 `select`（无状态、无副作用），理由与
[frame_delta/replay_route.py](../frame_delta/replay_route.py) 相同：复算必须
用同一份规则，且先与生产记录对账，才能把「输入不全」和「规则抄错」分开。

## 运行

```bash
.venv/Scripts/python.exe tools/experiments/opportunity_layer/probe_opportunity.py
.venv/Scripts/python.exe tools/experiments/opportunity_layer/probe_opportunity.py --selftest
.venv/Scripts/python.exe tools/experiments/opportunity_layer/probe_opportunity.py \
    --run 20261028_213019_1 --csv opp_ticks.csv
```

trace 默认根：`%APPDATA%/MaaRacingMaster/logs/<token>/trace/speedrush.jsonl`。

## 口径

1. **样本**：6 局 12 个 stage，`sel_dbg` 非空的巡航拍 10,859 个（577.3 s）。
   只覆盖选择层真正跑过的拍；非巡航段不在内。
2. **复算**：用 trace 里的选择层输入重建对象与公路帧——`sel_dbg.ego/c0/
   left/right/rw/car/coin`、`route` 的相位与参考道、`coarse` 与 `scene.stale`
   决定喂给选择器的粗层/承诺道。先对账生产记录的层号/原因/请求，再跑反事实。
3. **层时间**：`sel_layer × dt`；`dt` 取同拍，缺拍不计。
4. **L4 分账**：
   - 承诺期 = `route.ph=merging`（合同关闭机会层与越线请求）；
   - 非承诺拍跑反事实 A（`committed=False, commit_x=None`，即机会层可跨线
     直追的旧口径）：A 落在 L1/L3 = 可起意；A 落在 L2 = 仅安全擦边；
     A 仍为 L4 = 无机会。
5. **无机会细分**（互斥，按优先级）：空街（原始检出与源列表都空）→ 看见
   未进源（`raw_coins/raw_bonuses>0` 而源列表空）→ 无到站/视界外（有目标但
   无 0<t≤horizon 的到站时间）→ 横向太远（超容差，分「一道内/更远」）→
   容差内没选上（横向够得着，但到站时间来不及时或被车占住）。
6. **请求口径**：连续非空请求为一段；**本拍路线读的是上一拍请求**，起并 =
   路线 `vd=merge_start` 且 `why=opportunity`；未起并主因取段内 keep 原因的
   第一名。
7. **已知口径边界**：金币的 `count/conf` 没进 `sel_dbg`，复算按 1.0 处理
   （只影响同层内部排序，不影响层号）；「看见未进源」里的原始检出没有位置，
   该桶是**上界**，不是精确的漏失量。

| 层号+原因一致 | 10,476 | 96.5% |

## 金币位置可用性核验（试点：225902）

**要回答的**：那 22.2% 的「看见未进源」，是不是眼前真实可用、却没形成源的机会？
先盘点现有证据，再决定要不要补 trace 字段。

现有数据盘点：

| 需要的量 | 现存位置 | 覆盖 |
| --- | --- | --- |
| 每拍原始检出计数 | trace `raw_coins/raw_bonuses` | 全部拍 |
| 币组 id/置信/观测数/末见帧/部分观测 | trace `cgroups` | 全部拍（**无位置**） |
| 同拍 ego/走廊左/右缘 | trace `sel_dbg` | 全部拍 |
| 金币框像素位置（cx/cy/w/h/conf） | 只在运行时内存（感知/跟踪/币组） | **不落盘** |
| 币组 lead_x/lead_cy | 只在运行时内存（币组状态） | **不落盘** |
| 原始帧 | `debug/speedrush/20261028_225902_manual_p{1,2}/frames` | 2 个 stage，1704 帧，帧号与 trace 100% 可 join |
| 其他局的原始帧 | 无（225041 只有 HUD 裁剪，其余 4 局无帧） | 0 |

也就是说：**位置在运行时存在，但没有进入任何落盘产物**。唯一可离线重建的
是 225902 两段（占 76 s 未分组金币时间的约 18%）：用插件自带模型对录制帧
重跑感知（1704 帧约 41 s），按帧号 join 回 trace。脚本
`pilot_unGrouped_coins.py`；它 import 感知/标定做帧重放，与
`speedrush_drive/probe_tracking_replay.py` 同口径，分类不读任何下游决策结果。

试点口径（只读，不改任何控制）：

1. 对每个 gap 拍（`raw_coins>0` 且币源列表为空）重跑检出，逐框分类：
   - **视界边缘**：框触画面边界；
   - **远/无横向读数**：`cy−y_h < 20 px`（标定口径，约 50 m 外）；
   - **走廊内/外**：`x_lane_of(cx,cy)` 减去同拍 ego，与 `sel_dbg.left/right` 比；
   - 一拍多框按「走廊内 > 走廊外 > 远 > 边缘」取最可用的一类。
2. 连续 gap 拍合成一段，按段统计，不按帧；段内按类分时。

结果（225902，全部巡航拍；含 L1–L3，故比表内 L4 口径的 13.8 s 略大）：

- gap 拍 305 个、16.1 s（p1 4.7 s / p2 11.4 s），帧号 100% 可 join；
  重放能找回至少一枚的占 97%。
- 分类时间：**远/无横向读数 15.1 s、走廊内 0.7 s**；走廊外与视界边缘≈0。
- 33 段连续 gap：27 段以「远」主导，5 段含「走廊内」成分（每段 0.03~0.07 s），
  1 段重放无检出。最长一段 3.07 s，几乎全是远币。
- 对照：成组金币拍里「走廊内」16.1 s 占主导——重放确实能分出两类。

**判读**：这一局里，未进源的金币几乎都在视界顶端，没有横向读数，属于
「还没到能用的距离」，不是「眼前漏掉的近机会」。22.2% 的上界在这一局
大幅收缩。但这只是 1/6 局、18% 的 gap 时间，且是人工局，不能外推。

**保真与边界**：逐拍金币检出计数与在线一致 98%（685/697、916/931）；
成组金币拍只有 85%/75% 能找回，因为存续组本拍可能没有新检出；远币的走廊
归属用 ego 站边缘粗判。结论只用于「这些检出大致在哪」，不做逐拍精度断言。

**字段决策（收口 2026-10-29）**：

- 试点录像中，未分组金币主要位于视界顶端，符合远距离、尚不可用的解释；
  其余未录像时段无法判定。
- 22.2% 只能称为「可见但未进入选择层的时间上界」，不能称为漏失率。
- **不新增位置字段，不修改检出、分组或六拍确认门槛。**
- 重开条件：固定赛道基线显示金币机会与得分或碰撞存在可重复关联时，再按
  证据重开。
- 保真口径：98% 是**检出计数**的复现率，不是「远币」分类的准确率；方向性
  判断靠成组金币的对照分布与 33 段连续事件，不靠逐拍分类精度。

## 判读

- **88% 中心层主要不是被路线门挡出来的**：承诺 25.6% + 非承诺无机会 71.1%
  = L4 的 96.7%；真正「机会层本来会接」的只有 3.3%。
- **「看见了没进来」比「请求被拒」大一个量级**：源转换缺口 22.2% 是**时间
  上界**，不是漏失率；其中 76 s 是原始金币检出没有形成组、25 s 是奖励车未
  成源。请求层失败主要是短闪攒不到计分，而不是路线拒绝。试点局里这 76 s
  的九成是视界顶端远币（无横向读数），不是眼前近机会——见上节。
- **承诺期的机会压制是可量的**：L4 的 6.6%（33.6 s）在承诺期眼前有可见机会，
  按合同关闭；这是设计行为，但此前没有量。
- **道差结构**：无请求的可起意机会几乎都是 ±2 道及以上（±2 占 4.3 s），
  现有「只允许相邻 ±1 道请求」的口径覆盖不到。

## 边界

- 只有「机会是否可见/可起意」，没有得分、碰撞、完赛时间——不能据此说追这些
  机会会更好。
- 「看见未进源」是上界：原始检出没有位置。225902 试点显示以远币为主；其余
  约 82% 的 gap 时间没有帧，**无法判定**——不能把试点结论外推到这部分。
- 12 个 stage 赛道不同，跨 stage 不可当因果；同一 stage 内 700~1750 拍，
  分布只能作局内参考。
- 人工局（225902）与程序局混在同一张表；程序局的输入延迟/帧率与人工局不同，
  分层对比时需分开。

## 下一步

1. 机会层这条线**收在「试点收缩 + 其余无帧」**：不加字段，不再把 22.2%
   当漏失率使用；只有固定赛道基线出现金币机会与得分/碰撞的可重复关联时，
   才按证据重开。
2. 请求计分门槛（6 拍）与短闪的关系已是机制事实；是否放宽是控制决策，需先
   有结局证据（漏掉的请求对应真实币线且能改变得分），不能只凭时间占比。
3. 可比较基线仍要另立：固定赛道、固定协议、重复局，先测出方差再看几局够。
