# 小模型快速栈：最小可开状态能否供出（2026-10-21）

> **要回答的问题**（维护者口径）：开车其实只需要四件事——路的范围、车身方向、速度、
> 加上物品感知给的标签。深度模型（MoGe-2 ViT-S q4f16）慢不代表不能用，本实验把
> 这四件事直接画到帧上人工确认，并量化「供得出 / 供不出」的帧占比。
>
> **范围**：只读离线回放（`demos/video_20261021_160547_p1|p2`），不改生产代码。
> 全部读数由生产实现产出（找边、可行驶栅格、中远场地面带、YOLO 感知），探针只做
> 组装与可视化。所有数字来自 [`probe_fast_stack.py`](probe_fast_stack.py) 的实际运行。

## 一、口径

| 需要的状态 | 供数路径（本实验） | 是否用图像匹配 |
|---|---|---|
| 路的范围 | 近场：点云找边 `reading_from_points`（z≤16m，实测）；中远场：地面可见带 `ground_far_extents`（16~80m，推断级） | 否 |
| 车身方向 | 左右边界各一条 RANSAC 直线 → 路心线的斜率即航向、z=12m 处的横坐标即横偏 | 否 |
| 速度 | 静态目标（金币）框底距离帧间差分；跟车需要的是相对接近速率，另走框宽扩张率（不碰点云） | 否（目标级配对，非像素匹配） |
| 目标 | YOLO 框 + 框底中点取点图 Z | 否 |

## 二、实测（每段 300 帧 @60fps，token=1032 现役档）

| 段 | 找边双侧帧占比 | 远带≥3 帧占比 | 方向/横偏供出率 | 方向抖动（9 帧中位绝对偏差） | 速度供出率 | 速度中位 | 单帧总耗时 P50 |
|---|---|---|---|---|---|---|---|
| p2 起 0 | 0.95 | 1.00 | 0.87 | 0.70° | 0.78 | 247 km/h | 81 ms |
| p1@600（高速跟车） | 0.88 | 1.00 | 0.66 | 0.60° | 0.00 | — | 90 ms |
| p1@950 | 0.80 | 0.99 | 0.62 | — | 0.00 | — | 88 ms |

- 速度中位 247 km/h 与两路独立估计同量级：车道标记跨帧法 236 km/h、HUD 显示 231。
- 目标测距：近场（<15m）框底 Z 与框宽测距互差在分米级；>60m 的框底 Z 跳到 90~130m 乱值，
  必须按距离上限丢弃。
- 相对接近速率（框宽扩张率）在跟车段稳定给出 −55 m/s 量级，与前后车实际接近量级一致。

## 三、结论

1. **路的范围：成立**。近场实测边界 + 中远场地面带，双侧可读 80~95%，远带几乎不缺。
2. **车身方向：勉强成立**。供出率 0.62~0.87，抖动 ±0.7°；缺口在单侧边界只有一两个
   距离箱时（弯道、被车遮挡），以及假缘（把车当成墙）把斜率拽飞。
3. **速度：不成立，且是场景决定的**。金币在场就有（0.78），没有金币的纯跟车段就是 0。
   静态目标不是常备供数，不能当闭环的速度真源。
4. **时延：不成立**。单帧 80~90 ms（模型本体 47 ms），约 11~12 Hz。想抽稀换帧率走不通：
   现役 ONNX 是 1032 token 折叠静态图，`num_tokens` 不是图的输入，降档必须重新导出权重。

## 四、局限

- 方向、路的范围没有独立真源，靠人工看叠加图判定；帧内自车遮挡与真实并线会让横偏
  分布变宽，不能把分布宽直接当误差。
- 速度只有 p2 起段可与两路独立估计对照，其余段无基准。
- 可视化里 BEV 面板近场有一块黑区（自车掩码半窗过宽），只影响看图，不影响读数。
