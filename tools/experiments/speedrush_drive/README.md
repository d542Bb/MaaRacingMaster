# speedrush 驾驶感知实测（2026-09-16）

回答的问题：**旧 racing 的感知件能否直接搬到 speedrush 驾驶上？** 属 C 类问题（外部系统
行为——跨画面域的模型/算法表现），按守则必须实测，禁止靠猜。

## 素材与方法

- 帧源：维护者提供的 speedrush 真机窗口截图（15 张进入流程 + 2 张驾驶），
  1281×759 窗口截图，裁出 720p 客户区（`x=1 / y=38` 偏移，见 `docs/CODE_WIKI.md` §9.7）。
- 驾驶帧定位：以驾驶页独有的档位图标 `speedrush_drive_gear.png` 做模板匹配，
  >0.85 判为驾驶页。**16 帧中仅 2 帧是驾驶页**（gear 分 1.0000 / 0.9788）。
- 模型：`archive/racing/resources/onnx/model.onnx`（racing 时代 3 类微调，coin/car/bonus_car）。
- 探针：`probe_legacy_model.py`。

## 结果

### 1. 检测器在 speedrush 帧上的表现

| 帧类别 | 帧数 | coin | car | bonus | raw(阈值 0.05) |
|---|---|---|---|---|---|
| 进入流程 UI 页 | 14 | 0 | 0\~2 | 0 | 0\~12 |
| **驾驶页** | **2** | **0** | **0\~1** | **0** | **4\~5** |

两张驾驶帧目视确认均为**空旷路段**：无金币、无障碍车，仅远处一辆对手车。因此
**"0 检出"与画面一致，不构成模型失灵的证据**——本批素材无法判定模型复用性。

反例：活动页帧（背景为赛车宣传画）模型能检出画报中的金币（0.62）与车（0.74），
说明模型对**画报式**的金币/车外观仍有响应。

### 2. 标线体系与 racing 不同（实测，比模型更要紧）

驾驶帧显示 speedrush 的道路标线是：

- **车道分隔 = 白色虚线**（自车左右各一条）
- **路缘/道路边界 = 黄色实线**（两侧，透视斜线）

而旧 racing 的 `_detect_lane` 是**「找黄色标线」**（HSV 黄色范围 `[20,80,80]`），把它
当作单侧"墙"喂给 `_wall_avoidance`。两者语义在本域发生了**漂移**：

- 黄色线在 speedrush 里确实存在，但那是**路缘**，不是车道分隔 → 旧算法的"墙"语义
  恰好仍成立（路缘就是墙），**这一半可复用**；
- 但旧算法**没有检测白色车道分隔线的能力**，它靠硬编码透视测量点
  （`_lane_boundaries_at_y` 的 `bound(0.22, 1.00)` 等分数）反推车道边界——
  本域白线**直接可见**，用硬编码反而丢掉了现成的观测。

### 3. 光照变化已证实

两张驾驶帧分别为**阴天**与**晴天蓝天**。用户此前描述的"两种天光"得到印证。
这对基于颜色的阈值型检测（旧 racing 的 HSV）是直接威胁，对学习型检测影响较小。

### 4. HUD 可读数据清单（供数据记录阶段）

驾驶页 HUD 含：`阶段:N`、倒计时、`里程`、`超车`、总分、`得分速度 X/s`、双方比分与
血量百分比、`极限超车` 横幅。均可用 rapidocr 在 Python 侧读取。

## 结论与下一步

- **模型复用性未证实**，需含金币/障碍车的驾驶帧才能判定。素材缺口如实记录，不下断言。
- 旧算法的**标线检测**部分确认与本域画面域不匹配（白线 vs 黄线），这是"旧算法差"的
  根因之一，且决定了新方案该怎么做。
- **车道结构已确认**：**4 条车道**，由 3 条白虚线分隔、双侧黄色实线路缘界边。自车左右
  各紧贴一条白虚线，第二条白虚线贴画面左缘且断续——初查因单帧漏认该线误读为 3 条，
  把路面左右两半各放大一倍逐一核对后纠正。观测时自车位于**从左数第 3 条**车道。
  标线形态与车道结构已录入 `RULES.md` §3.8。

## 街车检测充分性重测（2026-09-21，补上「素材缺口」那一半）

回答的问题：旧 racing 模型的 `car` 类在 speedrush 域**有街车时是否稳定认得出、跨场次/
天况是否一致**——决定阶段 B 感知是否需要重训。`speedrush_vision` 实验（2026-09-18）的
60 帧初判只回答了"能不能认"。

### 素材与方法

- 帧源：recorder 全量导出 **34 场 × 28329 帧**（1280×720 客户区帧，`demos/<场>/frames/`）。
- 探针：`probe_streetcar_coverage.py`（scan 逐帧推理 → jsonl；analyze 派生指标）。
  阈值口径与旧栈运行时一致（0.35、NMS iou 0.45、RGB 640 letterbox），走参数化后的
  `core.yolo_detector`（与阶段 B 同一条路）。

### 结果

| 指标 | 值 | 判读 |
|---|---|---|
| 有 car 检出帧占比 | 场均 73.6%（p10–p90 55–96%） | p1/p2 后缀实为**阶段**：阶段 1 街车稀、阶段 2 密（目视证实） |
| 框落旧栈语义带 y∈[201,561] | 92–99%/场 | 空间 sanity 过 |
| 自车嫌疑区（cx∈[600,680]∧y>600）误检 | **0.0%** | 自车从未被认成街车（追车相机钉中央，与 control-route 副产品一致） |
| 轨迹均值/最长（贪心最近邻） | 8–19 帧 / 34–191 帧 @15fps | 时序连续 |
| 近框（宽≥120px）conf 中位 | 白天 **0.89** / 黄昏雨 **0.88** | 近距跨天况一致 |
| 中框（50–120px）conf 中位 | 0.87 / 0.87 | 一致 |
| 远框（<50px）conf 中位 | 0.77 / **0.67** | 弱点：远距小目标，黄昏雨再降一档 |

目视甄别（5 帧，覆盖低检出场零检出帧与高检出场多框帧）：零检出帧为**空旷路面或消失点
附近 <15px 车影**——"画面里没目标"为主因，不是模型失灵（vision 实验教训的同款验证）。
9/21 晨场含**雨景**（镜头水滴、路面湿反光）与黄昏逆光，近中距检出均正常。

### 结论

- **阶段 B 感知不需要为"街车认不出"重训**：近/中距（决策点所在距离）跨天况稳定高置信，
  无误自检，时序连续。
- 已知弱点如实记录：**远距小目标（<50px）置信偏低且受天况影响**（0.77→0.67）。它影响
  前瞻距离而非决策点；是否够用，待 τ 转向延迟实测（阶段 B 开工前置）给出所需前瞻量后判定。
- 触发重训的条件（与"能不能认街车"无关，来自 vision 实验硬缺口清单）：需要拆分两类奖励车、
  需要金币组结构、或 τ 实测证明远距前瞻不足时。
- 疑点：083222_p1（雨）最长轨迹 191 帧（≈12.7s），远超一次超车的合理时长，疑为消失点
  附近滞留的远距误检被贪心关联串成；不阻断结论（近中距指标独立成立），留作阶段 B 联调时
  的跟踪器设计输入。

复跑：`.venv/Scripts/python.exe tools/experiments/speedrush_drive/probe_streetcar_coverage.py scan`
（约 6 分钟）后接 `... analyze`。逐帧结果在数据目录 `speedrush/streetcar_coverage.jsonl`。
