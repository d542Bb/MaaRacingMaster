# perf_panel_v2 —— 性能面板 CPU + GPU 双线形态预览

status: active

## 目标

数据页「性能监控」卡当前是两格 CPU 视角：一格整机占用、一格本程序，各一条走势。要看的是「这颗器件被谁吃了」，而两个 CPU 数字放在一起只能比大小，看不出「本程序占整机多少」。

本目录是前端设计评审用的静态形态预览：把两格改成**一格 CPU、一格 GPU**，每格两条走势——灰线是该器件的总负载，红线是本程序占它的份额。数字同步给两个（总负载大号、程序负载小号，红色与红线对应），所以「红线离灰线多远」就是本程序之外的占用。

不接生产数据，数值为模拟；样式取正式前端的 token 与卡片语汇，但不引用生产代码。

## 形态

一块磁贴是一张海报，不是一张图表：

- **左上角图标**：CPU 是芯片轮廓，GPU 是显卡轮廓，24px、45% 透明度，只做器件标识。
- **右上角大字 + 型号**：`CPU` / `GPU` 64px、6% 黑，右上对齐；型号（`12 核` / `RTX 3060`）10px、45% 透明，紧贴大字下沿。两者都是弱装饰，不参与读数。
- **左下角数字**：总负载 32px、程序负载 13px 红字，距左边缘 10px。曲线会从这行字上穿过，所以数字带一层白色晕影（`text-shadow`，不是描边），线被柔化、读数不受影响。
- **曲线铺满整格**：平滑曲线（单调三次 Hermite，不过冲）+ 同色渐变面积，基线离磁贴底边 4px（贴边会被裁掉），面积一直铺到底。
- **层次**：曲线（z1）< 大字与型号（z2）< 图标与数字（z3）。
- **不留空高**：磁贴 96px，高度按内容定；两格间距 40px，磁贴与上下分区的间距都是 16px。

左右边缘不做淡出——面积与曲线在磁贴边界直接结束。

不接生产数据，数值为模拟；样式取正式前端的 token 与卡片语汇，但不引用生产代码。

## 状态（页面顶部切换）

- **运行中**：CPU 约 30%，程序约 11%；GPU 约 22%，程序约 8%。
- **核显+独显**：笔记本双适配器，游戏跑在独显上，程序占用明显高于整卡均值。
- **待运行**：数字压到低位，健康度转「待运行」，验证低值下曲线是否还看得出形状。
- **无 GPU 数据**：GPU 格只剩大字与一行说明，不画空曲线，整卡高度不变。
- **高负载**：红灰两线贴近，看数字压在浓色面积上是否仍清晰。

另有一个「固定 0–100 标尺」开关（默认关）：默认自适应标尺（带 20% 地板值，避免 2% 被撑满整格）；勾上后两格可直接比大小，代价是小数值被压扁。

## 口径

- **两格是两颗器件**：CPU 与 GPU 各自独立，不跨格比较谁高。
- **每条线的口径**：总负载 = 该器件整体利用率；程序负载 = 本程序占用 ÷ 该器件容量。
- **同刻度是前提**：同一格内两条线永远共用刻度，灰线与红线的间距才有「别人吃了多少」的含义；跨格比较只在固定 0–100 时成立。
- **窗口固定步长**：新点从右侧进入，曲线左移，不横向拉伸（现有实现的 `drawSpark` 按点序号铺满宽度，样本未满时会横向拉长，这里改成按固定容量取横坐标）。

## 硬件差异：小库没有，但系统计数器能用

先查库：能 pip 装的 GPU 小库全是 NVIDIA 的包装——`GPUtil`（2018 年最后更新）、`gpuinfo`（2020 年 alpha，Linux 取向）、`pynvml` / `nvidia-ml-py`（NVML 绑定），都只是换个壳调 nvidia-smi。AMD 有个 `pyadl`，2017 年停更、要随包带驱动 DLL、只管 AMD。Intel 核显没有任何库覆盖。**没有维护中的跨厂商小库。**

但「没有库」不等于「拿不到」。Windows 自带的 GPU 引擎性能计数器与厂商无关，按 **进程 × 引擎** 给占用（任务管理器读的就是它）。实测（`probe_gpu_pdh.py`，本机 RTX 3060）：

```
instances: 611
engines: {'3D': 18.9, 'Copy': 0.2}
top pids: 21588 → 11.8, 1180 → 4.5, 40640 → 2.3 ...
```

- **按进程**：实例名形如 `pid_21588_luid_0x..._phys_0_eng_0_engtype_3D`，直接解析出 pid、适配器 LUID、引擎类型。
- **跨厂商**：计数器由系统提供，AMD / Intel 核显同样有实例。
- **零依赖**：系统自带 `pdh.dll`，Python 用标准库 `ctypes` 直调即可，不需要 pywin32，也不用起子进程。
- **代价**：一条查询里 600 多个实例，两次采样之间才出比率（面板 1Hz 正好，第一次采样要丢弃）；一个进程可能同时占多个引擎，求和后要截到 100；进程没有 GPU 活动时实例不存在，读数按 0 处理。

两个数字都能从同一份数据算出来：程序负载 = 该 pid 各引擎求和（截 100）；整卡负载 = 每个引擎把所有进程求和后取最大值（引擎并行，不能相加）。

现有实现只有 `nvidia-smi`（整卡、仅 NVIDIA、只读第一行）。换到计数器后多卡与非 N 卡一并解决，采样开销也比每次起 `nvidia-smi`（实测 78–94ms）低。

## 与生产实现的差距

| 项 | 现状 | 本预览需要 |
|---|---|---|
| CPU 总负载 | 有（采样器 `sys.cpu_pct`） | 不变 |
| CPU 程序负载 | 有（本进程占用 ÷ 核数） | 不变 |
| GPU 总负载 | 有（`nvidia-smi` 整卡利用率，5 拍一采） | 不变，注意采样间隔比其他面粗 |
| **GPU 程序负载** | **无** | 改读 GPU 引擎计数器（见上节，探针已跑通） |
| **多卡 / 非 NVIDIA** | 只读卡 0，非 N 卡无数据 | 同一份计数器数据按适配器分组即可 |

后两项要动 `core/perf_sampler.py`，属于新增采集源，不在本次前端形态范围内。
