# speedrush_plan —— 横向轨迹规划标定与回放

status: active

motion_plan 架构（场景快照 → 时空横向轨迹评估 → 预览跟踪）的离线实验区。

## fit_plant.py

从控制 trace 拟合横向 plant 参数 `(a_lat_gain, tau_align_s, v_lat_max, tau_steer_s)`。

```bash
.venv/Scripts/python.exe tools/experiments/speedrush_plan/fit_plant.py \
    --trace <trace.jsonl> [--trace ...] [--out report.json]
```

口径：

- 似然 = 一步转移 + 生产同款 α-β 观测模型；修正拍不剔除。
- 留出验证按整段 trace 留一；参数 CI 用 Jacobian 近似（仅作退化检查）。
- `sigma_ego(t)` 由多步开环残差按 horizon 拟合，保守含路心观测噪声。
- 缺 `steer_raw` 列的旧 trace 只能拟合三个参数，`tau_steer` 不可辨识，
  `calibrated=false`；需要新录一局带 `steer_raw` 的 trace 才能解锁。
- `calibrated=false` 时 `motion.mode=live` 必须 fail-loud（影子/离线不受限）。

## replay_plan.py

读带 `scene/plan` 列的控制 trace，按录制顺序回放 `plan_motion`（gate 同构），
输出确定性对齐率、`plan.valid` 覆盖率、层分布、预览抖动与单拍 P99。

```bash
.venv/Scripts/python.exe tools/experiments/speedrush_plan/replay_plan.py \
    <trace.jsonl> [--out summary.json]
```

## 半程反打候选（2026-10-30，画龙实验）

**改动**：`plan_motion` 的候选从「恒杆 2s + 当前杆值」扩为「恒杆 2s + 半程反打
（前 1s 打 u、后 1s 打 −u）+ 当前杆值的反打」。恒杆开环在接近目标时预测里
没有“停下”，计划只能靠下一拍换杆追，选出的大杆值天然过冲、晚反打
（`docs/plan/lateral_behavior_contract.md` 阶段 1.5）。反打候选只给 |u|≥0.2
的杆值；当前杆值的反打恒存在，候选数固定 21（闸门存续项下标不随拍变）。

**离线回放**（`probe_reverse_candidates.py`，同批拍分别喂两种候选集、各自
gate；20261030 两局）：

| 指标 | 旧候选 | 新候选 |
| --- | --- | --- |
| 大误差反向打杆 | 25.0% / 36.9% | 23.5% / 31.4% |
| L4 保住段“朝速度反打”占比 | 63.2% / 56.1% | 71.1% / 57.1% |
| L4 偏移拍预测末端偏差（道） | 0.94 / 0.90 | 0.64 / 0.66 |
| L4 偏移拍预测峰值（道） | 1.13 / 1.18 | 0.98 / 1.05 |
| 杆值换向/分 | 45.6 / 31.0 | 46.2 / 31.7 |
| 单拍耗时 p50 / p99 (ms) | 0.41 / 0.88 | 0.70 / 1.37 |

方向符合预期；代价是计划单拍 +0.3ms p50、+0.5ms p99（控制链 p50 由约 2.3ms
升到约 2.6ms）。**离线只验证预测面**：ego 状态用录制值、开环重放，闭环是否
真的少画龙要看真机 A/B。

**观测量**（跑完对照）：横穿路中心次数、横位摆幅、车身压过走廊边线的拍数、
大误差反向打杆占比、计划失效、得分速度。

## 意图抖动：闸门确认 + 币不居中（2026-10-30 下午）

人工局 `20261030_114825` 的逐拍证据：计划杆值中位 3 拍一段、48% 的段
只活 1–2 拍；计划层里擦边层 36 段有 25 段只活 1 拍、金币段中位 2 拍。
根因是计划闸门的「价值差 > immediate(100) 立即切」：擦边 120 / 空中金币
120 / 奖励车 240 都过线，单帧检测闪断就拽杆，下一拍消失再拽回。

改动两处：

1. **闸门**：立即切换只给安全类（最优候选碰撞代价更低，或现任得分目标
   已失去、最优回中）；新出现的得分机会改走 dwell(0.2s) 确认。
2. **币目标**：`_coin_aim`——车有半宽，币心落在车身带（0.27 道）内就
   保持原线，带外只走到带边，不再对币心；换道请求按带边算。收集判据
   （计划层 0.35 道）比车身带宽，压在带边仍能吃到。

离线（闸门按 trace 逐拍恢复、同批拍）：

| 指标 | 改前 | 改后 |
| --- | --- | --- |
| 杆值段数（人工 87s） | 332 | 312 |
| 段长中位（拍） | 2 | 3 |
| 1–2 拍短段占比 | 51.5% | 46.5% |
| 杆值换向/分（人工） | 54.9 | 50.7 |
| 杆值段数（自动 613s） | 1,629 | 1,565 |
| 原始选择目标跳变（人工） | 158 | 144（币带内保持原线） |

幅度都不大：dwell 只有 0.2s，持续 3–4 拍的机会照样会切；真正的结构缺口
是「近到远目标候选链」没有实现——选择层每拍只挑一个目标，没有跨帧锁定的
链，层一变目标就跟着跳。链条是下一步的大件，本轮先不动。

## 车宽口径回放（2026-10-30，`probe_width_replay.py`）

**问题**：`traffic._refresh_width` 用框**中心行**做地面尺分母（`cy − y_h`），
但框宽对应的是车体触地深度处的像素尺——中心行比地面行高半个框高，透视下
分母偏小。三局 trace 实测半宽中位 1.72m（真车约 0.8~0.9m），83~93% 的车
被 `graze_max_width_m=2.2` 判成「大车」，擦边/超车价值层几乎全灭；同时
`late_block` 的「已重叠」豁免按放大后的车身和判，0.35s 内到站的邻道车被
当成已经贴上，规划层不再拦「往它那侧并」——这就是见车往上撞的口径漏洞。

**修法**：分母改框底行 `cy + h/2 − y_h`；结果越出车宽物理域
（`min_width_m`~`max_width_m`）不出 w_m、消费方回落标称半宽。

**只读回放**（同一批场景分别按录制宽度 / 框底行 / 夹域 / 全标称重跑
`plan_motion`，gate 各自独立回放）：

| 指标（90s 自动局 / 人工局） | 录制宽度 | 框底行 |
| --- | --- | --- |
| 擦边层 L2 拍数 | 38 / 46 | 58 / 66 |
| 通过带非空拍数 | 319 / 314 | 445 / 394 |
| 选定候选碰撞代价 >0 拍数 | 66 / 92 | 52 / 61 |
| 「已重叠」豁免拍数 | 79 / 207 | 53 / 150 |
| 被判大车的车次数 | 404 / 469 | 80 / 100 |

即：擦边机会 +50% 左右、幻影碰撞 -20~35%、「见车还敢并过去」的豁免 -30%。

```bash
.venv/Scripts/python.exe tools/experiments/speedrush_plan/probe_width_replay.py \
    <trace.jsonl> [--limit N] [--out out.json]
```

## 路线紧急逃生时间门回放（2026-10-30，`probe_route_ttc.py`）

**问题**：粗层净空只说明 24m 观察窗内有无车；`urgent` 用 `free_m/45` 代理
时间起意，窗内任何车都 ≤0.53s＝永远紧急。90s 自动局 21 次并线里 11 次车
还在 1s 以外，路线见车就并、并完再并——这是"不并线超车、一直画龙"的发动机。

**修法**：`tick_route(..., lane_ttc=整数道→最早到站时间)`。紧急逃生要求
承诺道与实测所在道取更近的到站时间 ≤`urgent_ttc_s`；无时间证据只认
`urgent_blind_m` 近距盲区；逃生目标道有车时到站时间须 ≥`merge_safe_ttc_s`；
中间道检查起点改用实测横位。

**只读回放**（trace 的 `coarse` + `sel_dbg.req` + `scene` 逐拍重放，新旧
各自推进路线状态）：

| 指标（回放旧 / 回放新；括号内为录制值） | 旧（代理时间） | 新（到站时间） |
| --- | --- | --- |
| 90s 局并线次数（录制 21） | 19 | 4 |
| 613s 局并线次数（录制 137） | 130 | 59 |
| 613s 局 `urgent_no_alt` 拍数（录制 94） | 154 | 34 |

613s 局里被时间门拦下的 99 次并线中，多数是「车还在 1s 以外」；同时新增
28 次（早先被无谓并线改掉的路线重排）。并线从「每 4~5s 一次」降到
「每 10s 量级」。

```bash
.venv/Scripts/python.exe tools/experiments/speedrush_plan/probe_route_ttc.py \
    <trace.jsonl> [--out out.json]
```

**边界**：回放用 band 中心近似 `center_at(0)`、请求取 trace 记录值，旧口径
重放得到 19/130 次（录制 21/137），差异来自这两处近似；方向与量级可用，
绝对值以真机 A/B 为准。

## 偏靶与肩道排查（2026-10-30，只读）

- **偏靶**：`|scene ego − x_target|` 在 90s 局 p50 1.6m / p90 4.2m；去掉
  `plan:frame_shift` 与并线拍后 p50 1.25m / p90 3.2m，且误差**符号对称**
  （p25 −0.81 道、p75 +0.92 道）——不是单向偏差或杆幅权限不足，主要是目标
  在动（并线/机会）与参考系跳变的混合。暂不加控制权限；车宽/路线/参考系
  三条落地后按同一口径复测，再看残差是否还剩稳态偏差。
- **肩道**：候选道中心落在走廊 `[l+0.5, r−0.5]` 之外的拍为 0/1511 与
  2/40123；走廊宽 ≈3.96 道（画线 3.5m×4）。没有「黄线外被当车道」的证据，
  69.8s / 87.5s 的贴肩是参考系跳变把自车放进肩道，不是候选道集合的问题。
- **仍开放**：`ro_hop=1`（物理不可能的路心跳变）在观测层仍只标注不拒收；
  要拒收需要第二信源互证（车道线横位），单靠延长确认拍数挡不住持续性错帧
  （20261030_122416 seq1520 的新值持续了 1s 以上）。本轮先在控制层做了
  参考系包含（`plan:frame_shift` 时只用 planner 帧保持）。
