## 方法与口径

- **素材**：旧检测模型（`archive/racing/resources/onnx/model.onnx`，3 类）+ 演示录像
  （`frames.jsonl` 帧 + `pads.jsonl` 的 `lx` 转向量，200 Hz）+ `hud.jsonl` 读数为旁证。
- **在图像空间做，不做米制标定**：只需**序关系**与**相对时间**。
- **时间轴**：金币的 y 与其 y 速率 → 到达本车所在行的剩余秒数（透视模型，见下）。
- **侧向**：本车的横移速率**由目标自身的 `dx/dt` 反测**（相机固定跟随、自车恒在画面中心
  x=0.5W；世界静止的目标在图上横移 = 本车在横移）——这一步替代了「车道线检测 + 标定」。
- **人类动作**：`pads.jsonl` 的 `lx` 持续符号（变道方向）。

## 已实测的三条约束（读任何后续结论都要带上）

### ① 旧模型的币类是**尺度盲**，只认「训练标签那一档」

训练集 `dataset/labels/train` 的 507 个 `coin` 标签：`y_center` 挤在归一化 **0.435–0.503**
（= 720p 下的 **y 313–362**），框高中位 **0.0167**（≈**12 px**）。后果：

- 全帧 letterbox（有效缩放 0.5）下网内币框只有 6 px → **大量漏检**；
- 路面带切片（`640×360`，有效缩放 1.0）→ 网内 12~20 px，正是训练档 → 检出率最好
  （见 [`../speedrush_vision/README.md`](../speedrush_vision/README.md) 的配对测量：币框 +53%）；
- 近场大币（屏幕 60 px 以上）在任何 letterbox 档都超出训练尺度 → 试过 `0.25×` 降采样金字塔
  可以救回（目视复核见下），但**本轮决定不用**，理由见 ②。

### ② 近场被**自车车身**遮住，吃币那一刻不可观测

实测 776 帧里所有币轨迹都终止在 **y≈370**（车顶轮廓线），与「模型尺度盲」的边界恰好重合；
近场裁图目视复核（`%TEMP%\sr_plan\nearfield_sheet.jpg` 那批）显示 y 360–700 的路面上**没有金币**，
只有 `+30` 浮字与幽灵车距离标记。**推论**：收集事件只能从**轨迹终止 + 位置**推断，
或改用 HUD 的 `+30/+90/+120` 增量做标签；任何规划器都不可能看见最后 0.3–0.5 s。

### ③ 决策可用窗口 ≈ **2~4 秒**，够用

币轨迹最长 **47 帧 ≈ 3.1 s**（y 250→370 走了 120 px，平均 ~39 px/s），即「进入可操作带 →
被车身遮住」有 2~4 秒。这正是路线文档要求的 2~3 秒视野的同量级 —— 视野是**能被满足的**。

## 浮字（得分弹字）路线：位置语义、成本账，以及为什么第一版不用它

**位置语义（维护者口径 2026-09-18，已入 `RULES.md` §4.8）**：浮字出现在「**加分行为的主体**」
所在处——吃金币等**玩家侧**行为归属本车，浮字在**车这一块**；**让街车退场**的加分发生在
**街车身上**，那类浮字在**路面上的那辆街车处**。故：

- 浮字**不给金币的车道归属**（金币的浮字在本车处，不在币处）——币的车道仍取自轨迹的 x；
- 浮字能给的是**时间、金额档、以及「玩家侧 vs 世界侧」的判别**（比分序列给不了这个判别）。

**成本实测（要回答"模版匹配是不是开销变大"）**：

| 环节 | 实测 |
|---|---|
| 黄掩码 + 连通域 + 形状过滤（730×280 浮字区） | **0.99 ms/帧** |
| 单字形归一化相关（`cv2.matchTemplate`，11 字形 × 约 8 个候选） | ~1–4 ms/帧（估） |
| 合计 | **~3–5 ms/帧**，比 OCR（单 ROI 约 12 ms）**便宜**；占 15 Hz 帧预算（66 ms）约 5–8% |

**结论**：算力不是障碍，**实现复杂度**才是（字形组装、面额吸附、跨帧跟踪三道，见下）。
故本实验**第一版不做浮字**，改用更便宜的现成通道：

> **收集事件 = 比分序列的跳变**（上一轮刚做可信：按卡片色取本机比分、离线全帧率读，
> `+30` 的跳变即一次收集）。所以决策点表 = **币轨迹的预期到达时间 × 比分跳变的实际时刻**，
> 零新感知代码。

浮字路线留作**事件来源分类**的升级件（区分 30 是金币还是普通超车、120 是动作还是半空四连币、
180 是社会车退场），届时只需在**候选时刻附近按需跑**，不必每帧跑。

**若将来做，实现要点**（已由实测形态确定）：① 亮黄 + 深描边 → 连通域**天然按字形分开**
（拼图里 `+`/`0`/`2` 各自成块），故"是哪个数字"= **单字形分类**，不是读整串；② 每个字形
**按包围盒归一化**到固定尺寸再与 `{+,0..9}` 相关 → 一个尺度即可，不必金字塔；③ 同 y 带内
按 x 组装成串；④ **吸附到合法面额**（面额是封闭离散集：30 的倍数 + 120/180 档），把被车身
遮末位的残串（如 `+12`）纠正或拒绝；⑤ 跨帧跟踪去重（同一浮字约 0.5–1 s，一帧最多 11 个候选
= 重叠确实存在）。伪阳性（黄色路缘线）靠描边与相关分数过滤。

## 下一步（方法与判据已定，未做）

1. **时间轴标定（唯一剩的技术步骤）**：逐轨迹用透视模型线性化拟合 `1/(y − y_h) = (t_a − t)/B`
   （全局扫 `y_h`，取总 R² 最大者），得到每条轨迹的 `B` 与 `t_a`，再换算出到收集行的剩余秒数。
   ⚠ 本轮试过的「轨迹平均 vy 配轨迹中段 y」**退化了**（拟合出 `y_h=315` 落在观测带内、给出
   70 s 的荒谬值）——根因是 `vy` 沿轨迹加速，平均量不能配中段位置。
2. **收集行 `y_c`**：用 `+30` 浮字出现行（近场目视约 y 490–560）或车顶轮廓（≈370）各算一版，
   **报敏感性**（`y_c` 取 380/440/500 三档看结论是否翻转）。
3. **决策点表**：每 0.25 s 取一次，列出可操作带内各币线的 `(x, 剩余秒, 价值)`、当前最优、
   未来 2~3 s 累计最优、人类动作；跑出「贪心解释不了 / 视野解释得了」的比例直方图。
4. **必须报的偏差**：币只在中央两条车道被检出（模型 x 带 0.44–0.55 的残留影响待量）、
   只算币不算超车/动作/社会车、不建模街车绕行成本。
