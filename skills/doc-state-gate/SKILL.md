# 现状文档落笔闸

现状文档指描述「现在怎么工作」的正文：README、模块文档、功能文档、业务文档、接入文档、CODE_WIKI、docs/ 下的 L1~L3 文档。它们只允许描述当前状态。本闸是 AGENTS.md 知识路由（L0~L4 信源等级、「过程叙述不进 L1~L3」）在写文档动作上的执行细则。

**主判据：写下的每句话，在删掉今天的临时文档、忘掉本次会话之后，必须仍然独立成立。**

不成立的典型形态：阶段叙事（「阶段一加了X」）、变更记叙（「原来是A，某时间点改成B」）、幽灵未来愿景（「为了未来X设计理念」）、只有读过本次会话才懂的指代。

## 落笔前自答（逐段）

1. **现状还是过程？** 试过什么、何时改的、为什么改、阶段N做了什么，都是过程，不进正文。去向：决策理由 → `docs/adr/`；时间线与「做了什么」 → git commit 与 `docs/update_log.md`；尚未落地的方向 → plan。
2. **有「原来…现在…」句式？** 只保留「现在」半句；行为变更的对比与理由住 ADR 或 commit message。
3. **理由是否依赖未来？** 现状不得用「为了未来的X」解释现在的结构；愿景住 plan/ADR。确实留了扩展缝，用「当前支持什么、扩展点在哪」的句式写。
4. **数值与清单是不是第二份副本？** 可机检的数值、枚举清单只写指向真源的路径（数值禁令），不复制数值本身。
5. **读者能不能不读代码就看懂？** 业务文档用业务语言；代码块与技术名词只在「没有它这句不成立」时出现，且保持最小。

## 临时计划/阶段文档的收尾

阶段性任务文档是消耗品，收尾时内容二选一（「留在原地」不是选项）：

- **折进现状**：仍然成立的结论按现状句式并入对应文档——写「现在如何」，不写「阶段N加了什么」；
- **删除**：其余内容直接删，历史由 git commit 与 ADR 承载。

完成后 grep 仓库：确认没有指向该临时文档的路径引用、没有「阶段N」式断头字样残留。

## 交付前自查

对本次会话写过的每一份**现状文档**（plan 类过程文档不在此列），假设读者只知道「现在的代码」：

- 逐句检查是否独立成立；「阶段」「原来」「之前」「目前先」「后续会」是过程残留的信号词，命中即核对该句该改写还是迁走；
- 临时任务文档已折叠或删除，无断链引用。
