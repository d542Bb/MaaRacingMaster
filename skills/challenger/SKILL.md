# Challenger（干净上下文攻击者）

当前对话里得出的结论，由参与构建它的同一个上下文来复核，必被锚定污染——它为自己的推理路径背书。真正独立的反对意见只能来自没读过这段对话的上下文。本技能把待攻击结论交给一个干净的子代理：只找反例，不给常规建议。

## 步骤

### 1. 提取攻击目标

从当前对话提取待攻击结论的完整陈述：结论本身、支撑它的关键证据、已知的边界条件，附结论涉及的文件路径。子代理没有对话历史，材料必须自包含——留在你脑子里的背景它不知道，也就攻击不到。

完成判据：产出一多段脱离本对话也能读懂的结论陈述，覆盖结论的全部承重假设。

### 2. 派发攻击子代理

用 general-purpose 子代理，提示词固定骨架：

- 你是独立复核者，没有参与得出该结论的过程。
- 任务：只寻找该结论中最可能错误、未经验证、被过早封死的假设。不提常规改进建议。
- 优先读仓库代码、测试、文档来验证，可动手验证的就不做纯逻辑推演。
- 输出二选一：
  - **攻击点清单**：按证据强度排序，每条附依据（文件、行号、数据）。
  - **PASS**：附检查过的假设清单与各自的验证方式；资料不足以判定的假设标「不可判定」，不得计入 PASS——PASS 是挣来的，不是找不到活干的托词。

### 3. 裁决与汇报

子代理返回的是待验证材料，逐条裁决后再向用户汇报：

- 攻击点成立——承认并修正结论，说明哪条证据起了作用；不成立——给出为什么不成立（证据），不静默丢弃。
- PASS 先核对清单是否覆盖了结论的承重假设；清单空泛或有遗漏，按「不可判定」处理并补查，不当成通过。

完成判据：用户看到的每条结论变化都能追溯到具体的攻击点与证据；PASS 能说清查过什么。

## 边界

- 与 grilling 分工：那是盘问用户补齐设计树，这里是攻击已形成的结论；一个在开工前，一个在结论后。
- 依赖会话内独有状态（用户口头补充、未落盘的临时产物）的结论部分传不进子代理，汇报时说明攻击范围受限在哪。
